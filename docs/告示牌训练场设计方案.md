# 告示牌训练场设计方案

> 状态：**Q-S1–Q-S3 已实施**（2026-11-23），单元测试通过，mod 编译通过，待游戏内按 §7 验收。审阅结论：决策点全部按建议执行。讨论时已定的几点见 §1，实施说明见 §8。
>
> 本方案沿用《训练场设计方案》（2×2 合成场地）、《箱子训练场设计方案》、《书与笔训练场设计方案》（下称"书方案"）和《砂轮训练场设计方案》（下称"砂轮方案"）的整体架构：
> - 插件主控，mod 以服务器身份操作场地；
> - 每轮一个新会话，记录写进 jsonl；
> - "恰好达到"的时刻由 mod 在 tick 里检测。
>
> 下面只写和它们不同的部分。
>
> 目标：新建一块场地，正前方是一块立着的告示牌。分三种题型训练 agent：打开告示牌逐行改写或清空文字；用染料给文字上色；用蜜脾给告示牌涂蜡。

## 1. 用户原始流程

1. agent 传送到对应的训练场地中，正前方有一块告示牌，视角对着它，直接右键就能打开
2. 清空 agent 身上的所有物品
3. 开始计时，发布任务：告示牌 50% 的概率写了随机字符，50% 的概率是空的，要求 agent 把告示牌的内容改成指定的随机字符（指定内容、样式等属性）
4. 检测到告示牌上有目标内容后，停止计时并记录

**审定的调整**（2026-11-23，讨论时确定）：

1. **"样式"改成整面的属性，三种题型各考一件事**（2026-11-23 更正）：`text` 只改文字，`color` 只上色，`wax` 只涂蜡。原版不能给单行文字设样式（F5），能改的只有整面的颜色、发光和涂蜡（F6）；发光不考（Q13）（Q2）。
2. **开局内容逐行随机**：每行各自决定有没有字；`text` 题再逐行决定改不改、清不清空（Q4、Q5）。
3. **`sign/*` 对齐原版**：`sign/set` 按编辑框的规则查，`sign/close` 等客户端做完再返回（Q9）。
   **追加（2026-11-23）**：编辑只作用于当前行（告示牌）、当前页（书），切行、翻页单独做。原版只能在当前行、当前页上打字；现在 `sign/set` 的 `line`、`book/set` 的 `page` 不切换就能改别的行、页，把"切过去"和"写"合成了一步。书的这部分改动和告示牌一起实施（Q9）。
4. **物品只发需要的**：`color` 题在随机的 1 格里发 32–64 个目标颜色的染料，`wax` 题在随机的 1 格里发 32–64 个蜜脾，`text` 题不发（Q6）。
5. **不做**悬挂告示牌、背面、别的木头种类（Q13）。
6. **追加（2026-11-23）：行为树读得到书和告示牌的编辑界面**。书与笔训练里 3 本书的题全是 `false_success`，查明原因是缺能力：树里读不到书的内容（F13）。`container` 来源增加两种界面类型 `book_edit`、`sign_edit`，带上界面里的文字（Q14，做法 A）。和书、告示牌的接口改动一起实施。

## 3. 总体设计

流程和砂轮场地相同，不需要预览：

1. 插件出题：题型、开局 4 行和颜色；`text` 题要改哪几行、改成什么，`color` 题的目标颜色；发什么物品、放在哪一格、发几个、选中哪个快捷栏格；
2. `arena/prepare`：清物品栏，重放告示牌并写上开局内容，发物品，设选中格，登记目标；
3. 发布任务，轮询 `arena/status`；`wax` 题发现涂了蜡但文字不对，就立刻结束本轮（Q8）；
4. 任务结束后调用 `arena/finish`，判定并写记录。

插件侧新增题型 `sign`，在新文件 `src/training/sign.js` 里实现。

mod 侧的改动：

1. 增加场地和工作站 `sign`；
2. `prepare` 新参数 `sign`，写开局内容；
3. `status` 返回告示牌的状态；
4. 增加一种"告示牌"写法的到达检测；
5. `sign/*`、`book/*` 对齐原版（Q9）；
6. `container/get` 报告书、告示牌的编辑界面，`container/close` 对它们等同于 Esc（Q14）。

## 4. 决策点

### Q1　场地和告示牌

- **场地原点 (10000, 120, 10480)**：接在书场地（10450）后面，间距 30 格。
- 场地名、题型名、工作站名都叫 `sign`。工作站是立着的橡木告示牌 `minecraft:oak_sign`，`ROTATION=8`，放在原点 +(0, 1, 2)，正面朝向站在原点的玩家（F2）。
- `prepare` 把玩家放在原点、准星对着告示牌，和其他有工作站的场地一样，返回 `aimOk`。站在这里离告示牌 2 格，在可编辑距离之内（F4）。
- **每轮重放**：`prepare` 先把那一格设成空气，再放告示牌，然后写开局内容。这样上一轮的文字、颜色、涂蜡和"可以编辑的人"都清掉了（F11）。上一轮超时时编辑框还开着也没关系：告示牌没了，编辑框会自己关掉；它发来的包对不上新告示牌登记的人，服务端不收（F4、F5）。
- 告示牌被打掉判 `lost`（沿用 `stationIntact`）。

**建议：采用。**

### Q2　三种题型

三种题型各只考一件事，另外两件保持开局的样子：

| 题型 | 要做的事 | 保持不变 | 发什么（Q6） |
|------|---------|---------|-------------|
| `text` | 逐行改写、清空正面的文字 | 颜色，不涂蜡 | 不发 |
| `color` | 用染料把正面文字改成指定颜色 | 文字，不涂蜡 | 32–64 个目标颜色的染料 |
| `wax` | 用蜜脾给告示牌涂蜡 | 文字、颜色 | 32–64 个蜜脾 |

- 发光不考：告示牌始终不发光，也不发荧光墨囊、墨囊（Q13）。
- `kind=text|color|wax` 指定题型，不写时每轮在三种里等概率抽。

**建议：采用。**（2026-11-23 更正：原稿是"每题都改文字，再加颜色或涂蜡"，按讨论改成三种题型各考一件事。）

### Q3　只考整面属性，不考单行样式

玩家改不了单行文字的样式（F5），所以目标只有 4 行纯文字、整面的颜色、是否涂蜡。开局也只写纯文字，不带样式：带样式的行改完后会沿用原样式，agent 也去不掉。

**建议：采用。**

### Q4　开局内容（逐行随机）

- **文字**：4 行里每行以 1/2 的概率写一串随机文字（Q7），否则是空行。
  - `text`、`wax` 题整块告示牌可以全空（蜜脾不要求有字，F6）；
  - `color` 题至少有一行字，全空时重抽，因为没字染不上（F6）。
- **颜色**：三种题型都在 16 种染料颜色里等概率抽，让画面多些变化。
- **不发光**（Q2）。
- **背面**：始终是空的、黑色、不发光。
- **不涂蜡**：涂了蜡就打不开了（F7）。

**建议：采用。**

### Q5　修改目标

**`text` 题**：

- **改几行** m 在 `edits`（缺省 `1-3`，范围 1–4）里等概率抽，行号在 1–4 里不重复地抽。
- 每一行的目标：

| 开局 | 目标 | 抽法 |
|------|------|------|
| 有字 | 改成一串新文字，或者**清空** | 清空的概率 1/4 |
| 空行 | 写上一串文字 | — |

- 没抽到的行保持原样。每个修改都会改变内容，所以文字目标一定和开局不同。允许全部清空。
- 颜色等于开局，不涂蜡。

**`color` 题**：目标颜色在开局颜色以外的 15 种里等概率抽；文字等于开局，不涂蜡。

**`wax` 题**：目标是涂蜡；文字、颜色等于开局。

**建议：采用。**

### Q6　发什么物品、放在哪

- **只发需要的**，放在主物品栏 36 格里随机的 1 格，数量在 32–64 里等概率抽：
  - `color` 题：目标颜色的染料；
  - `wax` 题：蜜脾；
  - `text` 题：什么都不发。
- **开局手上是空的**：`selectedSlot` 在快捷栏里没放物品的格子中随机抽（`prepare` 的 `selectedSlot` 参数已有，书方案 J4）。这样第一次右键一定打开编辑框，和原流程第 1 步一致；物品要 agent 自己拿到手上。
- agent 拿着染料、蜜脾去点告示牌会发生什么，让它自己去发现（F6），文案里不提。比如已经是这个颜色时再用染料，打开的是编辑框；涂过蜡再点，只有一声失败的音效。

**建议：采用。**

### Q7　随机文字

- 每行 2–6 个字符，从铁砧题的常用汉字表、英文字母、数字里抽，汉字和字母数字都有；不含空格、`§`、控制字符。不要首尾空格，因为空格看不见，agent 没法从画面上核对。
- 6 个汉字远窄于 90 像素（F3）。为了保险，`prepare` 也按编辑框的宽度规则查每一行（开局行和目标行都查），超宽就报错，不开始本轮。宽度要用客户端的字体量，所以这一步和 `sign/set` 共用同一个检查函数，在客户端线程上跑（Q9）。
- 所有文字（开局行、目标行）互不相同。

**建议：采用。**

### Q8　判定（只看最终状态）

**到达条件**，全部读服务端：

- 正面 4 行文字逐字等于目标（`color`、`wax` 题就是开局的文字）；
- 正面的颜色等于目标；
- 是否涂蜡等于目标；
- 背面和开局一样（空、黑色、不发光）；
- 没有人正在编辑（`playerWhoMayEdit` 为空，也就是编辑已经提交，F1、F5）；
- 光标为空。

不要求物品栏状态，用剩的物品不算错。发光不判（没有发光的物品，改不了）。

**`wax` 题提前结束（doomed）**：轮询时发现已经涂蜡、但文字被改过（不等于开局），就立刻结束本轮，因为再也改不回来（F7）。沿用村民交易题的 `doomed` 钩子，记 `doomed: 'waxed-changed'`。只有 `wax` 题发蜜脾，别的题型不会出现。

| 顺序 | 结果 | 条件 |
|------|------|------|
| 1 | `aborted` | 手动停止 |
| 2 | `lost` | 告示牌不在了 |
| 3 | `timeout` | 超时 |
| 4 | `success` / `false_success` / `failed` | 任务以完成结束时，到达条件成立就是 `success`，否则是 `false_success`；doomed 和其余情况是 `failed` |

**没做好的原因**（`faults`，`false_success` 和 `failed` 时记，可以有多项）：

| 原因 | 条件 |
|------|------|
| `editing` | 编辑框还开着（`playerWhoMayEdit` 不为空），改动没提交 |
| `text` | 正面 4 行不等于目标：`text` 题是没改、改错、多改、少改；`color`、`wax` 题是动了不该动的文字 |
| `color` | 颜色不等于目标：`color` 题是没染或染错（只发了目标颜色，基本不会染错）；其余题型不会出现 |
| `wax` | 是否涂蜡不等于目标：`wax` 题是没涂；其余题型不会出现 |
| `back` | 背面被改了 |
| `cursor` | 光标上有东西 |
| `dropped` | 发的物品掉在场内地上 |

**建议：采用。**

### Q9　`sign/*`、`book/*` 对齐原版（已定）

**原则**：编辑只作用于当前行、当前页，和原版打字一样；切行、翻页是单独的操作，和原版的方向键、翻页按钮一样。屏幕上显示的始终是正在改的那一行、那一页。

**`sign/set { text }`**：

- **去掉 `line` 参数**，只改当前行。传了 `line` 报错，提示用 `sign/line`。
- 和书方案 J3 做法 A 一样，按编辑框的规则查。不符合就报错，这一行不变，不截断：
  - 有 `isAllowedChatCharacter` 不收的字符（`§`、码值 < 32 的控制字符含换行、DEL）：报错，说明在第几个字符、码值是多少；
  - 宽度超过这块告示牌的 `getMaxTextLineWidth()`（立着的 90 像素，悬挂的 60 像素），宽度用 `font.width` 量：报错，说明宽度和上限。
- 检查函数单独写成 `SignApi.lineError(font, maxWidth, text)`，`arena/prepare` 查开局行、目标行时也用它（Q7）。

**新接口 `sign/line { line }`**：把当前行切到 0–3 的某一行，光标移到行末，等同于按方向键切行（`AbstractSignEditScreen` 76–88 行切行后调用 `signField.setCursorToEnd()`）。不在 0–3 时报错。直接切到第 n 行和连按几次方向键结果一样，不算后门。

**`book/set { text }`**：

- **去掉 `page` 参数**，只改当前页。传了 `page` 报错，提示用 `book/page`。
- J3 做法 A 的三条检查不变。
- 改完调用 `updatePageContent`，页码一起重算；书方案 §8 补充里为"改的不是当前页"加的页码刷新（访问器 `invokeGetPageNumberMessage`、`setNumberOfPages`）用不到了，删掉。

**`book/page { page }`**：

- 0 到总页数 − 1：照旧翻到那一页（等同于连点几次翻页按钮）。
- **等于总页数**：等同于在最后一页点"下一页"，追加一张空页再翻过去（`pageForward` 140–152 行）；已经 100 页时报错。
- 大于总页数：报错。一次只能追加一页，和原版一样。

**影响**：胶囊库和代码里目前没有调用 `book/set`、`book/page`、`sign/set` 的地方（2026-11-23 查过），改接口不影响已有胶囊。`src/mod/methods.js` 里四个接口的说明一起改，并新增 `sign/line`。书方案 J9 的文案不用改（本来就不说怎么翻页）。

**`sign/close`** 照 `book/close` 的修法：

- 等客户端线程关完再返回；
- 编辑框没打开时报错 `sign editor not open`；
- 超时报 `timed out waiting for the client thread`（`sign/get`、`sign/set` 也给这句缺省错误，避免 `Map.of` 收到 null）。

**影响**：这是 agent 的通用接口。胶囊库里已有的告示牌代码如果写过超宽的行，会开始报错。训练前先备份 `src/capsules/`。

### Q10　任务文案

写目标；`color`、`wax` 题另外点明物品栏里有染料或蜜脾、要用它（2026-11-24 更正）。不说怎么打开、怎么切行（`sign/line`）、怎么拿着物品右键。`prompts/training/sign.md`：

```
你正前方有一个告示牌。请按下面的要求修改它：
{{edits}}
没有提到的保持原样。
```

- `{{edits}}` 每项一行，最后一行以句号结尾，其余以分号结尾：
  - `text` 题（按行号顺序）：`- 正面第 2 行改成「风a雪B」；`、`- 正面第 3 行清空；`。行号从 1 开始（`sign/*` 接口的行号从 0 开始，这个对照 agent 自己查）。原来是空行的也说"改成"；
  - `color` 题：`- 物品栏里有 minecraft:light_blue_dye，用它把正面文字的颜色改成淡蓝色。`。物品用物品 ID，目标颜色用游戏里染料的中文名（白色、橙色、品红色、淡蓝色、黄色、黄绿色、粉红色、灰色、淡灰色、青色、紫色、蓝色、棕色、绿色、红色、黑色）；
  - `wax` 题：`- 物品栏里有 minecraft:honeycomb，用它给告示牌涂蜡。`。
- "没有提到的保持原样"对 `color`、`wax` 题就是"文字别动"（Q8 的 `text` 原因）。
- `color`、`wax` 题点明发了什么物品、要用它，但不说在哪一格，agent 自己在物品栏里找；`text` 题不发物品，也不提物品栏。

### Q13　超时、胶囊库、暂不做的部分

- **超时**：`timeoutSec` 建议 **300 秒**。一块告示牌最多改 4 行；`color`、`wax` 题只要把物品拿到手上右键一次。
- **胶囊库**：原样带进训练。训练前先备份 `src/capsules/`（Q9 的影响）。
- **暂不做**：
  - 悬挂告示牌（行宽 60 像素、编辑界面不同）、其他木头种类；

### Q14　`container` 来源报告书、告示牌的编辑界面（已定：做法 A）

**问题**：见 F13。书的内容、告示牌的文字只能靠 `book/get`、`sign/get` 读，而这两个接口在树里用不了，所以 agent 认不出哪本书是哪本，也核对不了写进去的字。真人打开书就看得到页，这是缺证据，不是 agent 没学会。

**做法 A**：`container/get` 在这两种界面打开时，不再报 `none`：

| 界面 | `type` | 另带的字段 |
|------|--------|-----------|
| 书与笔的编辑界面（`BookEditScreen`） | `book_edit` | `pages`（界面里的页列表，含还没保存的改动）、`currentPage`（0 起） |
| 告示牌的编辑界面（`AbstractSignEditScreen`，含悬挂告示牌） | `sign_edit` | `lines`（4 行，含还没保存的改动）、`currentLine`（0–3）、`isFront` |

- `slots` 为空列表，其余字段同 `none`。
- 读的是客户端界面的当前状态。编辑界面是纯客户端的，没有服务端回读，客户端状态就是准的（输入路径准则）；没保存的改动也在里面，和屏幕上看到的一致。
- 只报界面上看得到的东西，不替 agent 判断哪本是目标、写对没有。

**理由**：
- 大多数树已经读 `container`，"界面开着没有"这类判断不用改结构就能用上；
- 只补证据，不改"读取命令不当 Action、世界状态不进黑板"的设计。另一种做法（让读取命令当 Action 用，结果写进黑板）要推翻这条，影响面大，不采用。

**连带的改动**：

1. **`container/close` 对这两种界面等同于按 Esc**（新加的行为，需要审阅）：
   - 书：关掉、**不保存**（原版 Esc 不保存，书方案 F4）；
   - 告示牌：关掉，原版会保存（F4）。

   不这样改的话，默认中止流程见到 `book_edit` 就调 `container/close`，结果界面关不掉（F13）。保存并关闭仍然用 `book/close`、`sign/close`。

   **影响**：agent 用 `container/close` 关书，改动会丢，书题里表现为 `unsaved`，和真人按 Esc 一样。书方案 F9 里"agent 关书只能用 `book/close`，一定会保存"这句随之不再成立。
2. **词表**（插件 `game/vocab.js`）：`container.type` 增加 `book_edit`、`sign_edit`，说明里写清楚各带什么字段；顺便补上漏列的 `mount`。
3. **`src/mod/methods.js`**：`container/get`、`container/close` 的说明。
4. **`bt/observe.js` 的前后对比**：界面类型变化照常显示（如 `none → book_edit`）；这两种界面的文字变化暂不进对比，要看的话读 `container`。
5. **已有胶囊的影响**：判断"没有界面开着"的代码（如 `code/container.no-screen-open`）在书、告示牌打开时会从"是"变成"否"。这更符合实际，但行为会变；按"接着练"处理，让 agent 自己发现、修改。

**暂不做**：书的署名界面（`BookSignScreen`）仍报 `none`。agent 没有署名接口，也进不去这个界面。

## 5. 训练命令

### 5.1 完整格式

```
/bt train sign [runs=<次数>] [seed=<种子>] [kind=text|color|wax] [edits=<改几行>]
```

所有选项都可以不写，不写时按场地配置随机。

### 5.2 参数

| 参数 | 取值 | 缺省 | 含义 |
|------|------|------|------|
| `runs` | 1–1000 的整数 | 1 | 连续跑几轮 |
| `seed` | 0–4294967295 的整数 | 每轮随机 | 出题种子，规则同铁砧方案 §5.2 |
| `kind` | `text` / `color` / `wax` | 每轮在三种里等概率抽 | 题型（Q2）；和箱子题、锻造台题、砂轮题共用一个名字，取值按场地分别校验 |
| `edits` | `k` 或 `a-b`，1–4 | 场地配置，缺省 `1-3` | `text` 题改几行（Q5）；和书与笔题共用一个名字。和 `kind=color`、`kind=wax` 一起写时报错；不写 `kind` 时只作用于抽到的 `text` 题 |

写了其他场地的选项，按现有规则报"不认这些选项"。

### 5.3 相关命令

| 命令 | 含义 |
|------|------|
| `/arena sign` | 传送到告示牌场地的场外平台 |
| `/bt train status` / `/bt train stop` | 同其他场地 |
| `node scripts/training-report.js sign [--by kind\|edits\|target] [--last <N>] [--batch <批次>]` | 汇总训练记录（Q12），缺省按 `kind` 分组 |

### 5.4 示例

| 命令 | 效果 |
|------|------|
| `/bt train sign runs=10` | 按缺省设置跑 10 轮，三种题型随机 |
| `/bt train sign runs=5 kind=text edits=4` | 只考文字，4 行都改 |
| `/bt train sign runs=5 kind=color` | 只考上色 |
| `/bt train sign runs=5 kind=wax` | 只考涂蜡 |

## 7. 验收清单（实施后）

1. `/arena sign` 能传送到新场地的场外平台；其他场地和它们的训练不受影响。
2. `/bt train sign runs=3`：
   - 告示牌的正面对着 agent，`aimOk` 为真，右键打开的是正面（`sign/get` 的 `isFront` 为真）；
   - 告示牌的开局文字、颜色和记录一致，不发光；上一轮的文字、颜色、涂蜡没有留下来；
   - 物品栏里只有本轮发的物品（1 格，32–64 个），手上是空的。
3. 抽题检查（单元测试）：
   - `text` 题：改几行在范围内；清空只出在有字的行上；不发物品；
   - `color` 题：开局至少一行字；目标颜色和开局不同；发的是目标颜色的染料；文字目标等于开局；
   - `wax` 题：发的是蜜脾；文字、颜色目标等于开局；
   - 物品数量在 32–64；选中格上没有物品；
   - 文字长度、字符符合 Q7，互不相同；
   - 同一种子出同一道题。
4. 在游戏里手动验证：
   - `text` 题：右键、`sign/line`、`sign/set`、`sign/close`，判 `success`；按 Esc 关闭也判 `success`；
   - 编辑框开着就报完成，判 `false_success`，`faults` 有 `editing`；
   - `color` 题：把染料拿到手上右键，颜色变了、染料少 1 个，判 `success`；再点一次，打开的是编辑框、染料没少；
   - `wax` 题：拿蜜脾右键，判 `success`；先改了字再涂蜡，本轮立刻结束，判 `failed`，`doomed` 为 `waxed-changed`；

5. Q9：
   - `sign/set` 写带 `§` 的文字、写超过 90 像素的一行都报错，这一行不变；写 6 个汉字照常成功；传 `line` 报错；
