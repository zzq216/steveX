# 制图台训练场设计方案

> 状态：**修订版已实施**（2026-11-22），单元测试通过，待游戏内按 §6 验收。第一版（K1–K14 全部按建议执行）实施后，决定改为分别训练三种单项操作；修订版审阅时全部按本文执行，实施说明见 §7。
>
> - **第一版已经同意的改动**（修订版沿用）：把"选配方"改成"给出目标地图状态"；给地图加上可以读到的字段；按"地图签名 + 精确数量"判定，并且要分清地图是不是从发的那张做出来的；2×2 复制按织布机 L10 的先例处理。
> - **修订的内容**（2026-11-22 同意）：
>   1. 题目改成三种单项操作，用 `task=zoom|lock|clone|mix` 选，缺省 `mix`；
>   2. 放大题的目标缩放等级在"开局等级 + 1"到 4 之间随机；
>   3. 放大、锁定题开局发 1–3 张同编号的地图，只处理其中一部分；复制题做到总共 2–5 张；
>   4. 第一版的"随机走 1–4 步"保留为 `task=chain`，不放进 `mix`。
>
>   改动集中在 K3–K7、K11、§5–§7。
>
> 本方案沿用《织布机训练场设计方案》（下称"织布机方案"）的整体架构，下面只写不同的部分。织布机方案沿用的是切石机方案：插件主控，mod 以服务器身份操作场地；每轮一个新会话；记录写进 jsonl；"恰好达到"的时刻由 mod 在 tick 里检测。
>
> 目标：在已有场地旁边另建一块场地，场内正前方放一台制图台。训练 agent 分别掌握制图台的三种操作：放大、锁定、复制。每道题要求做出的地图在缩放等级、是否锁定、张数上都对。

## 1. 用户原始流程

1. agent 传送到对应的训练场地中。正前方放一台制图台，agent 的视角对着它，直接点右键就能打开
2. 清空 agent 身上的所有物品
3. 开始计时，并发布任务：从制图台的配方里随机选 1–4 个，把需要的一份材料放进 agent 的物品栏，要求 agent 按配方用制图台做出对应的物品，并把产物放回物品栏
4. 检测到物品栏里有目标物品时，停止计时并记录

第 1、2 步照用。第 3、4 步要按制图台的实际机制重新定义（§2 F1–F4）：

- 制图台没有配方表，只有放大、锁定、复制 3 种操作。
- 每一轮只考其中一种操作（K3）。题目是"把发的地图做成指定的一组地图"（K4）。
- 第一版的"随机走 1–4 步"保留为可选题型 `chain`，默认不出（K5）。
- 第 4 步只看物品 id 会误判（F3、F6），改成按地图签名、恰好达到目标来判定（K8、K9）。

## 2. 已核实的事实

依据 `1.21.11_src` 的 `CartographyTableMenu`、`MapItem`、`EmptyMapItem`、`MapItemSavedData`、`MapCloningRecipe`、`MapExtendingRecipe`、`ResultSlot`、`ServerPlayer`，以及 mod 现有的 `InventoryApi`、`ContainerApi`、`ArenaManager`。

| # | 事实 | 对方案的影响 |
|---|------|------------|
| F1 | 制图台有 3 格：<br>• 0 = 地图，只收带地图编号的**已绘制地图** `minecraft:filled_map`；<br>• 1 = 辅料，只收纸、空地图 `minecraft:map`、玻璃板；<br>• 2 = 结果；3–29 是背包，30–38 是快捷栏。<br>一共 3 种操作：<br>• **放大**：地图 + 纸，要求没锁定、缩放等级 < 4；<br>• **锁定**：地图 + 玻璃板，要求没锁定；<br>• **复制**：地图 + 空地图 → 2 张同编号的地图。<br>条件不满足时结果格为空。取一次结果，0、1 两格各扣 1 个 | 没有配方表可以抽，题目要改成目标地图状态（K3、K4）。每种操作消耗的辅料是固定的，一道单项题只用一种辅料 |
| F2 | 地图格里的地图要在服务器上有对应的地图数据，否则不出结果。空地图放不进 0 号格 | 不能直接发物品 id。开局地图要由 mod 用 `MapItem.create` 现做（K6） |
| F3 | 放大、锁定得到的地图 id 仍是 `minecraft:filled_map`，只是换了一个新的地图编号；缩放等级和锁定状态存在地图数据里，不在物品组件上。复制得到的两张保留原编号 | 只按 id 计数，分不出原图和做过的图。要按"缩放等级 + 是否锁定"区分（K9） |
| F4 | 锁定后不能再放大，也不能再锁。放大会生成一张内容为空的新地图（`scaled()` 用 `createFresh` 重新算中心，缩放等级 +1）。复制不看是否锁定。最大缩放等级是 4 | 几种操作混在一道题里时，**操作顺序决定做不做得成**。单项题不考这一点，`chain` 题才考（K5） |
| F5 | 放大后的地图中心由原图中心推出（`createFresh(中心 x, 中心 z, 缩放等级 + 1)`）。锁定保留中心和缩放等级。所以从开局地图做出来的地图，每个缩放等级的中心都是确定的 | 可以靠中心判断一张地图是不是从开局地图做出来的（K9） |
| F6 | 右键使用空地图（`EmptyMapItem`）会在**玩家当前位置**新做一张 0 级、未锁定的地图，消耗 1 张空地图 | 在数量上和"复制一次"完全一样（都是多 1 张 0 级未锁定的地图，少 1 张空地图），但不是复制。只按数量判定会误判为成功（K9） |
| F7 | **2×2 合成能复制地图**（`MapCloningRecipe`）：1 张已绘制地图 + k 张空地图 → k+1 张同编号的地图。放大的合成配方（`MapExtendingRecipe`，8 纸围 1 张地图）要 3×3，场内没有工作台，用不了。锁定没有合成配方 | 和织布机方案 F9 同类，按 L10 的先例处理（K10） |
| F8 | 制图台取结果时，原版调用的是 `Item.onCraftedBy`，**不增加** `crafted` 统计；2×2 合成格的 `ResultSlot` 调用 `ItemStack.onCraftedBy`，**会增加** `crafted`，增加量等于取出的张数 | 不能用 `crafted` 判定是否完成。但 `crafted:minecraft:filled_map` 的增量正好就是"在 2×2 复制出的张数"（K10） |
| F9 | 按住 Shift 点结果格会**循环做**：只要产物仍是 `filled_map` 就继续。0 号格放着多张同编号地图，并且辅料够时，一次会把它们全部放大或锁定 | 会做多。这是这项训练要观察的主要失误之一，放大、锁定题因此开局发一叠同编号的地图、只要求处理其中一部分（K4） |
| F10 | 结果格里的地图是预览：编号和原图相同，带 `map_post_processing` 组件（`LOCK` / `SCALE`）。取出时才处理，换成新编号。关闭界面时，0、1 两格的物品退回物品栏，结果格丢弃 | 输入格里的东西不算丢失（K8）。预览要让 agent 看得到（K2） |
| F11 | `InventoryApi.slotItem` 只给出 id、数量、耐久、附魔、旗帜图案等，**没有任何地图字段**；它在客户端读取。服务器每个 tick 会把物品栏里每张地图的数据（含缩放等级、锁定）同步给客户端（`ServerPlayer.synchronizeSpecialItemUpdates`），`ClientLevel.getMapData` 能读到 | agent 现在看不出自己做对了没有。在客户端补上字段就够了，不用改协议（K2） |
| F12 | 地图数据存在世界存档里，每个编号一个 `map_N.dat`。开局发的地图占 1 个编号，之后每放大或锁定一次再占 1 个 | 每轮多几个到十几个很小的文件（空白地图压缩后不到 1 KB），可以接受，不做清理（K13） |
| F13 | 已绘制地图和空地图一叠 64 张，纸 64，玻璃板 64。同编号的地图能叠在一起；分开放大、分开锁定的地图编号各不相同，叠不到一起 | 题目规模很小，不用做容量检查。开局的一叠同编号地图放在 1 格里（K6） |

## 3. 总体设计

流程和织布机方案相同：

1. 插件出题；
2. `arena/prepare` 发放地图和辅料、补回制图台、对准视角、登记目标；
3. 发布任务；
4. 轮询 `arena/status`；
5. 任务结束后调用 `arena/finish`；
6. 判定并写记录。

插件侧新增训练题型 `cartography`，实现放在新文件 `src/training/cartography.js` 里，接口和 `loom.js` 相同。训练器、记录、报告、每轮新会话都直接复用。

mod 侧的改动：

1. 增加工作站 `cartography`、场地 `cartography`，`opensStation` 认 `CartographyTableMenu`；
2. agent 能看到的物品描述里加地图字段（K2）；
3. `arena/prepare` 能现做开局地图，一叠可以有多张，编号相同（K6）；
4. 制图台工作站的 `status` / `finish` 按地图签名，计数物品栏、光标、制图台输入格、地上四处（K9）；
5. `Expect` 增加一种制图台写法（K9）。

不需要目录接口：只涉及 4 种物品（已绘制地图、空地图、纸、玻璃板），插件里写成常量。

## 4. 决策点

### K1　场地

新增场地 `cartography`：

- origin 设在 `(10000, 120, 10300)`，在织布机场地 `(10000, 120, 10270)` 之后，间隔 30 格。工作站是制图台。
- 场地的搭建、清场、屏障墙、告示牌逻辑原样复用。
- 制图台放在 `(ox, oy+1, oz+2)`，俯角由 mod 计算，`prepare` 返回前做射线自检 `aimOk`。这和织布机方案 L2 相同。制图台没有朝向属性。
- `/arena cartography` 传送到场外平台，`/bt train cartography` 开始训练。

**建议：采用。**

### K2　地图的可观察性（mod）

`InventoryApi.slotItem` 给带地图编号的物品加一个字段：

```json
"map": { "id": 12, "scale": 1, "locked": false }
```

- 数据从客户端的 `ClientLevel.getMapData` 读（F11）。读不到时（比如刚做出来、还没同步过来）只给 `{ "id": 12 }`，下一次查询就有了。
- 物品带 `map_post_processing` 组件时（制图台结果格里的预览，F10），另给 `"mapPostProcessing": "scale"` 或 `"lock"`，表示"取出后会放大 / 锁定"。

物品栏、`container/get` 的各格、光标，用的都是同一个 `slotItem`，补一处就全部生效。`methods.js` 的说明里写上这两个字段。

这里只把原版已有的数据露出来，不教做法，和织布机缺旗帜图案层时的处理一样。地图中心不给：agent 要分辨一张地图是复制来的（编号相同）还是新做的（编号不同），看编号就够了。

**建议：采用。**

### K3　题型：三种单项操作（修订）

每轮只考一种操作，用 `task` 选：

| task | 考什么 | 用到的辅料 |
|------|-------|-----------|
| `zoom` | 放大 | 纸 |
| `lock` | 锁定 | 玻璃板 |
| `clone` | 复制 | 空地图 |
| `mix`（缺省） | 每轮在上面三种里等概率抽一种 | 同上 |
| `chain` | 第一版的随机 1–4 步（K5），默认不出 | 按需要 |

为什么拆开：每一轮只练一种操作，复盘时容易看出是哪一步没学会，存下的胶囊也是一种操作一个，不会混成一棵大树。这和坐骑场地 `task=equip|unequip` 的拆法一致。

拆开后缺了"多种操作要排顺序"（F4）这一层，由 `chain` 题补，等单项操作练稳了再开。

`task` 这个选项名和铁砧题、坐骑题共用，训练器先只检查取值是不是这几个题型认识的值之一，再由各场地的 setup 按自己的题型校验。这和现在 `task`、`kind` 两个共用选项的做法相同。

**建议：采用。**

### K4　单项题怎么出（修订）

三种题的开局都是"n 张缩放等级 s₀、未锁定、编号相同的地图"，叠在 1 格里。s₀ 在 `scale` 范围里抽（0–3，缺省 `0-3`）。

| task | 开局 | 目标 | 最省用量 |
|------|------|------|---------|
| `zoom` | n 张 s₀ 级（n 在 `maps` 里抽，1–3） | 其中 m 张放大到 t 级，其余 n−m 张不动。m 在 [1, n] 里随机，t 在 [s₀+1, 4] 里随机 | 纸 m × (t − s₀) |
| `lock` | n 张 s₀ 级（n 在 `maps` 里抽，1–3） | 其中 m 张锁定，其余 n−m 张不动。m 在 [1, n] 里随机 | 玻璃板 m |
| `clone` | 1 张 s₀ 级 | 总共 c 张 s₀ 级未锁定的地图。c 在 `copies` 里抽（2–5） | 空地图 c − 1 |

例如 `zoom`，s₀=0、n=3、m=2、t=2，目标是"1 张缩放等级 0、未锁定的地图，2 张缩放等级 2、未锁定的地图"，最省用量是 4 张纸。

- **放大题要连续放大几次**（t − s₀ 次）：这仍然只是放大一种操作，同时检验 agent 会不会把同一步重复做对次数。
- **只处理一部分**：开局的 n 张叠在一起。把整叠放进地图格、再用 Shift 点结果，会把整叠都做掉（F9），导致做多。m = n 时没有这个风险，m < n 时才有，所以 m 在 [1, n] 里随机。复制题开局只有 1 张：取一次结果后地图格就空了，Shift 不会连着做。复制题的变化来自要做几张。
- 目标写成 `goals: [{ scale, locked, count }]`，按缩放等级从低到高、未锁定在前的顺序排列。不动的那 n−m 张也写进目标，这样"不该做的不做"也在要求里。

参数：

- `scale=k|a-b`：开局缩放等级，0–3，缺省 `0-3`。
- `maps=k|a-b`：放大、锁定题开局几张，1–3，缺省 `1-3`。
- `copies=k|a-b`：复制题做到总共几张，2–5，缺省 `2-5`。

**发料**：只发这道题用到的那一种辅料，数量 = 最省用量 + 余量。余量在 `spare` 里抽（0–3，缺省 `0-3`），和织布机一样。

- 余量为 0 时，必须一次做对。
- 余量 > 0 时，放大、锁定题可能用 Shift 做多（F9）；复制题可能右键空地图新做一张（F6），或者多复制一张。判定都能分辨出来（K8）。

**摆放**：开局那叠地图和辅料各占 1 格，在 36 格里随机摆放，由种子决定。

**随机数的抽取顺序**：

1. 题型（`mix` 时）；
2. s₀；
3. 按题型往下抽：`zoom` 抽 t → n → m；`lock` 抽 n → m；`clone` 抽 c；
4. 余量；
5. 打乱格位。

**建议：采用。**

### K5　`chain` 题（第一版的随机 1–4 步，保留）

第一版已经实施并通过测试的出题方式原样保留，用 `task=chain` 手动开，**不放进 `mix`**：

- **出题**：开局 1 张缩放等级 s₀、未锁定的地图。随机走 n 步合法操作，n 在 `ops` 里抽，1–4，缺省 `1-4`。每一步先在当前合法的操作种类里等概率选一种，再在能做这种操作的地图状态里等概率选一个。合法操作是：放大，对未锁定、缩放等级 < 4 的地图；锁定，对未锁定的地图；复制，对任意地图。走完后的全部地图状态就是目标。抽出来的那串操作只作记录，**不当作标准答案**。
- **最省用量**：
  - 纸 = 目标里的最大缩放等级 − s₀；
  - 玻璃板 = 目标里"有锁定地图的缩放等级"的个数；
  - 空地图 = 目标总张数 − 1。

  做法是从 s₀ 开始逐级往上：在每一级先复制出要留下的、要锁定的、要继续放大的，再锁定一张、复制出其余锁定的，最后放大一张。
- **发料**：用到的辅料各加 `spare` 个余量，没用到的不发。余量为 0 时只有顺序对了才做得成（F4）。
- 记录里另写 `ops`（抽样走的步骤）、`opCount`、`kinds`（这道题要用到的操作种类，如 `zoom+clone`）。
- `ops` 选项只对 `chain` 题有意义。用别的题型时写了 `ops` 会报错；`maps`、`copies` 写在 `chain` 题上也报错。

**建议：采用。**

### K6　开局地图（mod）

`arena/prepare` 的 `items` 允许这样一项：`{ slot, id: "minecraft:filled_map", count: n, map: { scale } }`。mod 用 `MapItem.create` 在主世界现做一张这个缩放等级的地图，再复制成 n 张同编号的，叠在指定的格子里。n 在 1–64 之间。

- **地图中心放在远离场地的地方**：取 `(ox + 8192, oz)` 作为建图坐标。缩放等级 4 的一格是 2048 方块，8192 隔了 4 格。这样，从开局地图放大出来的各级地图，中心都不会和场地附近右键新做的地图（以及它们再放大出来的地图）重合，K9 靠这一点分辨。
- 地图不追踪玩家（`trackingPosition=false`），内容是空白的，不影响任何操作。
- 一轮最多一项开局地图。mod 记下它的编号和各级中心，用于判定。

**建议：采用。**

### K7　任务文案（修订）

按"只补能力与证据，不教写法"的原则：文案只说现状和要求，不提纸、玻璃板、空地图各有什么用，不提操作顺序、Shift 点击、2×2 复制，也不说发了多少辅料。agent 可以自己读物品栏和 `container/get`。也不说这道题考的是哪种操作，看目标就知道了。

模板 `prompts/training/cartography.md`：

```
你正前方有一台制图台，视角已经对准它。你的物品栏里有{{maps}}（缩放等级 {{scale}}，未锁定）。
请把{{it}}做成：{{list}}。做完后物品栏里的地图只剩这些，不要做出其他物品。
```

- `{{maps}}`：n = 1 时是"一张地图"，n > 1 时是"3 张相同的地图"。`{{it}}` 对应是"它"或"它们"。
- `{{list}}` 按目标顺序列出，例如 `1 张缩放等级 0、未锁定的地图，2 张缩放等级 2、未锁定的地图`。
- 说法和 K2 的字段对应（`scale`、`locked`），不另造说法。
- "做完后物品栏里的地图只剩这些"是要求，不是做法：没写进目标的状态都不该留下。

**建议：采用。**

### K8　判定

任务结束时，分别清点物品栏（不含光标）、光标、制图台的 0、1 号格（界面还开着时）、场内地上这四处，按签名计数（K9）。判定顺序沿用织布机方案 L8：

| 顺序 | 结果 | 条件 |
|------|------|------|
| 1 | `aborted` | 手动停止 |
| 2 | `lost` | 制图台被挖掉；场内地上有物品；或者**地图不守恒**（见下） |
| 3 | `overshoot` | 任一目标签名在四处合计超过要求的张数；或者"由开局地图做出的地图"总张数超过目标总张数（复制多了，撤不回） |
| 4 | `mismap` | 出现了做不成目标的东西：不是从开局地图做出来的地图（F6 右键新做的那种）；开局时没有的物品 id；或者一张由开局地图做出、但已经走不到任何目标的地图（见下） |
| 5 | `timeout` | 超时 |
| 6 | `success` / `false_success` / `failed` | 任务以完成结束时，到达条件（K9）成立就是 `success`，否则是 `false_success`；其余情况是 `failed` |

- **地图守恒**：四处的"已绘制地图总张数 + 空地图张数"，应该等于开局地图张数 n 加上开局发的空地图数。复制（制图台或 2×2）和右键新做，都是 1 张空地图换 1 张已绘制地图；放大、锁定是一张换一张。少了说明有地图被扔出场外，判 `lost`。纸、玻璃板不检查。
- **走不到任何目标**：一张地图的状态是（缩放等级 s，是否锁定 L）。它能走到目标（g，G）的条件是：
  - 已锁定时，s = g 且 G 也是锁定；
  - 未锁定时，s ≤ g。

  走不到任何一个目标的，就是做错了，比如锁错了级、放大过头。还能走到目标、只是还没做完的地图，不算 `mismap`，按第 6 行判为没做完，记在 `unfinished` 里。
- 单项题里各种做多的样子：
  - 放大、锁定题用 Shift 把整叠都做了，是 `overshoot`（目标级别的张数超了）；
  - 放大题放过了头，是 `mismap`；
  - 复制题多复制一张，是 `overshoot`；
  - 复制题右键新做一张，是 `mismap`。
- 剩下的纸、玻璃板、空地图不判。
- 记录里写：
  - `madeOf`：每个目标实际做了多少；
  - `extra`：做错的东西及数量；
  - `unfinished`：还没做完的地图；
  - `copied`：见 K10。

**建议：采用。** `mismap` 的中文名是"做错"，和织布机的 `misweave` 同名。

### K9　签名与"恰好达到"的检测（mod）

**签名**：没有地图编号的物品就是 id。已绘制地图按服务器上的地图数据分两种：

- 由开局地图做出来的：`minecraft:filled_map#scale=N`，锁定的加 `,locked`，如 `minecraft:filled_map#scale=1,locked`；
- 其他的（中心对不上，或者没有地图数据）：`minecraft:filled_map#foreign`。

"由开局地图做出来"的判法：地图在主世界，并且中心等于开局地图在这个缩放等级上的中心（F5）。各级中心由 mod 在 `prepare` 时从开局地图的中心逐级推出：

```
c(s+1) = createFresh(c(s), s + 1) 的中心
```

不比较编号：复制出来的编号相同，放大、锁定出来的编号是新的，分开放大、分开锁定的地图编号也各不相同（F13），这些都应该算对。

**到达检测**：沿用织布机方案 L9，mod 在服务器 tick 里检测，记下第一次达到的时刻 `reachedAtMs`，不打断 agent。`Expect` 增加制图台写法：

```
expect: { cartography: { goals: [{ scale, locked, count }], allowed: [id...] } }
```

- 开局地图的编号和各级中心，由 K6 的 `items` 项登记，不用写在 `expect` 里；
- `allowed` 是开局发的全部物品 id（已绘制地图和这道题的辅料）。

同时满足下面几条就算到达：

1. 每个目标的签名在物品栏里恰好是 count 张，在制图台输入格里没有；
2. 物品栏、制图台输入格里没有其他 `filled_map#…` 签名（没有多出来的级别，也没有 `#foreign`）；
3. 光标为空；
4. 没有不在 `allowed` 里的 id。

剩多少辅料不比较。

`status` 对制图台工作站返回 `held`、`carried`、`tableInput`、`dropped`，都按签名计数。`tableInput` 是玩家当前打开的制图台界面的 0、1 号格，界面没开时为空。另外给 `containerOpen`。这些都只读，`finish` 的顺序不用改。

**建议：采用。**

### K10　2×2 复制地图（F7）

| 方案 | 做法 | 说明 |
|------|------|------|
| **A** | 允许，结果一样就算对；记录里写 `copied` | 放大、锁定仍然必须用制图台，训练目的不受影响。`copied` 取 `prepare` 时 `watch: ["minecraft:filled_map"]` 监测的 `crafted` 增量。只有 2×2 合成会加这个统计，制图台不加（F8），所以增量就是"在 2×2 里复制出的张数"（包括放进去的那张原图）。直接用现有的 watch 机制，不用新写代码 |
| B | 禁止：发现就判错 | 产物完全相同，没有理由算错 |
| C | 不发空地图，逼着用制图台复制 | 复制题就出不成了 |

`clone` 题可能有不少轮走 2×2 而不用制图台，`copied` 会把这种情况记下来，报告里能看出比例。

2×2 里没有别的配方能用上纸、玻璃板、地图（F7），所以不会出现别的绕路。

**建议：A。**

## 6. 验收清单（实施后）

1. `/arena cartography` 能传送到新场地的场外平台；其他场地和它们的训练不受影响。
2. `/bt train cartography runs=3`：每轮开始时，正前方有制图台，`aimOk=true`；物品栏里只有开局那叠地图（编号相同，叠在 1 格）和这道题用的那一种辅料；第一次右键就能打开制图台。
3. 物品栏和 `container/get` 里的地图带 `map { id, scale, locked }`；制图台结果格的预览带 `mapPostProcessing`。
4. 抽题检查（单元测试，抽几千道）：
   - `mix` 时三种题大致各占三分之一，不出 `chain`；
   - 放大题 t 在 [s₀+1, 4]、m 在 [1, n]；锁定题 m 在 [1, n]；复制题 c 在 `copies` 范围里；
   - 只发用到的那一种辅料，数量 = 最省用量 + 余量；
   - `chain` 题照第一版检查（每一步合法、最省用量用模拟器验证做得成）；
   - 同一种子出同一道题。
5. 在游戏里手动验证：
   - 恰好做完时，`reachedMs` 有值，判为 `success`；
   - 放大、锁定题把整叠放进地图格、用 Shift 点结果，判为 `overshoot`；
   - 放大题放过了头，判为 `mismap`；
   - 复制题右键空地图新做一张，签名是 `#foreign`，判为 `mismap`；
   - 在 2×2 里复制地图，结果正确时判为 `success`，`copied` 大于 0；
   - 把一张地图扔出场外，判为 `lost`；
   - 任务结束时地图还在制图台输入格里，不算丢失；
   - `task=chain` 的题，余量为 0、顺序做错，判为 `mismap` 或没做完。
6. 轮次中把制图台挖掉后，记录里 `stationIntact=false`；下一轮开始时制图台已经补回。
7. `training-report` 能按 `task` / `scale` / `spare` / `ops` 汇总，`mismap` 显示为"做错"。
