# 工作台训练场设计方案（3×3 合成专项）

> 状态：**W-S1–W-S3 已实施**（2026-11-01），单元测试通过，待游戏内验收（§6）。实施说明见 §7。W1–W10 全部采纳建议方案（W5 按审阅时修改后的版本：不排除蛋糕，靠 mod 侧兜底拆堆）。本方案沿用《训练场设计方案（2×2 合成专项）》（下称"2×2 方案"）的整体架构：插件主控、mod 以服务器身份操作场地、`crafted` 统计判定、每轮一个新会话、jsonl 记录。下面只写和 2×2 不同的部分。
>
> 目标：在 2×2 训练场旁边另建一块场地，场内正前方放一个工作台。训练 agent 用工作台完成一次 3×3 合成，并且能和 2×2 的训练曲线放在一起比较。

## 1. 用户原始流程

1. agent 传送到对应的训练场地中，正前方放一个工作台，agent 的视角对着工作台，直接点击右键就能打开
2. 清空 agent 身上的所有物品
3. 从只能用 3×3 工作台合成的物品中随机挑一个，把 1 份合成材料随机拆分后放进物品栏
4. 开始计时，并在 DSH 发布任务，例如 `/bt task 现在你的视角正对着一个工作台，只要点击右键就可以打开工作台。你的物品栏里有合成 minecraft:<目标> 所需的 1 份材料。请用这些材料合成 1 次 minecraft:<目标>`
5. 检测到物品栏里有目标物品时停止计时并记录

本方案保留这个流程。第 4 步的文案（W6）和第 5 步的判定（W7）按 2×2 方案已定的原则做了调整。

## 2. 已核实的事实

| # | 事实 | 对方案的影响 |
|---|------|------------|
| G1 | `recipes.json` 里放不进 2×2 的配方有 **599** 条（582 种产物），全部能放进 3×3。其中有序配方 570 条、无序配方 29 条 | 候选集合就是"能放进 3×3、放不进 2×2"，不需要再单独定义（W3） |
| G2 | 把有序配方的图案按符号规整（`#`、`X` 统一记为 A、B……）后，599 条只有 **76 种形状**。前几种占了大头：`AAA/ABA/AAA`（染色玻璃、陶瓦等）66 条，`AAA`（台阶）64 条，楼梯 58 条，`AAA/AAA`（活板门、墙）57 条 | 按配方等概率抽，近一半轮次会落在台阶、楼梯、染色、活板门这 4 种形状上，训练会被同一种摆法占满（W4） |
| G3 | 一个配方最多用到 **5 种**不同材料，最多 9 个材料位 | 工作台合成格最多要点 9 次，比 2×2 的点击计划长得多，超时可能要放宽（W9） |
| G4 | 有 56 条 3×3 配方的产物也能用别的 2×2 配方做出来（床和挽具染色、粒合成锭、铜块打蜡等）。但只用发下去的这份 3×3 材料，走不通那些 2×2 配方 | 不会出现绕开工作台的情况；判定用的"这份材料能做出什么"要在 3×3 范围内算（W7） |
| G5 | 不可堆叠材料只有一处会出问题：**蛋糕**要 3 个牛奶桶，而牛奶桶最多 1 个一组。现在的随机拆堆不知道堆叠上限，只有 1/4 的概率拆成 1+1+1；其余情况 `arena/prepare` 会因数量超过堆叠上限直接报错。蛋糕合成后会在合成格里留下 3 个空桶，关闭界面时它们会自动退回物品栏，不影响判定 | 发放时按堆叠上限兜底拆堆，蛋糕不必排除（W5） |
| G6 | 工作台的界面在 `container/get` 里是 `type: "crafting"`，结果格是 0，合成格是 1–9，后面依次是背包和快捷栏。2×2 用的玩家物品栏界面是 `type: "inventory"`，结果格 0、合成格 1–4，编号不一样 | 2×2 训练里学到的胶囊不能直接拿来用，这正好检验迁移能力（W10） |
| G7 | 工作台的结果格和物品栏的 2×2 结果格是同一个类（`ResultSlot`），从它取出物品同样会增加 `crafted` 统计 | 2×2 方案 T4 的判定依据在这里同样成立 |
| G8 | 从结果格**普通左键**取出时，成品挂在光标上，不在物品栏里；按住 Shift 点击才会直接进物品栏 | 用户流程第 5 步只看物品栏，会漏判已经合成成功的情况（W7） |
| G9 | 每轮 `prepare` 的第 6 步 `resetRecipes` 会**收回**所有已解锁配方。agent 也**没有**操作配方书的原始命令（`methods.js` 里没有配方书相关方法） | 不存在"点配方书自动填格"的捷径，不需要为此做决策。上一次讨论中我说"配方书会全部解锁、可以一键填格"，这个说法是错的，在此更正 |
| G10 | 当前传送进场的朝向是 yaw=0、pitch=0（水平看向 +z）。玩家眼睛高度是脚下 +1.62 格，平视会越过正前方工作台的顶面 | 必须由 mod 按工作台的位置算出 pitch（W2） |

## 3. 总体设计

和 2×2 方案 §3 的流程图完全相同。区别只有三处：

- `arena/prepare` 多做两件事：放置工作台，把视角对准它（W2）
- 抽样从"放得进 2×2"换成"放得进 3×3、放不进 2×2"，并按形状分组抽（W3、W4）
- 任务文案和判定范围改成 3×3 版本（W6、W7）

插件侧的训练器、记录、报告、每轮新会话都直接复用，靠场地配置区分（§5 配置）。

## 4. 决策点

### W1　新开场地，还是改造 craft2x2

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **A** | 新增场地 `craft3x3`，origin 设在 `(10000, 120, 10030)`，和 craft2x2 间隔 30 格，各自有场外平台和告示牌 | 2×2 训练还能继续跑，用来做回归；两份记录天然分开 | 多一块场地 |
| B | 在 craft2x2 里按轮次放或撤工作台 | 只有一块场地 | 2×2 训练时场内多一个工作台，agent 可能直接拿它做 2×2 配方，两种训练会互相干扰 |

**建议：A。** `/arena craft3x3` 用来传送到它的场外平台，`/bt train craft3x3` 用来开始训练。场地的搭建、清场、屏障墙、告示牌逻辑原样复用。

### W2　工作台的位置、朝向和视角

- **工作台位置**：放在场内中心正前方，中间空一格：`(ox, oy+1, oz+2)`。玩家站在 `(ox+0.5, oy+1, oz+0.5)`，朝向 +z。
- **视角**：传送时 yaw=0。pitch 由 mod 按"眼睛位置 → 工作台中心"的连线算出，这个位置约为 29°。视线会落在工作台朝向玩家的那个面上，距离约 2 格，在 4.5 格的交互距离之内。
- **服务器侧自检**：`prepare` 结束前，在服务器上用玩家当前视线做一次方块射线检测，结果写进返回值 `aimOk`（射线是否命中工作台）。`aimOk=false` 时本轮记为 `aborted` 并停止整组，这说明场地坐标出了问题。
- **等客户端更新视线目标**：客户端要过 1 个 tick 才会更新准星指向的目标。插件在 `prepare` 返回后等 **100 ms** 再发任务，避免 agent 第一次右键落空。

**建议**：采用以上做法。工作台的位置和 pitch 写在 mod 里，不做成配置项。

### W3　候选集合

- **候选**：能放进 3×3、放不进 2×2 的配方，共 599 条（G1）。sampler 的 `GRID` 改成参数（2 或 3），候选筛选统一写成"放得进 N×N，但放不进 (N−1)×(N−1)"。2×2 场地的候选保持不变（N=2 时没有更小的格子，等同于现在的规则）。
- **多选材料**、**同一符号同一种物品**、**1 份材料**、**随机拆堆**、**随机槽位**、**种子可复现**、**`item=` 固定目标**：全部沿用 2×2 方案 T7。

**建议**：采用以上规则。

### W4　按形状分组抽样

G2 显示，按配方等概率抽会严重偏向少数几种形状。可选的抽法：

| 方案 | 做法 | 效果 |
|------|------|------|
| A | 599 条配方等概率抽 | 台阶、楼梯、染色、活板门这 4 种形状约占 41% |
| B | 按产物去重后等概率抽 | 582 种产物，和 A 几乎一样，不解决问题 |
| **C** | **先在 76 种形状里等概率抽一种，再在这种形状里等概率抽一条配方** | 每种摆法出现的机会相同；同一形状内部仍然覆盖不同材料 |

- 形状的算法：有序配方取图案，把符号按出现顺序换成 A、B、C……（例如楼梯的 `#  /## /###` 记为 `A  /AA /AAA`）。无序配方按"无序 + 材料个数"归组（无序配方共 29 条）。
- 记录里加一个 `shape` 字段，报告可以按形状汇总。
- 用 `item=` 固定目标时不分组，直接在这个产物的配方里抽。

**建议：C。**

### W5　特殊配方

| 配方 | 情况 | 建议 |
|------|------|------|
| `cake` | 要 3 个不可堆叠的牛奶桶，现在的拆堆可能发出超过堆叠上限的一堆（G5）；合成后合成格里留下 3 个空桶 | 保留。发放问题由下面的兜底拆堆解决。空桶不影响判定，关界面时自动退回物品栏，下一轮清空物品栏也不会残留。合成后怎么处理空桶、不可堆叠材料只能逐个放，这些都是真实游戏里会遇到、值得观察的行为 |
| 盔甲纹饰锻造模板（19 条，形状 `ABA/ACA/AAA`） | 材料里有模板本身和 7 颗钻石，合成后模板会翻倍，属于正常合成 | 保留 |
| 染色、打蜡这类"给已有物品换属性"的配方 | 2×2 方案 T7 已说明需要时再加进 `exclude` | 保留，训练中发现问题再排除 |

**兜底拆堆**：`arena/prepare` 收到超过堆叠上限的一堆时，不再整轮报错，而是在 mod 里把它拆成若干堆，每堆不超过上限，多出来的堆放进剩余空槽（由 seed 决定放哪些槽）。实际发放的槽位写进返回值和记录，所以种子仍然可以复现这一轮。

**建议**：`craft3x3.exclude` 默认为空，靠 mod 侧的兜底拆堆保证所有配方都能正常发放。

### W6　任务文案

用户流程第 4 步里的"只要点击右键就可以打开工作台"是在教做法。按"只补能力与证据，不教写法"的原则，文案只描述现状，怎么打开工作台、界面槽位怎么编号，由 agent 自己用 `command_docs` 和 `container/get` 查。另一个原因是，如果学到的子树依赖"有人提前告诉我按右键"，到了真实世界里（工作台需要自己找、自己对准）就用不上了。

| 模式 | 文案 |
|------|------|
| **named**（默认） | `你正前方有一个工作台，视角已经对准它。你的物品栏里有合成 {{target}} 所需的 1 份材料。请用这些材料合成 1 次 {{target}}。` |
| hidden | `你正前方有一个工作台，视角已经对准它。你的物品栏里有某个物品的 1 份合成材料。请把它合成出来。` |

模板放在 `prompts/training/craft3x3_named.md` 和 `craft3x3_hidden.md`，用场地配置里的 `mode` 切换，模板选择规则和 2×2 相同。

**建议**：采用上表。如果你认为"视角已经对准它"也算提示，可以只保留"你正前方有一个工作台"。

### W7　判定

不采用用户流程第 5 步的"物品栏里出现目标物品"，沿用 2×2 方案 T4 的判定表：任务结束状态，加上 `crafted` 统计有没有增加。原因有两个：

1. 普通左键从结果格取出的成品挂在光标上（G8），只看物品栏会判不出合成成功。
2. 只有真正合成，`crafted` 统计才会增加（G7）；`/give` 和捡起掉落物都不算。

物品栏和光标物品照常记录，作为参考。

判定范围的变化：hidden 模式下的"这份材料能做出什么"（`craftableResults`），要在**能放进 3×3 的全部配方**里算，包括 2×2 配方。原因是场内有工作台，agent 可能先做出中间产物（例如用木板做木棍）。named 模式只看目标物品，不受影响。

**建议**：沿用 T4，判定范围按上面调整。

### W8　工作台被破坏怎么办

在生存模式下，agent 按住左键大约 3.75 秒就能把工作台挖掉，工作台会变成物品被捡进背包。

| 方案 | 做法 | 说明 |
|------|------|------|
| **A** | 每轮 `prepare` 都重新放置工作台（场地本来就是幂等搭建）。轮次进行中被挖掉不补放，`status` 和 `finish` 返回 `stationIntact`，写进记录 | 挖掉工作台是 agent 自己的失误，环境照实反映，记录里留下证据 |
| B | 训练时切换为冒险模式，方块挖不掉 | 环境和平时游戏不一致，agent 读到的游戏模式也不同 |

**建议：A。**

### W9　记录与超时

记录在 2×2 方案 T10 的字段基础上增加：

| 字段 | 含义 |
|------|------|
| `grid` | 3 |
| `shape` | 配方形状（W4） |
| `stationIntact` | 本轮结束时工作台是否还在（W8） |
| `openedMs` | 从 t0 到第一次打开工作台界面的时间。mod 在服务器 tick 里检测到玩家当前菜单是工作台菜单时记录，只记第一次 |

`openedMs` 把用时拆成"打开工作台之前"和"打开之后摆料取出"两段，方便看时间到底花在哪一步。

**超时**：3×3 的合成格点击最多要 9 次，规划也更复杂（G3）。场地配置里允许单独设置 `timeoutSec`，覆盖全局值；`craft3x3` 建议设为 **900 秒**。

**建议**：采用以上字段，`craft3x3.timeoutSec = 900`。

### W10　是否带着 2×2 的胶囊库训练

现在的库已经收敛到 `trees/craft.once-2x2-from-recipes`。它用的是物品栏界面的槽位编号，并且不包含"打开工作台"这一步（G6）。

| 方案 | 做法 | 能看到什么 |
|------|------|-----------|
| **A** | 胶囊库、事实库原样带进 3×3 训练 | agent 会新建一套 3×3 子树，还是把 2×2 的子树改造成按格子大小通用的版本。这正是我们想观察的迁移能力 |
| B | 清空胶囊库，从零开始训练 | 得到一条干净的 3×3 学习曲线，但看不到迁移 |

带着库训练时，2×2 子树会出现在 `capsule_search` 结果里，agent 可能会尝试复用。这属于"能力和证据"，不是"教写法"，符合原则。

训练报告里加一项：每轮引用了哪些 2×2 时期的胶囊（按胶囊的创建时间早于 3×3 第一轮来判断）。

**建议：A。** 训练开始前先备份 `src/capsules/`，想做对照时再用 B 跑一组。

配置变化（`config.js`）：

```js
training: {
  timeoutSec: 600,
  pollMs: 1000,
  recipes: 'dsh-plugins/agent/data/recipes.json',
  arenas: {
    craft2x2: { origin: [10000, 120, 10000], mode: 'named', exclude: [] },
```

多份材料、指定产物个数（`n=` / `m=`）见 2×2 方案 T14，craft3x3 同样适用，模板为 `craft3x3_multi.md`。

## 6. 验收清单（实施后）

1. `/arena craft3x3` 能传送到新场地的场外平台；craft2x2 场地和它的训练不受影响。
2. `/bt train craft3x3 runs=3`：每轮开始时，正前方有工作台，准星对准它（`aimOk=true`），物品栏里只有本轮的材料。agent 第一次右键就能打开工作台。
3. 抽样只出现放不进 2×2 的配方，并且按形状分布，不会集中在台阶、楼梯；`seed` 相同时结果完全一样。
4. 普通左键取出的成品挂在光标上时，仍然判为 `success`。
5. 轮次中把工作台挖掉后，记录里 `stationIntact=false`；下一轮开始时工作台已经补回。
6. 记录里有 `grid`、`shape`、`stationIntact`、`openedMs`；`training-report` 能按场地和形状汇总。
7. 用 `item=cake` 固定目标，连跑几轮（换不同 seed）：每轮都能正常发放，3 个牛奶桶各占一格，记录里的槽位和实际发放一致；合成后留在合成格里的空桶不影响判定。

## 7. 实施说明（2026-11-01）

**mod（W-S1）**：`ArenaManager`、`ArenaApi`、`ArenaCommand`
- 已知场地从"名字 → origin"改为"名字 → `Site(origin, station)`"，预先登记 `craft2x2`（无工作站）和 `craft3x3`（`(10000, 120, 10030)`，工作台）。`/arena` 按登记的工作站搭场地
- `build` / `prepare` 的 `station` 参数：省略时用已登记的，显式 `null` 表示没有。工作站格在场内清空循环里直接放工作台，重复搭建不会来回改方块
- 俯角：`atan2(眼睛高度 − 工作台中心高度, 水平距离)`，眼睛高度取 `player.getEyeHeight()`。自检用 `ClipContext.Block.OUTLINE` 从眼睛沿视线打到交互距离，命中工作站那一格且方块仍是工作台才算 `aimOk`
- 兜底拆堆：`split(items, seed)`，空槽用 `java.util.Random(seed)` 打乱。没超限的堆不受影响，所以不碰不可堆叠材料的轮次和以前完全一样。`prepare` 返回 `given`
- `openedAtMs`：服务器 tick 里玩家当前菜单是 `CraftingMenu` 时记录（物品栏的 2×2 是 `InventoryMenu`，不会误记）
