> 目标：在陆地上训练 agent 的移动和寻路，全程要求不掉血。分三套：
> - **路线**：按给定的顺序经过几个点再到终点，有平地、模拟起伏、真实世界三张图；
> - **寻路**：只给起点和终点，尽快走到，有模拟起伏、真实世界两张图；
> - **跑酷**：先实测按键的时间精度，下一稿再设计。
>
> 前两套共五个场景，按 Q18 的顺序训练。

## 1. 用户原始流程

1. 设计两套训练场地：第一套让 agent 沿着指定路线走；第二套只给定起点和终点，要求 agent 以最快的时间到达终点。
2. 每一套再细分为两个场地：一个纯平面，一个有起伏的地面。
3. 起伏的地面直接复制真实世界的地形，剔除有水的地方（或者在筛选地形时直接排除）；纯平面由我们自己设计。
4. 开放记忆世界：训练开始后，把训练场地直接复制到记忆世界的对应位置，省去 snapshot 获取视觉信息的步骤。
5. 再加一套训练场地，训练跑酷技巧，比如各种极限跳跃、旋转跳、顶头跳等移动技巧。
6. 要求 agent 在不掉血的情况下完成寻路，结束后告诉 agent 本次是否掉血、掉了多少。

**讨论时已定**（2026-11-27）：

1. **路线只给坐标**，不在地面上铺出 agent 看得见的路线。
2. **计时从 agent 开始移动的那一刻算起**（Q8）。
3. **到达就算通过**，不设时间门槛；用时和参照用时的比值只作记录（Q5、Q15）。
4. **陆地的范围**：只含走、疾跑、跳上 1 格、安全下落、绕开坑洞。梯子、门、活板门、游泳、在岩浆里移动都不含（Q16）。
5. **掉血判到达，另外记录**：掉血不影响这一轮是否判为到达（Q10）。
6. **复盘里给每次受伤的来源、位置、时刻和数值**（Q14）。
7. **记忆预填做成开关**：先在预填的图上练规划，胶囊准入要求在不预填、只能自己看的图上也过门槛（Q11）。
8. **跑酷先实测按键精度，再决定收哪些跳法**（Q17）。
9. **场地按区块对齐，大小做成参数**（Q1）。难度靠距离、点数、高差控制，不靠场地大小。

**第一稿审阅意见**（2026-11-27）：

10. **平地铺草方块**；**寻路题不设平地**，只用起伏地形。平地只留给路线题（Q2）。
11. **地形筛选放宽**（Q3）：
    - 优先选地表，从上往下找；
    - 液体只排除水；
    - 允许露在外面的危险方块，允许方块实体。
    
    随之定下（第一稿讨论时的建议，用户同意）：附近有可燃方块的岩浆所在的窗口不收；容器清空，刷怪笼停用。
12. **路线题改为先定起点和终点，再随机放 n 个中间点**，agent 按给定的顺序经过这些点，最后到达终点（Q4）。起点、中间点、终点上画观察标记，给人看，agent 看不到（Q4b）。
13. **不限制路线和场地**：删掉"折线、走廊、离开场地就结束"的规则，让 agent 自己找最合适的路线（Q4、Q7）。场地外面是空的，走出去就会掉下去，本轮结束，不另留缓冲（Q1、Q10）。
14. **记忆要处理的文件更多**：地形以外还有方块实体、生物群系等（Q11）。
15. **查询结果用一个黑板参数承接**：树里查询的结果放进缓冲区，黑板里只放一个参数（句柄），agent 再对它做各种操作。要解决的是黑板的值太小、装不下查询结果的问题（产出树的回合本来就调不到查询工具，结果不会进上下文，F19）。另开设计方案（Q12）。

**第三稿**（2026-11-28，用户提出）：

16. **五个场景，按顺序训练**（Q18）：
    1. 平地路径点；
    2. 模拟起伏地形路径点；
    3. 真实世界路径点；
    4. 模拟起伏地形寻路；
    5. 真实世界寻路。
17. **模拟起伏地形**夹在平地和真实世界之间，只引入"高差"这一个变量：草方块地面，有台阶、坎，有少量悬崖和坑，没有树、水、危险方块（Q2b）。实现上不新增题型，只给 `ground` 加一个取值 `synthetic`，寻路题也收 `ground`。

**第三稿审阅意见**（2026-11-28）：

18. **真实世界里的水改为替换**：有水就整个窗口不要，很难抽到合适的窗口。改为复制时把水替换掉（水面换成草方块，水下换成泥土，流水换成空气），只把水面占比太大的窗口（海洋、大湖）排除（Q3）。这条修订了第 11 条的"液体只排除水"。

**第四稿**（2026-11-28，用户提出）：

19. **场地每轮随机偏移**：为了不让 agent 继续推理训练地图的形状，训练地图生成的位置每次都向 x 和 z 方向随机偏移几格（Q19）。
20. **边缘点**：新设一个参数，控制有多少个路径点（不包括起点和终点）放在地图边缘，更有效地解决 agent 每次都冲过头的问题（Q20）。

## 3. 总体设计

**三套场地，前两套共五个场景**：

| 套 | 平地（`flat`） | 模拟起伏（`synthetic`） | 真实世界（`terrain`） |
|----|------|------|------|
| 路线（题型 `route`） | ① 草方块地板，没有障碍（Q2） | ② 按高度图生成的起伏地面（Q2b） | ③ 复制来的真实地形（Q3） |
| 寻路（题型 `goal`） | 不设 | ④ 同②（Q2b） | ⑤ 同③（Q3） |
| 跑酷 | 下一稿设计（Q17） | — | — |

圈号是训练顺序（Q18）。五个场景共用 mod 里的一块场地 `land`，每轮开局按本轮的题目重建（Q1）。地形种类用选项 `ground` 区分，记忆预填用选项 `memory` 区分。

**每轮的流程**：

1. **准备地形**：
   - 平地：mod 铺草方块地板；
   - 模拟起伏：插件按种子生成一张高度图，mod 按高度图铺地面（Q2b）；
   - 真实世界：插件抽一个源窗口，mod 把它复制进场地（Q3）。不合格就换一个窗口；
   - 三种地形放好以后，mod 都把场地的格子信息（每格的碰撞顶高、是否危险、每列的地表高度）交给插件。插件的出题只看这一份，三种地形走同一条路。
2. **出题**：插件在格子信息上出题。路线题出起点、终点和中间点的顺序（Q4），寻路题出起点和终点（Q5）。插件按同一套可走性规则，验证每一段都到得了、全程不用掉血，并算出参照路线和参照用时（只记录，不给 agent 看路线）。
3. **`arena/prepare`**：
   - 清物品栏，把玩家放到起点，设开局状态（Q6），登记要画的观察标记（Q4b）；
   - 在客户端一侧清掉场地范围内的记忆；`memory=prefill` 时，再把场地写进记忆（Q11）。
4. **发布任务，轮询 `arena/status`**。掉出场地或者死亡，就立刻结束本轮（Q10）。
5. **任务结束后调用 `arena/finish`**，判定并写记录。判定说明交给复盘（Q14）。

**插件侧**：新文件 `src/training/land.js`，提供题型 `route`、`goal`，包括：
- 模拟起伏地形的高度图生成；
- 可走性、出题、参照路线；
- 判定、判定说明、记录。

**mod 侧**：新文件 `arena/LandArena.java`，包括：
- 场地 `land` 的搭建；平地、按高度图铺地面；
- 窗口复制（方块、方块实体、生物群系）；
- 三种地形共用的格子信息；
- 逐 tick 的位置、中间点进度、到达、掉出场地；
- 受伤和死亡事件；
- 观察标记的叠加层；
- 客户端一侧的记忆清除和预填。

## 4. 决策点

### Q1　场地

- **位置**：场地 `land` 占 4 × 4 个区块，按区块对齐：x ∈ [10496, 10560)，z ∈ [9984, 10048)，y ∈ [90, 150]。离弓箭场的空场地（x 到 10349）有 140 多格。场外平台沿用其他场地的做法，在 −x 方向。
- **本轮场地**：大小由 `size`（单位区块，2–4）定，从场地的西北角起取 `size × size` 个区块。场地的其余部分每轮清成空气。
  > 第四稿：本轮场地不再贴着西北角，而是在场地范围里随机偏移；场地范围扩到 5 × 5 个区块（Q19）。
- **缺省大小**：

  | 场地 | 缺省 `size` | 理由 |
  |---|---|---|
  | 路线（三种地形） | 2（32 × 32） | 点数和点之间的距离决定难度，和场地大小关系不大 |
  | 寻路（模拟起伏、真实世界） | 4（64 × 64） | 32 格的窗口装不下一座山丘或一条沟；模拟起伏取同样大小，两个寻路场景只差地形内容。实施时测一下 4 × 4 的开局耗时，太慢就降到 3 |

- **高度**：平地的地板顶面在 y = 100，人站在 y = 101。模拟起伏的最低地表在 y = 100（Q2b）。真实世界把窗口的最低地表对齐到 y = 100（Q3）。
- **这一带可能有山**：第一次搭场地时把整个范围清成空气，之后每轮 `prepare` 重建。
- **场地外面是空的**（§1 第 13 条）：四周不加墙，也不另外复制一圈缓冲。走出地板或窗口的边缘就会掉下去，本轮结束（Q10）。文案不写场地范围，也不写"掉下去就结束"，让 agent 自己发现。

**建议：采用。**

### Q2　平地（只用于路线题）

- **地板**：本轮场地的水平范围内铺一层 `minecraft:grass_block`，顶面 y = 100。下面是空的。
- 没有障碍。点和点之间都是直线可达，难点在于走准、转向、按顺序经过。
- 生物群系：整块场地设成 `minecraft:plains`，每轮都一样，记忆里查到的群系和看到的草色对得上。

**建议：采用。**

### Q2b　模拟起伏地形（第三稿）

**定位**：夹在平地和真实世界之间，只引入"高差"这一个变量（§1 第 17 条）。agent 在这里要学会的是：
- 上 1 格要跳；
- 走下 3 格以内不掉血，超过就掉；
- 跳下去比走下去多摔约 1.25 格（F1）；
- 有的地方上不去、下不来，只能绕。

树、水、危险方块、半砖、楼梯这些真实世界才有的东西，一样都不放。

**生成**（插件里，按种子，可复现）：

1. **基础高度图**：几层不同尺度的噪声叠加（平滑的大起伏加一点小起伏），缩放到 0 到 `relief`（缺省 `4-12`，按轮抽）之间，取整。最低处对齐到 y = 100。
2. **整平成台阶**：相邻两列的高差压到最多 1 格，这样基础地形处处走得通。这一步之后的地形就是一片有坡、有台阶的丘陵。
3. **加悬崖**：抽 `cliffs` 个（缺省 `1-3`）随机形状的区域，整块抬高或压低 4–6 格。边缘就是 4 格以上的坎，上不去，走下去会掉血。
   - 抬高的是台地。一部分台地在某一侧留一条 1 格一级的坡道，上得去；
   - 压低的是坑。每个坑都留一条坡道，掉进去会掉血，但能自己走出来，不会被困住到超时。
4. **铺方块**：每一列顶上是 `minecraft:grass_block`，往下 3 格是 `minecraft:dirt`，再往下到 y = 96 是 `minecraft:stone`。

**生物群系**：同平地，整块设成 `minecraft:plains`。

**交给出题**：mod 按高度图铺好以后，照样交回格子信息（§3 第 1 步）。插件不直接用自己生成的高度图出题，三种地形走同一条路，免得两边算法出入。

**出题**：同真实世界（Q4、Q5）。起点、终点、中间点都在地表上；出题时仍要求每一段都有一条不用掉血的路。悬崖和坑只是让"直线走过去"不一定可行。

**参数**：`relief`、`cliffs` 都放在场地配置里，按地形种类分开写（§6 的配置）。

**建议：采用。**

### Q3　真实地形从哪来、怎么筛、怎么复制

**来源**：同一个存档的主世界，离场地很远的几块"源区域"（配置项 `terrainSources`）。缺省是 4 块，每块 16 × 16 个区块：

| 源区域 | 区块范围（x, z）起点 | 方块坐标起点 |
|---|---|---|
| A | (2500, 2500) | (40000, 40000) |
| B | (−2516, 2500) | (−40256, 40000) |
| C | (2500, −2516) | (40000, −40256) |
| D | (−2516, −2516) | (−40256, −40256) |

分散成几块是为了生物群系多样：同一块 256 格的区域里往往只有一两种群系。区块在第一次被抽中时由服务器生成，之后从存档读。

**地表**（§1 第 11 条"优先选地表，从上往下找"）：
- 每一列的地表取不算树叶的高度图（F18），也就是这一列最高的、挡移动的、不是树叶的方块。
- 起点、中间点、终点只放在地表上，不放在原木上。洞穴、树下的地面不出题。
- agent 怎么走不限：钻进山洞、爬上树都可以。

**抽窗口**：在源区域里按种子抽一个按区块对齐的 `size × size` 窗口。mod 扫描后报告窗口的摘要，插件按下面的条件决定收不收，不收就换下一个，最多试 20 个：

1. **水面占比不超过 `maxWater`**（缺省 0.25）：地表是水的列（按含液体的高度图看最上面那格）不超过窗口的 25%。水会在复制时替换掉（见下面的"复制"），但海洋、大湖的窗口替换后基本是一整块平地，在起伏场景里没有训练价值，所以不收。岩浆照收。
2. **岩浆不会点火**：每一格岩浆周围水平 4 格、往上 4 格以内没有可燃方块（F16）。
3. **高差在 `relief` 里**（缺省 `4-24`）：地表最高减最低。小于 4 和平地差不多；大于 24 多半有悬崖，复制的高度范围也放不下。
4. **出得了题**：插件按 Q4 或 Q5 出得了题。出不了就算这个窗口不收。

露在外面的危险方块、方块实体都照收（§1 第 11 条）。危险方块在格子信息里标出来，出题时绕开（Q5）。

**复制**：
- 竖直范围从窗口的最低地表 − 4 到最高地表 + 16（上方留给树），最低地表对齐到场地的 y = 100。
- **方块**：复制方块状态，不触发相邻方块更新，沙子、沙砾不会落下，流动的岩浆也不会扩散。树叶改成 `persistent=true`：窗口边缘被切断的树离原木太远，不改的话会慢慢掉光。树、草、花、雪层照常保留。
- **方块实体**：连数据一起复制，但有两处改动：
  - 箱子、木桶、漏斗这类容器清空，去掉战利品表。冒险模式也能开箱子，不清的话 agent 可能拿到食物、末影珍珠，改变任务的性质；
  - 刷怪笼清掉要刷的生物，变成空刷怪笼（F17）。每 20 tick 清一次怪拦不住骷髅放箭。
- **水**（§1 第 18 条）：只改复制进场地的那一份，源世界不动。

  | 原来是什么 | 换成什么 | 原因 |
  |---|---|---|
  | 每一列最上面那格水源，上面是空气 | `grass_block` | 湖面、河面变成和岸齐平的一片草地 |
  | 其余的水源（水面以下、冰下面） | `dirt` | 草方块被盖住也会慢慢变成泥土，直接放泥土 |
  | 流动的水（不是水源） | 空气 | 山坡上的瀑布、溢流只是薄薄一层流水，换成草方块会在坡上留下一道道台阶和柱子 |
  | 海带、海草、海泡菜、气泡柱这类只能待在水里的方块 | 和它所在位置的水一样处理 | 水没了，它们会变成掉落物，或者悬在空中 |
  | 含水方块（含水的楼梯、半砖、栅栏……） | 去掉含水，方块本身保留 | |
  | 冰 | 保留 | 冰是方块，不是水；能走，只是会滑 |

  替换在格子信息之前做，所以出题、可走性、记忆预填看到的都是替换后的场地。代价是填平的湖面、河面是一片没有高差的平地，不会让 agent 学错什么。
- **生物群系**：按窗口复制到场地。不复制的话，场地还是原来的群系，草的颜色会变，agent 查 `biomes` 记忆也对不上。
- **实体**：不复制。

**交给插件的格子信息**：插件不知道每种方块的碰撞形状，所以由 mod 逐格算好再交出去：
- 每一格的碰撞顶高（空 / 整格 / 半砖、楼梯这类不满一格的，给出顶面高度）；
- 是否危险：岩浆、岩浆块、仙人掌、甜浆果丛、细雪、火、营火、凋灵玫瑰、滴水石锥；
- 每一列的地表高度（F18）。

插件的可走性、出题、参照路线都只看这份信息。格式实施时定（大约 64 × 64 × 48 格，压缩后几十 KB）。

**建议：采用。**

### Q4　路线题：怎么出、怎么判

**出题顺序**（§1 第 12 条）：先定起点和终点，再随机放中间点，最后定顺序。

1. **起点和终点**：都在地表上，离场地边缘至少 2 格，两点的水平直线距离在 `dist` 里（缺省 `12-28`，不超过场地对角线）。
2. **中间点**：n 个，n 在 `points` 里抽（缺省 `2-4`，范围 1–8）。在场地的地表上随机抽，离场地边缘至少 2 格，彼此之间、和起点终点之间至少隔 4 格。
   > 第四稿：其中 `edge` 个改放在场地边缘（Q20），其余的仍离边缘至少 2 格。
3. **顺序**：中间点按抽出的先后编号，这就是要经过的顺序。
4. **每一段都到得了**：起点 → 第 1 个点 → … → 第 n 个点 → 终点，每一段都存在一条不用掉血的路（按 Q5 的可走性）。有一段不满足就重新抽中间点。
5. **参照路线**：把每一段的最短路线接起来，参照用时的算法同 Q5。

**判定**：
- **经过一个点**：脚的水平位置在这个点所在的格子里，脚的高度和这一格地表的高度差不超过 1（从上面跳过去也算）。
- **按顺序**：第 k 个点只有在第 k − 1 个点经过以后才算。先走到后面的点不算数，之后还得再去一次。
- **到达**：经过了全部中间点之后，站到终点所在的格子上（水平方向在这一格里，脚的高度差不超过 0.5）。没经过全部中间点就先走到终点，不算到达，本轮继续。到达不要求停下。
- 不限制路线：怎么走、离点和点之间的直线多远都可以（§1 第 13 条）。

坐标给到格子中心 (x.5, y, z.5)，y 是站在这一格上时脚的高度。

**建议：采用。**

### Q4b　观察标记（给人看，agent 看不到）

起点、各中间点（标上序号）、终点各画一个标记，方便人在画面上看 agent 走到了哪里。agent 和人用的是同一个客户端画面，所以标记要做到"画出来，但视觉采集不到"：

- **不用调试图形**：F3 一类总在最上层的调试图形会让视觉的采集整帧跳过（F15）。
- **不用粒子**：粒子画在世界渲染里，可能写进深度，被视觉当成"那里有东西"。
- **做法**：客户端一侧，在世界渲染之后画一层**不写深度**的叠加层：每个点一根竖直的彩色光柱，加一个序号。已经经过的点变灰。
- **开关**：配置项 `markers`，缺省开。
- agent 也读不到：标记不是方块、不是实体，不进任何记忆文件，`status` 里给 agent 的部分也不提它。

**验收**：同一个画面，标记开、关各做一次 snapshot，结果必须完全一样（§7 第 7 条）。

**建议：采用。**

### Q5　寻路题：怎么出起点和终点、参照路线

**可走性**（两个题型共用一套，按 Q3 的格子信息算）：
- 一格**能站** = 脚下有碰撞顶面，往上 2 格没有碰撞，不是危险方块，在本轮场地范围内；
- **移动**：在 8 个方向的相邻格之间走。斜着走要求两个侧面的格子也能过，不能贴着墙角斜穿过去。高差上 ≤ 1 格、走下 ≤ 3 格；
- 洞穴、树上、树下的格子只要满足条件也算能站：参照路线可以穿过它们，只是起点、终点、中间点不放在那里（Q3）。

**起点和终点**：
- 都在地表上，离场地边缘至少 2 格；
- 两点的水平直线距离在 `dist` 里（缺省 `24-56`，不超过场地对角线）；
- 存在一条不用掉血的路（按上面的可走性做 BFS）。

**参照路线和参照用时**：
- 在可走性图上找最短路线，长度 L 按水平距离算（斜走 √2）。
- 参照用时 = L ÷ 疾跑速度（约 0.28 格/tick，F3），取整到 tick。
- 这只是估算：疾跑跳比单纯疾跑快，上坡要跳又会慢一点，所以"用时 ÷ 参照用时"可能小于 1。它只用来比较轮与轮之间，不当作最优解。
- 参照路线不给 agent，只写进记录，供人复盘时看。参照用时给 agent 看（Q14）。

**到达**：站到终点所在的格子上（同 Q4）。终点只给坐标，观察标记 agent 看不到（Q4b）。

**建议：采用。**

### Q6　开局状态

- **物品栏清空**，什么都不发。
- **冒险模式**，本轮结束后改回生存。冒险模式不能挖方块、不能放方块。生存模式下空手也能挖泥土、树叶，挖出来的方块还能拿来垫脚，"寻路"就变成了"开路"，可走性、参照路线也都不成立了。摔落伤害、跳跃、疾跑在冒险模式下和生存模式一样。冒险模式仍能开箱子，所以复制时清空了容器（Q3）。
- 生命、饥饿值、饱和度补满，清效果、着火和摔落距离，白天、晴天（沿用 F4）。
- 敌对生物照常每 20 tick 清一次（F4）。
- **位置**：站在起点格子的中心，偏航角随机（不对着第一个点或终点），俯仰角 0。

**建议：采用。**

### Q7　任务文案

写目标和规则，不说怎么走、怎么查记忆、怎么规划，也不说场地多大、掉下去会怎样（§1 第 13 条）。

`prompts/training/route.md`：

```
你站在 {{start}}。请以最快速度按顺序经过下面 {{n}} 个点，最后走到终点 {{goal}}：
{{points}}
走进一个点所在的那一格就算经过；没按顺序经过的点不算数。经过全部点之后站到终点这一格上，就算到达。
要求全程不掉血：掉血不影响是否判为到达，但会记录下来。用时从你开始移动时算起。
```

`prompts/training/goal.md`：

```
你站在 {{start}}。请以最快速度走到 {{goal}}，站到这一格上就算到达。
要求全程不掉血：掉血不影响是否判为到达，但会记录下来。用时从你开始移动时算起。
```

- `{{points}}` 每个点一行，带序号，例如 `1. (10510.5, 103, 9990.5)`；
- 坐标写到一位小数，就是精确值（格子中心是 .5，脚的高度是整数）；
- 三种地形用同一份文案，不说地形是什么样；
- **不说记忆里有没有预填**：`nbt_query` 本来就在 agent 手里，查一下就知道。说了等于替它做了"先查记忆"这一步。

**建议：采用。**

### Q8　计时与到达

- **开始移动**：服务端看到玩家的位置第一次离开起点（水平距离超过 0.05 格，或者高度变化超过 0.05 格，原地跳一下也算）的那个 tick。只转视角不算。
- **到达**：满足 Q4 或 Q5 到达条件的那个 tick，记为 `reachedAtMs`。
- **用时** = 到达的 tick − 开始移动的 tick，单位 tick，另换算成秒。
- 另外记 **开始移动前用了多久**（从发布任务到开始移动，按墙钟算）。这一段主要是大模型的规划时间，单独看，不混进用时。
- 中途停下来想一想，时间照样算在用时里：开始移动以后的时间都算。

**建议：采用。**

### Q9　受伤的记录

- mod 在 `AFTER_DAMAGE`（F6）里记录本轮玩家的每一次受伤，从发布任务起算：
  - tick 和时刻；
  - 伤害来源（`minecraft:fall`、`minecraft:cactus`、`minecraft:lava`、`minecraft:in_wall`……）；
  - 实际受到的伤害、受伤后的生命值；
  - 当时的位置；摔落伤害另外记摔落距离。
- 汇总：受伤几次、一共掉了多少。
- 不比较开局和结束时的生命值（F6）。
- **死亡**（`AFTER_DEATH`）：允许岩浆和危险方块以后，死亡是可能的，比如掉进岩浆。记死亡来源和位置，本轮立刻结束（Q10）。复活走现有的 `player/respawn`。训练中死亡和 P2 的 died 请求怎么衔接，实施时核对，不能让它触发一轮修复对话。
- 掉出场地不等摔死就结束本轮（Q10），所以通常不会走到死亡这一步。

**建议：采用。**

### Q10　判定

**提前结束（doomed）**，mod 在 tick 里一发现就记下时刻，轮询时立刻结束本轮：

| 代号 | 条件 |
|------|------|
| `fell` | 掉出场地：脚的高度低于场地最低的方块 − 2（平地是 y < 98，模拟起伏和真实世界是 y < 94）。mod 记下离开场地边缘时的位置，立刻把玩家传送到场外平台 |
| `died` | 死亡（Q9） |

**掉出场地为什么不等摔死**：§1 第 13 条的意思是"走出去就会掉下去，本轮结束"，这里保留这个结果，但不让它真的摔死。原因有两个：
- 场地下面不是虚空：y < 90 是这一带原来的地形，掉到山上可能只摔掉几颗心，然后 agent 就在场地外面的野地里走；
- 真的死亡要复活，还可能牵动 P2 的 died 请求（Q9）。

记录里的 `fell` 和摔死对 agent 的含义一样：本轮结束，复盘里写明从哪里掉下去的。

**结果**：

| 顺序 | 结果 | 条件 |
|------|------|------|
| 1 | `aborted` | 手动停止 |
| 2 | `timeout` | 超时 |
| 3 | `success` / `false_success` / `failed` | 任务以完成结束时，到达条件成立就是 `success`，否则是 `false_success`；doomed 和其余情况是 `failed` |

**没做好的原因**（`faults`，`false_success` 和 `failed` 时记）：

| 原因 | 条件 |
|------|------|
| `unreached` | 没有到达 |
| `skipped` | 路线题：报完成时还有中间点没按顺序经过 |
| `fell` / `died` | 同 doomed |

**受伤不进 `faults`**（§1 第 5 条）：另记 `hurt`（是否受过伤）和 `damage`（一共掉了多少）。`success` 但受过伤的轮次，报告里单独数（Q15）。

**建议：采用。**

### Q11　记忆的清除和预填

**要处理的文件**（F7，§1 第 14 条）：

| 记忆文件 | 开局清除 | 预填 | 理由 |
|---|---|---|---|
| `terrain`（地形） | 清 | 填 | |
| `block_entities`（方块实体） | 清 | 填 | 真实世界的地形里允许有方块实体了（Q3）；平地和模拟起伏没有，填的是空 |
| `biomes`（生物群系） | 清 | 填 | 真实世界的群系跟着窗口复制（Q3）；平地和模拟起伏是平原（Q2、Q2b） |
| `containers`（容器内容） | 清 | 不填 | 这是 agent 打开过才会有的记忆。容器又是空的，预填等于告诉它"里面什么都没有" |
| `entities`（实体） | 清 | 不填 | 场地里没有实体 |

**两种模式都要清**（F8）：`prepare` 时，把整块 `land` 范围从上面五个文件里删掉。场地被我们换掉了，agent 并没有看见，所以"agent 对这块地一无所知"才是对的。

**`memory=prefill`**：清完以后，对本轮场地跑一遍视觉自己的序列化代码，相当于"把整块地都看了一遍"：
- 只写"露在外面"的方块：至少有一面挨着空气或者不满一格的方块，也就是视觉有可能看到的那些。埋在里面的石头不写，否则一块 64 × 64 的地有十几万格，查询会被它们淹没；
- 方块实体、生物群系同样只写场地范围内的；
- 用视觉自己的代码而不是另写一套，条目格式自然和视觉写进去的完全一样。客户端此时就站在场地里，场地在渲染距离以内，客户端的世界里有这些方块。

**`memory=none`**：只清不填，agent 要自己 snapshot 去看。

**只动采集端的这几个文件**：
- 瞬时的 `terrain.nbt` 和记忆端的镜像世界都不动，agent 不读它们（F7）。
- 代价是：镜像世界里没有预填的方块，删除判定也就不会碰这些格子。这些格子一轮之内不会变，每轮开局又会清，所以没有影响。

**做法**（F12）：
- `ArenaApi` 等服务器上的 `prepare` 做完，到渲染线程上清除、写入，再立刻落盘（不等限频）。
- 落盘完成后 `prepare` 才返回，返回里带 `memory { cleared, prefilled }`，按文件分别给条数。
- 这样发布任务时，`nbt_query` 读到的一定是本轮的状态。

**待实施时核实**：`biomes` 设计成跨会话单调增长（F7），按范围删除可能和它的某些假设冲突，比如记忆端靠"只增不减"做的增量处理。核实结论补进本条；真有冲突，退一步只清不填生物群系也可以，影响很小。

**缺省值**：`memory` 缺省 `prefill`（先练规划），取值 `prefill`、`none`、`any`（每轮等概率抽）。胶囊准入要求在 `none` 的图上也过门槛（§1 第 7 条）。准入现在还没有实现（F13），所以先在报告里按记忆模式分组看成功率（Q15）。

**建议：采用。**

### Q12　读地形的能力：查询结果缓冲区

> **2026-11-28 先放大了上限**：黑板单个值 16 KB → 256 KB，沙箱输出 64 KB → 256 KB，查询条数 512 → 4096（字节预算 256 KB 不变）。一个值现在装得下约 2500 条带状态的地形记录：32 × 32 的场地地表一次查完，64 × 64 的起伏地形分两三次。**本训练场在场地范围内不再需要缓冲区**；用户决定缓冲区方案暂不考虑，等行为树再次碰到 256 KB 上限时再拿出来。"按位置查"（查询条件的区间值引用黑板）和上限无关，`memory=none` 的寻路题正式训练前仍建议先做。下面是放大前的分析，留作记录。

**问题**（F9、F19）：查询只在树里做，大模型在产出树的回合调不到查询工具，结果本来就不进上下文。问题都在树里：
- 查询结果写进黑板，一个值最多 16 KB，只装得下约 160 条地形记录，512 条的上限在树里用不满；
- 黑板会被整份复制进每个展开、修复、复盘请求，不宜直接调大；
- 查询参数只能写字面量，不能"走到哪查到哪"；
- 一万多格的寻路，沿途有几百万格方块，任何单次结果都装不下。

**用户的提法**（§1 第 15 条）：查询的结果用一个黑板参数承接，agent 再对它做各种操作。

**这和已定的设计一致**：大结果走缓冲区和句柄，不进黑板（F19）。落地的样子：

1. 树里的查询节点加一个参数 `into`。给了它，完整结果放进本任务的**缓冲区**，黑板里只写**句柄**（一个小字符串）、条数和版本戳。
2. 树对缓冲区能做的操作：
   - **再查询**：新条目 `core.buffer.query` 以句柄为数据源再做过滤、投影、计数；
   - **交给代码**：Compute 以句柄为输入，沙箱代码拿到整份数据，跑 A\* 之类的算法；代码算出的大结果（比如一条路线）也可以作为句柄输出；
   - **按位置查**：查询条件里的区间值可以引用黑板，这样就能"走到哪查到哪"。
3. 缓冲区跟着任务走，带版本戳，记忆文件更新以后能看出"这一份已经旧了"（《算法层与执行层设计方案》§6.2）。
4. 缓冲区里的单份结果可以远大于 512 条（缺省上限 20 万条、32 MB），不受黑板 16 KB 的约束。
5. 查询工具本身不改，仍然只在普通问答回合可用。

**这件事另写设计方案**（《查询结果缓冲区设计方案》）：
- 它改的是行为树的数据通道，不只服务这个训练场；
- 它要动《nbt查询api设计方案》里已定的规则（v1 不暴露句柄、四个参数只能写字面量）。

本方案只定衔接：
- 训练场本身不依赖它：`memory=prefill` 的场地范围固定，用现有的能力分几次查也能读完；
- 但 `memory=none` 的寻路题和以后的长距离寻路，要等它做完才练得好。所以建议它的实施排在本方案的 L2 之后、正式训练 `memory=none` 之前。

**建议：采用。**

### Q13　mod 怎么记录

- **轨迹**：从发布任务起，每 tick 记一次脚的位置，以及是否在地上、是否在疾跑、偏航角。
  - 内存里全留，`status` 只返回摘要。
  - `finish` 返回时，从开始移动起每 4 tick 取一个点，另外保留每次起跳、落地、经过中间点、受伤的那一 tick，最多 3000 个点（约 10 分钟）。超出就再抽稀一半。
- **中间点进度**：每个点按顺序经过的 tick；先到了后面的点（不算数）也记下 tick，复盘时能看出顺序错了。
- **到达**、**掉出场地**：tick 和位置；掉出场地另记离开边缘时的位置。
- **受伤、死亡**：Q9。
- **`status`** 另有：
  - `field { size, ground }`；
  - `started`（开始移动的 tick，没开始为 null）、`reachedAtMs`；
  - `route { passed[], next }`；
  - `hurt { count, total }`、`dead`、`fellAtMs`；
  - 当前的位置。

**建议：采用。**

### Q14　判定说明（复盘里给 agent 的）

只列事实，不给建议，不给参照路线：

- 本轮结果、doomed 的原因；
- **用时**：开始移动前用了多久，开始移动到到达用了多少 tick（秒）；
- **参照用时**（两个题型都给）：写成"参照用时 Y tick（按一条不掉血的最短路线、全程疾跑估算）"。agent 知道离"快"还差多少，但不知道路线该怎么走；
- **路线题**：每个点是否按顺序经过、在第几 tick；走到了但顺序不对的点，写明在第几 tick 到过；
- **轨迹**：每秒一个点（20 tick），外加起跳、落地、经过中间点的点。这是它自己走过的路，用来对照自己的计划；
- **受伤**：每一次的来源、数值、受伤后的生命值、位置、tick，摔落另给摔落距离；一共掉了多少。没受伤就写"全程没有受伤"；
- **掉出场地**：从哪里离开边缘、在第几 tick；**死亡**：来源和位置。

**建议：采用。**

### Q16　超时、胶囊库、暂不做的部分

- **超时**：`timeoutSec` 缺省 **600 秒**，从发布任务算起，不另设"开始移动后的上限"：被卡住、原地打转的轮次照样会超时。开始移动前的规划时间（Q8）比走路本身长得多，所以不按参照用时的倍数另设上限。

### Q17　跑酷：先实测按键精度

**为什么要先测**：
- 疾跑跳过 1–3 格的空隙、跳上 1 格同时越过空隙，这类跳法在寻路里用得上，能容忍好几 tick 的误差。
- 4 格空隙要贴着边缘起跳；旋转跳要在空中按 tick 配合转向和横移；顶头跳要掐准起跳时机。
- 按键没有对齐 tick（F10），视角转动又有平滑速度（F11）。如果通道本身就有 1–2 tick 的抖动，agent 练到的就是噪声：成功率上不去，原因不在策略。

**测什么**（用 L1 的逐 tick 轨迹，在 `land` 的平地上，由开发者用批量接口直接发，不经过 agent）：

1. **起跳时机的抖动**：同一串"按住前进 + 疾跑、等 X ms、按跳"重复 50 次，看起跳点沿前进方向分布多宽。
2. **按位置起跳**：边轮询 `player` 边在离边缘某个距离时按跳，同样重复 50 次，看起跳点的分布。这才是 agent 实际会用的写法，多了一层轮询的延迟。
3. **空中转向**：起跳后 N ms 调 `camera/turn` 转 90°，看转完时已经过了几 tick。

**怎么用结果**：起跳点的分布宽度和各种跳法能容忍的起跳范围（用移动模拟算）一比，就知道哪些跳法在现在的通道上做得出来。下一稿据此决定跑酷场地收哪些跳法；做不出来的，再看要不要补一条按 tick 对齐的输入能力，那要另开设计。

**建议：采用。**

### Q19　场地随机偏移（第四稿）

**起因**（§1 第 19 条）：平地路线题跑了 6 轮（任务 5–10，`points=6`），12 个会话都没有在树里读记忆。agent 是靠历史推算边界的，依据有三类：
- 掉落位置：任务 8 冲出南边，复盘记下"场地边缘 z≈9984"；
- 站过的坐标：如"10525.4 能站，东边至少到 10526"；
- 出题坐标的范围：如"出过的点 z 最大 10013.5，北边大概在 10015–10017"。

场地每轮都在同一个位置，这些推算就一直有效，查记忆显得多余。推不准的地方（比如北边），它宁可每个点都停下再走，也不去查。

**做法**：本轮场地的西北角 = 场地范围的西北角 + (ox, oz)。
- ox、oz 各自独立，在 `offset` 里按种子抽，缺省 `0-16`，取整数。
- 起点、中间点、终点、观察标记、记忆预填都按偏移后的实际位置算。插件拿到的格子信息本来就带 `field.x0 / z0`（§8 第 2 条），出题不用改。
- 寻路题也偏移。

**偏移量为什么取 0–16，而不是几格**：
- 只偏 ±3 格时，agent 会推出"南边在 9981–9987 之间"，然后每个点多留几格余量，照样不用查记忆。
- 偏移的范围要大过它愿意留的余量。0–16 大约是一个区块：两轮之间同一条边最多差 16 格，历史坐标基本没有参考价值了。
- 取任意整数，不取 4 的倍数。取 4 的倍数时，每个方向只有 5 种可能，又能被推出来。

**场地范围要扩大**：
- 现在场地范围是 4 × 4 个区块（64 格），边长 4 的场地已经占满，没有地方偏移。
- 改成 **5 × 5 个区块（80 格）**：x ∈ [10496, 10576)，z ∈ [9984, 10064)，仍按区块对齐。边长 4 加最大偏移 16 正好放下。
- 每轮重建要检查的格数从 64 × 64 × 61 变成 80 × 80 × 61（约 25 万 → 39 万）。只改和目标不同的格，平地和起伏地形轮与轮之间差别不大，开局时间增加有限。实施时实测一下。
- 场外平台仍在 −x 方向，位置不变。

**对已定规则的影响**：
- **§1 第 9 条"场地按区块对齐"**：只剩场地范围按区块对齐，本轮场地不再对齐。真实世界的源窗口仍按区块取，只是放到场地里时整体平移。
- **生物群系**：按 4 × 4 格的单元复制（`fillBiomes`），偏移不是 4 的倍数时，群系和方块最多错开 3 格。表现为边界附近的草色、雪的位置差一点，不影响走路。平地和模拟起伏整块都是平原，没有影响。
- **记忆**：开局仍然清掉整个场地范围（现在 80 × 80），预填只填本轮场地。prepare 等客户端载入的区块按本轮场地实际覆盖的区块算：边长 2 的场地偏移后可能跨 3 × 3 个区块。
- **掉出场地、在不在场地里**：按 build 记下的本轮场地判，本来就不依赖西北角。

**给 agent 什么**：
- 文案不变，不说偏移。
- 判定说明仍写"x × x 区块"，不写偏移量，也不写场地的坐标范围（Q14）。
- 偏移只进记录（`offset: [ox, oz]`）。

**命令与配置**：
- 场地配置 `offset`，缺省 `'0-16'`。
- 命令选项 `offset=a-b`（0–16）。`offset=0` 回到固定位置，方便调试和对比。

**建议：采用。**

**附带一个不在本稿范围的选择**：路线题的 `size` 缺省是 2，不变。想让场地大小也不固定，可以直接用 `size=2-3`，现有选项已经支持。

### Q20　边缘点（第四稿）

**起因**（§1 第 20 条）：现在的中间点都离边缘至少 2 格（`EDGE_MARGIN`），冲过头几格多数还在场地里，只有任务 8 掉了下去。冲过头的代价太小，agent 学不到"该刹车的时候刹车"。

**和 Q19 一起才有效**：
- 只有边缘点、场地不偏移：agent 记住边界，靠边就刹车，还是不查记忆。
- 只偏移、没有边缘点：每个点都留足余量，冲过头也掉不下去。
- 两个都有：要么每个点都停（安全，但慢）；要么只在靠边的点刹车（快，但要先知道边在哪）。文案要求"以最快速度"，会把它推向后者。

**参数**：
- 命令选项和场地配置 `edge`：`k` 或 `a-b`，0–8；
- 本轮实际的边缘点数 = min(抽到的值, 本轮中间点数 n)；
- 起点和终点不算，仍离边缘至少 2 格。
- 缺省值有两个选择：
  - **`0-2`（建议）**：有的轮次没有边缘点，有的有一两个，agent 要学会"什么时候需要刹车"，而不是"每个点都刹车"；
  - `0`：保持现在的行为，需要时用命令打开。

**"边缘"怎么定义**：本轮场地**最外一圈**的格子，即这一格挨着场地的边界（审阅意见，2026-11-28）。
- 起草时建议的是最外两圈，理由是只算一圈太苛刻。审阅时定为一圈：从里往外冲进这一格，过了格子中心再多走 0.5 格就离开了地面，必须在格子里停住或者及时转向。
- 这一格同样要满足"能出题"（地表、不危险、有路可走）。

**怎么抽**：
1. 先从 n 个中间点的序号里随机挑出 `edge` 个，作为边缘点；
2. 边缘点在最外一圈里抽，其余中间点按原来的规则抽（离边缘 ≥ 2 格）；
3. 点与点之间至少隔 4 格、每一段都到得了、起终点距离在 `dist` 里，这些规则不变；不满足就重抽，抽不出来就换地形（§8 第 1 条）。
- 不限制经过边缘点的方向。有的边缘点后一段沿着边走，冲过头也不掉；有的要掉头，冲过头就掉。这正好要 agent 自己判断。
- 模拟起伏和真实世界地形里，"边缘"只指场地的边界。场地内部的悬崖、坑本来就有，不另外算。

**给 agent 什么**：
- 文案不变，不说哪些点靠边；
- 判定说明不说哪些点是边缘点。掉下去时照常写"在哪里离开场地边缘"（Q14），这本来就是它自己的轨迹。

**记录与报告**：
- 记录加 `edgePoints`：边缘点的序号；
- 题目说明加一项，例如 `路线：平地，6 个点（2 个靠边），20 格`；
- 报告加 `--by edge`，按边缘点数分组，看到达率和掉落率怎么随它变化。

**建议：采用，缺省 `0-2`。**

## 5. 训练命令

### 5.1 完整格式

```
/bt train route [runs=<次数>] [seed=<种子>] [ground=<地形>] [memory=<记忆>] [size=<区块>] [points=<点数>] [edge=<边缘点数>] [dist=<距离>] [offset=<偏移>]
/bt train goal  [runs=<次数>] [seed=<种子>] [ground=<地形>] [memory=<记忆>] [size=<区块>] [dist=<距离>] [offset=<偏移>]
```

所有选项都可以不写，不写时按场地配置随机。

### 5.2 参数

| 参数 | 取值 | 缺省 | 含义 |
|------|------|------|------|
| `runs`、`seed` | 同弓箭方案 §5.2 | | |
| `ground` | 路线：`flat`、`synthetic`、`terrain`、`any`；寻路：`synthetic`、`terrain`、`any` | 场地配置，路线缺省 `flat`，寻路缺省 `synthetic` | 地形种类（§3），`any` 每轮在本题型能用的几种里等概率抽。寻路题不收 `flat` |
| `memory` | `prefill`、`none`、`any` | 场地配置，缺省 `prefill` | 开局是否把场地写进记忆（Q11） |
| `size` | `k` 或 `a-b`，2–4 | 路线 2，寻路 4 | 本轮场地的边长，单位区块（Q1） |
| `points` | `k` 或 `a-b`，1–8 | `2-4` | 路线题：中间点数（Q4） |
| `dist` | `a-b`，4–88 | 路线 `12-28`，寻路 `24-56` | 起终点的水平直线距离（Q4、Q5），不超过场地对角线 |
| `edge` | `k` 或 `a-b`，0–8 | `0-2` | 第四稿。路线题：放在场地边缘的中间点数，超过本轮中间点数时取中间点数（Q20） |
| `offset` | `k` 或 `a-b`，0–16 | `0-16` | 第四稿。本轮场地在 x、z 方向各自随机偏移的格数（Q19）；`0` 为固定位置 |

高差 `relief`（按地形种类分开）、悬崖数 `cliffs`、水面占比上限 `maxWater`、源区域 `terrainSources`、观察标记 `markers` 只放在场地配置里，不做命令选项。

### 5.3 相关命令

| 命令 | 含义 |
|------|------|
| `/arena land` | 传送到场地的场外平台 |
| `/bt train status` / `/bt train stop` | 同其他场地 |
| `node scripts/training-report.js route\|goal [--by ground\|memory\|dist\|points\|edge] [--last <N>] [--batch <批次>]` | 汇总训练记录（Q15；`edge` 是第四稿加的，Q20） |

### 5.4 示例

| 命令 | 效果 |
|------|------|
| `/bt train route runs=10` | ① 平地，2–4 个中间点，先练走准、转向、按顺序 |
| `/bt train route runs=5 points=1 dist=8-12` | ① 平地上经过一个点再到终点 |
| `/bt train route runs=10 ground=synthetic` | ② 模拟起伏，练上台阶、走下坎、绕开悬崖 |
| `/bt train route runs=10 ground=terrain` | ③ 真实世界上按顺序经过几个点 |
| `/bt train goal runs=10` | ④ 模拟起伏，4 × 4 区块，记忆预填 |
| `/bt train goal runs=10 ground=terrain` | ⑤ 真实世界，4 × 4 区块，记忆预填 |
| `/bt train goal runs=10 ground=terrain size=2 dist=12-24` | 小一点的真实地形，近一点的终点 |
| `/bt train goal runs=10 ground=terrain memory=none` | 不预填，要自己看（"按位置查"做完再正式练，Q12） |

## 7. 验收清单（实施后）

1. `/arena land` 能传送到场外平台；其他场地和它们的训练不受影响。
2. `/bt train route runs=3`：
   - 场地是 32 × 32 的草方块平地，场地以外是空的；玩家站在起点格子中心，冒险模式，物品栏是空的，满血满饱和；
   - 本轮结束后改回生存模式；
   - 文案里的起点、中间点、终点和记录一致。
3. 抽题检查（单元测试）：
   - 起终点距离、中间点数、点之间的间距、离边缘的距离在范围内；点都在地表上，不在原木上；
   - 每一段都存在不掉血的路线；
   - 模拟起伏满足 Q2b：相邻两列除了悬崖和坑的边缘，高差都不超过 1；每个坑都有坡道；高差在 `relief` 里；
   - 真实世界的窗口满足 Q3 的条件：水面占比不超过 `maxWater`，岩浆周围没有可燃方块，高差在范围内；
   - 同一种子出同一道题。
4. 可走性和游戏一致：
   - 在模拟起伏和真实世界地形上，按记录里的参照路线手动走一遍，不掉血、走得通；
   - 走下 3 格的坎不掉血，4 格掉 1 点；从 3 格的坎上跳下掉血（F1）。
5. 路线题，在游戏里手动验证：
   - 按顺序经过全部点，走到终点，判 `success`，用时从第一步算起；
   - 先走到第 2 个点再走第 1 个点，第 2 个点不算数，记录里有"顺序不对时到过"的 tick；
   - 没经过全部点就走到终点，本轮不结束；这时报完成，判 `false_success`，`faults` 有 `skipped`；
   - 走出场地边缘，掉下去，立刻被传送到场外平台，`doomed` 为 `fell`，记下离开边缘的位置。
6. 模拟起伏和真实世界地形：
   - 模拟起伏：只有草方块、泥土、石头；有台阶、坡、悬崖；掉进坑里会掉血，但能顺着坡道走出来；
   - 真实世界：
     - 有树、有坡，没有水：抽到一个有河或湖的窗口，原来的水面是一片和岸齐平的草地，水下是泥土，坡上原来有流水的地方是空气，没有悬空的海草、海带；含水的方块不再含水；
     - 树叶过一段时间也不掉；
     - 窗口里有箱子时，箱子是空的；有刷怪笼时，不刷怪；
     - 场地的生物群系和源窗口一致（F3 屏幕里看群系，草的颜色和源窗口一样）。
7. 观察标记（Q4b）：
   - 起点、中间点（带序号）、终点上有光柱，经过的点变灰；
   - 同一个画面，标记开、关各做一次 snapshot，结果完全一样；
   - 关掉 `markers` 以后不画。
8. 受伤：
   - 故意从 4 格高处走下去，判定说明里有一次 `minecraft:fall`，数值 1，位置和摔落距离对得上；到达后结果仍是 `success`，`hurt` 为 true；
   - 自然回血以后，记录里掉血的总量不变。
9. 记忆：
   - `memory=prefill`：发布任务时，`nbt_query` 能查到本轮场地露在外面的方块、方块实体、生物群系，查不到埋在里面的方块，也查不到上一轮的；`containers`、`entities` 在场地范围内是空的；
   - `memory=none`：发布任务时，五个数据源在场地范围内都是空的，snapshot 以后能查到看见的那些；
   - 连跑两轮不同的起伏地形，第二轮开局记忆里没有第一轮的东西；
   - 按 Q11 的"待核实"，核对清除生物群系对记忆端有没有影响，结论补进 Q11。
10. 死亡：在场地里死亡（比如走进岩浆），本轮结束，`doomed` 为 `died`，不会触发 P2 的 died 修复对话，下一轮能正常开局。
11. `training-report route` / `goal` 能按 `ground`、`memory`、`dist`、`points` 汇总。
12. 第四稿（L5）：
    - 单元测试：同一种子出同一个偏移；偏移在 `offset` 范围里；边缘点数 = min(抽到的值, n)，边缘点都在最外一圈，其余中间点和起终点离边缘 ≥ 2 格；
    - 游戏内：连跑几轮 `route`，场地位置每轮不同，上一轮的地板不残留；观察标记、记忆预填和本轮场地对得上；边长 4 加偏移 16 时场地完整，不越出场地范围；
    - 掉出场地的判定和"离开边缘的位置"在偏移后的场地上仍然正确；
    - `offset=0` 时场地回到原来的位置；
    - 开局耗时和第三稿相比，记一下增加多少；
    - `training-report route --by edge` 能分组。

**和方案的出入、方案里没写死的细节**：

1. **地形在出题之前放好**（§3 第 1 步）：新接口 `arena/land-build` 单独调用，插件在题型的 `preview` 钩子里调它，拿回格子信息再出题；`arena/prepare` 只放玩家、登记题目，不重建场地。真实世界的窗口不合格（水、高差、岩浆）或者出不了题，就换下一个窗口，最多 20 个；模拟起伏出不了题就换一张高度图，最多 5 张；每轮记录里的 `rejected` 是试过又放弃的那些。
2. **格子信息的格式**（Q3）：每列一个数组 `[地表那一面的序号, 面数, 脚高, 头顶净空, 危险, …]`。头顶净空最多记 6 格：走下 3 格要落点那一列留 3 + 1.8 格，4 格不够。细雪按没有碰撞算（人会陷进去），身体两格四周有仙人掌也算危险。
3. **可走性**（Q5）：上 ≤ 0.6 走上去，≤ 1 要跳（出发点头顶要留 dy + 1.8），走下 ≤ 3（落点那一列要留 drop + 1.8）；斜着走只在高差 ≤ 0.6、两个侧面的格子也有高差 ≤ 0.6 的面时才算。移动是有方向的，每一段都按有向图找最短路。
4. **死亡不让它真的发生**（Q9）：方案里留了"和 P2 的 died 请求怎么衔接"。实施时用 Fabric 的 `ALLOW_DEATH` 把本轮玩家的死亡拦下来（生命值留 1，记 `died`），下一 tick 回满血、传送到场外平台。不会真死，也就不会复活、不会触发 P2 的 died 请求。
5. **掉出场地**（Q10）：阈值是场地最低的方块 − 2（平地 y < 98，模拟起伏、真实世界 y < 94）；离开场地边缘时的位置另记一份（`edge`）。
6. **观察标记**（Q4b）：画在 HUD 上——每个点从脚的位置往上 3 格、每 0.15 格投影一个小方块，顶上写序号（起点"起"、终点"终"）；用本帧世界渲染的投影矩阵（`LevelRendererMixin` 交过来）。已经经过的中间点和终点变灰。
7. **记忆**（Q11）：`prepare` 返回之前，先等客户端载入本轮场地的全部区块（最多 10 秒），再在渲染线程上清除、预填、立即落盘。方块实体 store 的 `sync` 会顺带写一次观察者姿态文件（取当前相机），和视觉采集时一样。出错时 `memory` 是 `{ error }`，插件判 aborted 并停止整组。
8. **模拟起伏**（Q2b）：坡道朝场地中间（左右偏 60° 以内），免得伸出场地；最后再按高度图粗查一遍，坑的中心走不出来（坡道被后来的悬崖挡住了）就把这个坑填平，记录的 `cliffs` 里这一项带 `filled`。
9. **轨迹**（Q13）：每个点带真实的 tick（本轮从 prepare 起算），和事件、中间点的 tick 是同一套计数。
10. **命令行的 `dist`**：这一层放宽到 4–88（陆地寻路的上限），弓箭题的 setup 再按自己的上限（60 / 16）查。
11. **报告**（Q15）：`training-report route|goal`，缺省按地形分组（平地 → 模拟起伏 → 真实世界），`--by memory|dist|points`；记录里两种记忆模式都有时分成两张表。
12. **第四稿（L5，2026-11-28）**：
    - mod：`LandArena.SITE` 64 → 80；`arena/land-build` 收 `offset: [ox, oz]`（缺省 `[0, 0]`，超出 0 … 80 − 16·size 报错），返回里带 `offset`，`field` 是偏移后的本轮场地。build 记下两个西北角：整块场地（`prepare` 核对 origin、场外平台用它）和本轮场地（在不在场地里、掉出场地、预填、等客户端载入区块用它）。重建、清实体、清记忆仍按整块场地。
    - 插件：偏移在 `sample` 的最后抽（x、z 各一次），前面的随机数和第三稿一样，`offset=0` 时出题和第三稿完全相同。边缘点在 `sampleOnGraph` 里抽：先抽数量 k = min(抽到的值, n)、再洗牌挑 k 个序号，这些序号从最外一圈抽，其余照旧；`edge` 上限是 0 时不动随机数。寻路题传 `edge=` 会被当作不认识的选项拒掉。
