# 视角平滑转动设计方案

> 状态：**已实施**（2026-11-24），单元测试通过，mod 编译通过，待游戏内按 §5 验收。方案在对话中讨论、用户拍板后直接实施，本文是记录。
>
> 目标：`camera/turn`、`camera/look-at` 改成像人移动鼠标一样平滑转过去；保留一步到位的 `instant` 开关。开关由配置决定，agent 控制不了；两种转法对已有胶囊的效果完全相同。

## 1. 原来的实现

- `AgentCamera` 把整个角度差一次交给 `LocalPlayer.turn()`，相当于鼠标瞬间甩到位。
- 调用经 `mc.execute` 交给客户端线程就立刻返回 `{ status: "ok" }`，这时视角其实还没转。
- 胶囊库里有 38 个文件用到这两个接口，几乎都是"`camera/look-at` → 核对朝向（如 `code/aim.verify-facing`）→ `key/use-once`"，只依赖转完之后的朝向。快树没有用到视角接口，也没有胶囊在并行节点里转视角（2026-11-24 查过）。

## 2. 决定

### S1　转到位才返回

两种转法都在视角真正到位之后才返回。平滑转动如果立刻返回，后面的核对和 `key/use-once` 会在转到一半时执行，胶囊就坏了。顺带修掉了原来"没转就返回"的问题。

返回 `{ status: "ok", yaw, pitch, ms }`，`ms` 是转动用了多少毫秒（一步到位为 0）。

### S2　终点和原来逐位相同

- 终点在调用时一次算定：`look-at` 按调用时的眼睛位置算方向；偏航走最短路径；俯仰夹在 ±90°。
- 增量换算和原来调用 `Entity.turn` 时一样（先转成 float 再乘 0.15F），最后一帧直接设到终点，所以两种转法的终点和原来逐位相同。
- 中途不加抖动、不过冲：精确瞄准（如弓箭）只看终点，拟人化只体现在中途的速度变化上。

### S3　每帧推进，速度曲线拟人

- 平滑转动挂在真人鼠标转视角的同一处：`MouseHandler.handleAccumulatedMovement` 的末尾（新 mixin `MouseHandlerMixin`），每帧推进一次；客户端 tick 再推一次兜底（窗口不渲染时也能转完）。
- 速度曲线用最小加加速度曲线 s(t) = 10t³ − 15t⁴ + 6t⁵（起步、收尾慢，中间快，是人手移动的常用模型）。
- 时长 = 角度 ÷ `speed`，`speed` 是平均角速度（度/秒，30–3600），缺省 360：180° 用 0.5 秒，峰值约 675 度/秒。角度按偏航、俯仰的合成算。
- 每帧把视角设到曲线上的位置，其余和 `Entity.turn` 一样：上一帧的角度跟着加同样的增量（不做帧间插值），通知坐骑。
- 上一次还没转完又来一次视角调用：上一次以错误 `camera move superseded by a newer camera call` 结束，按新的一次转。离开世界时进行中的转动以错误结束。

### S4　异步应答，转动期间不挡其他请求

mod 的 WebSocket 在同一线程上按顺序处理一个连接的消息。转动期间如果这个线程一直等着，训练器的 `arena/status` 轮询、树里的其他调用都会排队。

- handler 可以返回 `CompletableFuture`，`AgentWebSocketServer` 不等它，完成时再发响应；`busyMethods` 到完成时才清掉。
- 异步应答最多等 10 秒（最慢的转动：30 度/秒转约 200°，约 7 秒），超时报 `<method> did not finish within 10000 ms`。

### S5　开关由配置决定，agent 改不了

- mod 的两个接口新增参数 `instant`（布尔，缺省 false）和 `speed`（缺省 360）。
- 插件配置 `camera: { instant: false, speed: 360 }`（`config.js`，`normalizeConfig` 校验）。
- agent 的一切 mod 调用都经过 `GameState.env`：对这两个接口，按配置补上 `instant`、`speed`；agent 自己写了其中任何一个就报错 `instant 由配置决定，调用里不能写`，调用不会发到 mod。
- `methods.js` 里这两个参数标成 `operator: true`，原始命令登记时跳过，agent 看到的参数只有 `dx, dy` / `x, y, z`；树里写了也过不了校验（未知参数）。
- 接口说明对两种转法写法一样（"转到位后才返回；转动的快慢由配置决定"），切换开关不改变 agent 看到的任何东西。
- 训练器、网页控制面板等直接调 mod 的地方不经过 `GameState.env`，不写这两个参数就是缺省的平滑转动。

## 3. 对已有胶囊的影响

| 方面 | 影响 |
|------|------|
| 转完之后的朝向 | 和原来逐位相同（S2），核对朝向、之后的操作照旧 |
| 调用什么时候返回 | 原来"交给客户端就返回"，现在"到位才返回"：原来紧跟着读朝向有可能读到旧值，现在不会 |
| 参数与说明 | 不变（S5），已有树、胶囊的校验结果不变 |
| 用时 | 平滑转动时每次转视角多花约 角度 ÷ 360 秒。复盘的成本画像、和以前任务的用时比较会变长；判定结果不受影响 |
| 服务端看到的朝向 | 平滑转动时服务端会收到中间的朝向。现有胶囊没有依赖这一点的 |
| 弓箭场地 F8（松手时用的是上一 tick 的朝向） | 不变：接口返回时客户端已到位，和原来一样 |

切换 `camera.instant` 只改变中途怎么转、用多长时间，以上各项结论对两种转法都成立。

**以后要注意**：快树如果用视角接口做战斗反射，平滑转动会让反应变慢，到时再考虑给快树单独的转法。

## 4. 改动

**mod**：`AgentCamera.java`（重写）、`api/CameraApi.java`、`AgentWebSocketServer.java`（异步应答）、`mixin/MouseHandlerMixin.java`（新）、`stevex.mixins.json`、`SteveXClient.java`（tick 兜底、离开世界时清掉）、`src/mod/methods.js`

**插件**：`src/game/state.js`（`CAMERA_METHODS`、按配置补参数、拒绝 agent 写的）、`src/game/raw_commands.js`（跳过 operator 参数）、`src/config.js`（`camera` 配置与校验）、`src/runtime.js`；测试 `test/camera.test.js`（新，3 条，也加进根目录的测试列表）。插件 349 条、根目录 348 条通过；`gradlew compileJava` 通过。

## 5. 验收清单（游戏内）

1. `camera/turn { dx: 180 }`：视角在约 0.5 秒里平滑转过去，先慢后快再慢；返回时 `ms` 约 500，`yaw` 比原来多 180。
2. 同样的调用在 `camera.instant: true` 下一步到位，`ms` 为 0；两种转法最后的 `yaw`、`pitch` 完全相同（同一起点各做一次比较）。
3. `camera/look-at` 对准一个方块，转完立刻读 `f3` 的准星目标，就是那个方块。
4. 转动期间另发 `player`、`arena/status`，照常立刻返回，不等转完。
5. 转动期间再发一次 `camera/turn`：第一次报 `camera move superseded`，第二次正常转完。
6. 在树里写 `['camera/turn', { dx: 10, instant: true }]`，校验报未知参数；绕过校验直接经命令环境调用，报"由配置决定"。
7. 跑一轮用到 `camera/look-at` 的训练（如 `/bt train craft3x3 runs=3`），结果和改动前一致。
