# 切石机训练场设计方案

> 状态：**Q-S1–Q-S4 已实施**（2026-11-15），单元测试通过，待游戏内按 §6 验收。审阅结论：Q1–Q13 全部采纳建议。实施时有两处和方案不同（随机数抽取顺序、Q8 的材料当量），见 §7。
>
> 本方案沿用《工作台训练场设计方案》（下称"3×3 方案"）和《箱子训练场设计方案》（下称"箱子方案"）的整体架构：插件主控，mod 以服务器身份操作场地；每轮一个新会话；记录写进 jsonl；"恰好达到"的时刻由 mod 在 tick 里检测。下面只写和它们不同的部分。
>
> 目标：在已有场地旁边另建一块场地，场内正前方放一台切石机。训练 agent 用切石机把指定材料切成指定数量的几种样式，要求不多不少。

## 1. 用户原始流程

1. agent 传送到对应的训练场地中。正前方放一台切石机，agent 的视角对着它，直接点右键就能打开
2. 清空 agent 身上的所有物品
3. 开始计时，并发布任务：
   - 从能切的材料里随机选 1–3 种（参数控制）
   - 每种材料占物品栏的 0–1/4 格，每格放随机个数（参数可以改成每格放满）
   - 每种材料随机选 0–3 种要切成的样式，把材料数量平均分成样式数那么多份，每份随机生成一个目标数量
   - 任务里只告诉 agent 有哪种材料，请它把这种材料分别切成各样式的目标个数
4. 检测到物品栏里的目标物品恰好是指定数量（不多不少）时，停止计时并记录

本方案保留这个流程。第 3 步的取值范围、目标个数的生成方法、多种材料之间的关系，按 §2 的事实做了调整（Q3–Q6）。第 4 步的判定沿用箱子方案的做法（Q8、Q9）。

## 2. 已核实的事实

数据来自游戏 jar 里 `data/minecraft/recipe/*.json` 中 `type` 为 `minecraft:stonecutting` 的条目，以及 `1.21.11_src` 的 `StonecutterMenu`、`AbstractContainerMenu`。

| # | 事实 | 对方案的影响 |

## 3. 总体设计

流程和箱子方案相同：插件出题 → `arena/prepare` 发放材料、补回切石机、对准视角、登记目标计数 → 发布任务 → 轮询 `arena/status` → 任务结束后调用 `arena/finish` → 判定并写记录。

插件侧新增一种训练题型 `stonecut`（和 `craft`、`storage` 并列），在一个新文件里实现，接口和 `storage.js` 相同。训练器、记录、报告、每轮新会话都直接复用。

mod 侧有三处改动：

1. 增加一种工作站 `stonecutter`；
2. 切石机工作站也返回物品栏、光标、输入格、地上的计数；
3. 增加一种"只看目标"的到达检测。

## 4. 决策点

### Q1　场地

新增场地 `stonecutter`，origin 设在 `(10000, 120, 10090)`，和箱子场地间隔 30 格，工作站为切石机。场地的搭建、清场、屏障墙、告示牌逻辑原样复用。`/arena stonecutter` 传送到场外平台，`/bt train stonecutter` 开始训练。

**建议：采用。**

### Q2　切石机的位置、朝向和视角

和 3×3 方案 W2 相同：切石机放在 `(ox, oy+1, oz+2)`，玩家朝 +z 站着，俯角由 mod 计算，`prepare` 返回前做射线自检 `aimOk`。F14 已经验证现有的俯角公式能对准切石机的顶面。切石机的 `FACING` 取朝向玩家，只影响外观。

**建议：采用。**

### Q3　材料池与按家族抽样

**材料池**：58 种材料，去掉 `exclude` 里的，再去掉在 Q4 规则下一种样式都切不出来的材料（默认只有玄武岩）。

| 方案 | 做法 | 效果 |
|------|------|------|
| A | 材料等概率抽 | 铜约占 28%（F4），每 3–4 轮就有一轮是铜 |
| **B** | **先在家族里等概率抽一个，再在家族里等概率抽一种材料**。8 个铜家族合并成 1 个"铜"家族，合并后共 29 个家族 | 铜约占 3.4%，和石头、深板岩、砂岩这些家族机会相同；同一家族里仍然覆盖不同材料 |
| C | 和 B 一样分家族，但铜不合并 | 铜约占 8/36 ≈ 22%，问题基本没解决 |

- 家族用并查集计算：材料 A 能切出材料 B，或者 A、B 能切出同一种产物，就把两者归为一家。铜合并的规则是：把 id 里的 `waxed_` 和氧化阶段前缀（`exposed_` / `weathered_` / `oxidized_`）去掉后，相同的归为一家。家族在出题时计算，不写成固定表。
- 用 `material=` 固定第一种材料时，不经过家族抽样。

**建议：B。**

### Q4　2×2 合成捷径

F6 的 25 个产物用物品栏的 2×2 合成也能做出来。

| 方案 | 做法 | 说明 |
|------|------|------|
| **A** | 默认不拿这 25 个"材料 → 产物"组合出题；参数 `bypass=keep` 可以放开 | 每道题都必须用切石机。agent 如果用 2×2 做出别的东西，会被判为切错 |
| B | 照常出题，用哪种方法都算对 | 一部分轮次根本没在练切石机；2×2 的消耗比例还不一样（比如铜块在 2×2 里是 4 → 4，在切石机里是 1 → 4） |
| C | 照常出题，但要求必须用切石机做出来 | mod 要区分产物来自哪个菜单，判定复杂，收益不大 |

只排除"同一种材料直接做出同一种产物"的组合。比如 agent 先用 2×2 把石头做成石砖，再用切石机把石砖切成石砖台阶，这仍然用到了切石机，不需要拦。

**建议：A。**

### Q5　一轮里有几种材料、各有多少

| 项 | 用户流程 | 建议 |
|----|---------|------|
| 材料种数 | 1–3 种 | 参数 `materials=k\|a-b`（1–3），默认 `1-3` |
| 每种材料占的格数 | 0 到物品栏的 1/4 | 参数 `slots=k\|a-b`（1–9），默认 `1-9`。下限从 0 改成 1，因为 0 格出不了题 |
| 每格放几个 | 随机，可以改成放满 | 复用箱子方案的 `fill=random\|full\|mix`：random 时每格在 [1, 64] 里随机，full 时每格 64 |
| 材料之间的关系 | 没有规定 | **同一个家族最多出一种材料**（Q3 的家族）。这样不同材料的产物不会重叠，任何一种材料也不会是另一种材料的产物（F4）。剩下的家族不够时，减少材料种数，记录里写实际数量 |
| 发放位置 | 没有规定 | 全部材料格在 36 格里随机分布，由 seed 决定 |

**建议：采用上表。** 刚开始训练时可以先用 `materials=1` 跑一组，再放开到 `1-3`。

### Q6　样式数和目标个数

对每种材料（共 N 个，占 s 格）：

1. **样式数 m**：在参数 `styles=k|a-b`（1–3，默认 `1-3`）的范围里随机，并且不超过这种材料能切出的样式数（扣掉 Q4 排除的）和 N。下限从 0 改成 1（F1）。
2. **选样式**：从能切出的样式里不重复地随机选 m 个。
3. **平均分**：每份 `share = ⌊N / m⌋`，除不尽的余数不分配，作为剩余材料留在物品栏里。
4. **每份消耗几个材料 c**：在 `[1, min(share, cap)]` 里随机；目标个数 **t = c × 每次产出**（F2）。这样一定能恰好切出来，而且不会超过这一份的材料。
5. **物品栏容量上限 cap**：设全部材料共占 S 格，全部样式共 M 个，每个样式最多能用 `b = ⌊(36 − S) / M⌋` 格放产物，那么 `cap = ⌊64 × b / 每次产出⌋`。
   - 因为 S ≤ 27、M ≤ 9，b 至少是 1。
   - 产物合计最多占 `M × b ≤ 36 − S` 格，所以按"把一叠材料放进输入格，切出来的产物放进空格"这种最直接的做法，物品栏一定装得下。
   - 例子：9 格铜块全部切成台阶本来要 72 格（F2、F3）；有 3 种材料、9 种样式、材料占 27 格时，b = 1，这个样式最多要 8 份铜块，也就是 64 个台阶。

不另外生成"材料不够"的题（箱子方案里的 `gt`），所以每道题都能做到。

**随机数的抽取顺序**（保证同一种子出同一道题）：材料种数 → fill（mix 时）→ 逐种材料（家族 → 材料 → 格数 s → 每格数量 → 样式数 m → 选 m 个样式）→ 算 b → 逐个样式抽 c → 打乱格位。每格数量要放在样式数之前，因为样式数不能超过材料数 N（§7）。

**建议：采用。**

### Q7　任务文案

按"只补能力与证据，不教写法"的原则，文案只说现状和要求，不提右键、按钮编号、Shift 点击，也不说材料有多少个。agent 可以自己用 `container/get` 和 Q11 的数据去查。

模板 `prompts/training/stonecut.md`：

```
你正前方有一个切石机，视角已经对准它。你的物品栏里有这些材料：{{materials}}。
请用切石机切出：{{list}}。切好的物品留在物品栏里，不要切出其他物品。
```

- `{{materials}}` 是材料 id 列表，例如 `minecraft:stone、minecraft:granite`
- `{{list}}` 按材料分组，例如 `用 minecraft:stone 切 10 个 minecraft:stone_slab、3 个 minecraft:stone_stairs；用 minecraft:granite 切 4 个 minecraft:granite_wall`
- 只有一种材料时也用同一个模板，`{{list}}` 只有一组

"用哪种材料切"属于题目本身。Q5 已经保证产物不重叠，写出来不会帮 agent 做决定，只是把要求说清楚。"不要切出其他物品"和箱子文案的"其他物品不要动"一样，是要求，不是做法。

**建议：采用。** 如果你认为"按材料分组"也算提示，可以改成只列"10 个 A、3 个 B、4 个 C"，让 agent 自己查每个产物用哪种材料切。

### Q8　判定

在任务结束时，按以下几处计数：物品栏（不含光标）、光标、切石机输入格（界面还开着时）、场内地上。判定顺序沿用箱子方案 C8：

| 顺序 | 结果 | 条件 |
|------|------|------|
| 1 | `aborted` | 手动停止 |
| 2 | `lost` | 切石机被挖掉；场内地上有物品（比如 Shift 切满后掉出来的，F10）；或者"材料当量"变少了 |
| 3 | `overshoot` | 任一目标在四处合计超过 t |
| 4 | `miscut` | 出现了题目没要的产物：任何开局时没有、也不是目标的物品 id 合计大于 0，包括没用完的中间产物（比如为了切石砖台阶先切出的石砖还剩下几个） |
| 5 | `timeout` | 超时 |
| 6 | `success` / `false_success` / `failed` | 任务以完成结束时，如果到达条件（Q9）成立就是 `success`，否则是 `false_success`；其余情况是 `failed` |

- **材料当量**：每个产物按"1 / 直接配方的每次产出"折算回材料（F5 保证这样折算和走哪条路无关），加上剩下的材料，应该等于开局时的材料数。为了避免分数，计算时整体乘 8。这一条能抓住 `dropped` 漏掉的情况，比如物品被扔出场外。
- 剩下多少材料不判；走中间产物也可以，只要最后不剩多余的产物。
- 记录里写 `movedOf`（每个目标实际切了多少）和 `extra`（多余产物及数量）。

**建议：采用。**

### Q9　"恰好达到"的检测（mod）

沿用箱子方案 C9：mod 在服务器 tick 里检测，记下第一次达到的时刻 `reachedAtMs`，不打断 agent。

`Expect` 增加一种只看目标的写法：`expect: { targets: {id: t}, allowed: [id...] }`，`allowed` 是全部材料和目标。同时满足下面几条就算到达：

1. 每个目标在物品栏里的数量恰好是 t，在光标和输入格里都是 0；
2. 光标为空；
3. 物品栏、光标、输入格里没有 `allowed` 以外的物品。

材料剩多少不比较（F5、F11）。原来箱子用的写法 `{inventory, container}` 保持不变。

`status` 对切石机工作站返回 `held`、`carried`、`cutterInput`、`dropped`。其中 `cutterInput` 是玩家当前打开的切石机界面的输入格（0 号格）；界面没开时为空。只读计数，不改动状态，`finish` 的顺序不用改。

**建议：采用。**

### Q10　记录与报告

每轮记录在箱子记录的通用字段之外，增加：

| 字段 | 含义 |
|------|------|
| `materials` | `[{ id, family, slots, count, styles: [{ id, yield, uses, want, made }] }]`，其中 `uses` 是 c，`want` 是 t，`made` 是实际切出的数量 |
| `materialCount`、`targetCount` | 实际的材料种数和样式总数（可能被 Q5 降低） |
| `layout` | 实际发放的格位 |
| `extra` | 多余产物（Q8） |
| `final` | `{ inventory, carried, cutterInput, dropped }` |
| `stationIntact`、`openedMs`、`reachedMs` | 同 3×3 方案和箱子方案 |

题目说明（label）的写法例如：`用 stone 切 10 个 stone_slab（×2，5 份）、3 个 stone_stairs；用 granite 切 4 个 granite_wall（2 种材料，3 种样式，seed=…）`。

报告增加 `--by materials|styles|yield|family`，并给 `miscut` 一个中文名"切错"。

**建议：采用。**

### Q11　切石配方数据

| 方案 | 做法 | 说明 |
|------|------|------|

  3. 家族名取不是同家族别的材料切出来的那种材料，比如石头家族叫 `stone`，铜叫 `copper`
- **实际数据**：默认（`bypass=exclude`）下，材料池是 57 种、28 个家族、229 个"材料 → 样式"组合。方案里写 29 个家族，少的那个是玄武岩，它唯一的样式被 Q4 排除了。`bypass=keep` 时是 58 种、254 个组合

- **和方案不同 2：没做 Q8 的"材料当量"检查**。实施时发现它会误判：
  - agent 走效率低的路时，实际消耗会多于按直接配方算的量。比如先用 2×2 把 4 个铜块做成 4 个切制铜，再切成 8 个台阶，消耗了 4 个铜块；按直接配方（1 个铜块切 8 个台阶）只算消耗 1 个，当量就会"变少"，被误判为 `lost`
  - 2×2 做出的其他东西（比如石头做的按钮）没有切石配方，无法折算
  - 所以 `lost` 只看切石机被挖和场内地上的掉落物。扔出场外的东西现在判不出来，箱子训练场也是这样
