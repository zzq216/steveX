# 锻造台训练场设计方案

> 状态：**M-S1–M-S4 已实施**（2026-11-21），单元测试通过，待游戏内按 §7 验收。审阅结论：决策点全部按建议执行。实施时和方案不同或补充的地方见 §8。已定的几点：
> - 文案不写"右键就能打开"，只写"正前方有一个锻造台，视角已经对准它"（M5）；
> - 纹饰目标只写目标，纹饰样式和材料直接用 mod 返回的 id（M5）；
> - "先升级再加纹饰"的连做题先不做，留作以后的选项（M12）；
> - 抽样分两层：先在"升级 / 纹饰"里等概率选一类，选到纹饰再分别抽样式、盔甲、材料（M3）；
> - 一轮 1–4 道题，可以用参数改（M3）。
>
> 本方案沿用《工作台训练场设计方案》（下称"3×3 方案"）、《箱子训练场设计方案》（下称"箱子方案"）和《铁砧训练场设计方案》（下称"铁砧方案"）的整体架构：
> - 插件主控，mod 以服务器身份操作场地；
> - 每轮一个新会话，记录写进 jsonl；
> - "恰好达到"的时刻由 mod 在 tick 里检测。
>
> 下面只写和它们不同的部分。
>
> 目标：另建一块场地，场内正前方放一个锻造台。训练 agent 用锻造台把钻石装备升级成下界合金装备、给盔甲加纹饰，一轮可能有几件要做，做好的物品放回物品栏。

## 1. 用户原始流程

1. agent 传送到对应的训练场地中。正前方放一个锻造台，agent 的视角对着它，直接点右键就能打开
2. 清空 agent 身上的所有物品
3. 开始计时，并发布任务：从锻造台配方中随机选 1–4 个，把需要的一份材料放进 agent 的物品栏，要求 agent 按配方把对应的物品锻造好，并把产物放回物品栏
4. 检测到物品栏里有对应的目标物品后，停止计时并记录

本方案保留这个流程的主体，按 §2 的事实做了几处调整：

- 不按"配方"等概率抽，改成先选类别、再抽具体组合（M3，已定）。纹饰配方一条对应约 300 种组合，按配方抽会让题目分布很偏；
- 文案只写目标，不写"右键打开"，也不列出发了哪些材料（M5）。列出材料等于告诉它每件用哪个模板；
- 判定看物品类型**和纹饰**，不看合成统计（M6）。加纹饰前后物品 id 不变，只看 id 会开局就判成功；
- agent 现在看不到物品上的纹饰，要先补上这项观测（M8）。

## 2. 已核实的事实

## 3. 总体设计

流程和铁砧场地相同，出题时先预览，再发题：

1. 插件出题：抽题数 n，逐道抽类别、底材、模板、材料，再抽格位；
2. `arena/smithing-preview`：用服务器上的锻造配方算出每道题的产物。做不出来的那道题重抽；
3. `arena/prepare`：补回锻造台，清物品栏，发放材料，对准视角，登记目标；
4. 发布任务，轮询 `arena/status`；
5. 任务结束后调用 `arena/finish`，判定并写记录。

插件侧新增题型 `smithing`，在新文件 `src/training/smithing.js` 里实现。抽题沿用铁砧题的做法，放在 `preview` 钩子里，训练器的公共流程不用改。

mod 侧的改动：

1. 增加工作站 `smithing_table`，场地 `smithing`；
2. 两个只读接口：`arena/smithing-catalog`（全部锻造配方、可加纹饰的盔甲、纹饰材料）、`arena/smithing-preview`（算产物）；
3. 一个 mixin 记下每次取出的产物；铁砧的 `AnvilQuickMoveMixin` 扩展到锻造台；
4. 锻造台工作站的 `status` 返回物品、三个输入格、取出记录；
5. 增加一种"锻造"写法的到达检测，可以有多个目标；
6. 物品信息补上 `trim` 和 `trimMaterial`（M8），对 agent 的全部观测都生效。

插件侧另外补一份锻造配方数据（M9）。

## 4. 决策点

### M1　场地

- **场地原点 (10000, 120, 10210)**：接在铁砧场地（10180）后面，间距 30 格，和工作台、箱子、切石机、熔炉、附魔台、铁砧场地排成一列。
- 锻造台和其他工作站一样放在 (ox, oy+1, oz+2)。锻造台是完整方块，没有朝向，`aimOk` 自检照用。
- 锻造台不会损坏（F11），每轮 `prepare` 的 `build` 照常补全场地即可，不用另外换新。
- **完好检查**：位置上的方块是锻造台。被挖掉不补放，判 `lost`（同 3×3 方案 W8）。

**建议：采用。**

### M2　题目来源：从游戏里读

`arena/smithing-catalog` 是只读接口，从服务器的配方管理器、物品标签和物品组件里实际读出，不手写清单：

```
arena/smithing-catalog → {
  upgrades:  [{ template, base, addition: [id…], result }],   // 12 条（F1）
  trims:     [{ template, pattern }],                         // 18 条（F1）
  armors:    [id…],                                           // trimmable_armor 标签，29 件（F2）
  materials: [{ item, material }]                             // 带 provides_trim_material 组件的物品，11 种（F7）
}
```

- 全部按 id 排序，保证同一个种子出同一组题；
- 插件在第一次出题时调用一次，同一组训练里缓存下来（同铁砧方案 §8 ②）。

**建议：采用。**

### M3　出题与抽样（已定：两层抽样，一轮 1–4 道）

**题数** n 在 `tasks`（缺省 `1-4`）里等概率抽。

**每道题**依次抽：

1. **类别**：`upgrade` / `trim` 等概率（已定）；
2. `upgrade`：12 条升级配方等概率抽一条。发放：升级模板、钻石底材、下界合金锭各 1 个。目标是配方的 `result`，不带纹饰；
3. `trim`：纹饰样式在 18 种里、盔甲在 29 件里、材料在 11 种里，各自等概率抽。发放：这种样式的模板、这件盔甲（不带纹饰）、这种材料的物品各 1 个。目标是这件盔甲，带 `{ pattern, material }` 纹饰。

**同一轮里不出完全相同的目标**：抽到和前面某道题目标相同（物品 id 和纹饰都相同）的，这一道重抽。物品 id 相同、纹饰不同的可以同时出现（例如两件铁胸甲，一件金纹饰，一件红石纹饰），这正是要练的配对。

> 一轮里有几道纹饰题时，模板、盔甲、材料要正确配对：把金锭放到了本该配红石的盔甲上，材料就用掉了，这一轮做不成。这是这个场地主要的难点。升级题之间材料可以互换，没有这个问题。

**格位**：同种物品合成一堆（F4：模板、下界合金锭等都能叠；盔甲、工具不能叠，各占一格），每一堆放在主物品栏 36 格里随机的格子。一轮最多 4 道题，最多 12 堆，放得下。

**抽取顺序**（同一种子出同一组题）：题数 → 逐道（类别 → 配方或样式 → 盔甲 → 材料）→ 格位。预览不通过（M4）时用 `seed + 重试次数` 整组重抽，最多 20 次；还不行就本轮 `aborted`，报"抽不出能做的题"。

**固定参数**：`kind=upgrade|trim` 只出一类；`base=<id>` 固定底材（升级题的钻石物品或纹饰题的盔甲），`pattern=<id>`、`material=<id>` 固定纹饰样式、纹饰材料（只用于纹饰题）。见 §5。

**建议：采用。**

### M4　出题预览

`arena/smithing-preview { template, base, addition }` 是一个只读的纯计算接口：

- mod 用这三件物品建一个 `SmithingRecipeInput`，交给服务器的配方管理器找锻造配方（和 `SmithingMenu.createResult` 106–122 行走同一条路），有配方就 `assemble`；
- 返回：

```
→ { result: { id, trim: { pattern, material } | null } | null }
```

插件只在每道题都有产物、产物和 M3 预期的目标相同时才发题。按 F1、F2，所有抽出来的组合都应该能做，所以这一步只是防止游戏数据和 catalog 对不上，正常情况下不会重抽。目标以预览的 `result` 为准，插件里不再写一份纹饰规则。

**建议：采用。**

### M5　任务文案（已定：只写目标）

文案只说现状和要做出的物品，不说怎么打开、哪件放哪一格，**也不列出物品栏里发了什么**。列出来就等于告诉它每件用哪个模板、哪种材料。模板 `prompts/training/smithing.md`：

```
你正前方有一个锻造台，视角已经对准它。
你的物品栏里有做出下面 {{n}} 件物品所需的材料，每件正好一份：
{{goals}}
请用锻造台把它们都做出来，做好的物品放在你的物品栏里。
```

`{{goals}}` 每道题一行：

- 升级题：`1. minecraft:netherite_sword`
- 纹饰题：`2. 带纹饰（样式 minecraft:sentry，材料 minecraft:gold）的 minecraft:iron_chestplate`

说明：

- 物品、纹饰样式、纹饰材料都用注册名，和 M8 补上的 `trim` 字段写法一致，agent 可以直接比对；
- 纹饰材料写的是材料 id（`minecraft:gold`），不是物品 id（`minecraft:gold_ingot`），F7。找出对应的物品是 agent 自己的事，查得到（M8、M9）；
- "每件正好一份"是这一轮的事实，理由同铁砧方案 A5"经验等级足够"：不说的话，agent 会为"材料不够"写分支；
- 不说"右键打开"（3×3 方案 W6）。

**建议：采用。**

### M6　判定（只看最终状态）

**到达**：玩家身上（主物品栏、快捷栏、副手、盔甲栏，**不含光标**）能为每道题找到**各不相同**的一件物品，满足：

1. 物品 id 和目标相同；
2. 纹饰和目标相同：升级题**没有纹饰**；纹饰题的 `pattern` 和 `material` 都相同。

一件物品只能对应一道题（两道题的目标都是铁胸甲时，要有两件铁胸甲分别满足）。最多 4 道题，按回溯配对即可。

不看附魔、耐久、名字，不看是怎么做的、做了几次。**不用 `crafted` 统计**（F8）。**不要求关界面**（F9）。

任务结束时，按以下几处找物品：玩家身上、光标、锻造台的三个输入格（界面开着时）、场内地上。

| 顺序 | 结果 | 条件 |
|------|------|------|
| 1 | `aborted` | 手动停止；或者抽不出能做的题（M3） |
| 2 | `lost` | 锻造台不在了；或者"相关物品"的总件数少于 n：以上几处里，物品 id 是某道题的底材或目标的物品，加起来不到 n 件（有物品被扔出场外或丢进岩浆）。底材做成产物、件数不变，所以做错了不算丢失 |
| 3 | `timeout` | 超时 |
| 4 | `success` / `false_success` / `failed` | 任务以完成结束时，到达条件成立就是 `success`，否则是 `false_success`（比如配错了材料、只做了一部分、产物还拿在光标上）；其余情况是 `failed` |

- 记录里另记 `goalsMet`：结束时有几道题配得上，用来看部分完成的情况（M10）。
- 到达时刻 `reachedMs` 记第一次达到的时刻（沿用箱子方案 C9）。

**建议：采用。**

### M7　"恰好达到"的检测与取出记录（mod）

沿用箱子方案 C9：mod 在服务器 tick 里检测，记下第一次达到的时刻 `reachedAtMs`，不打断 agent。

`Expect` 增加一种锻造写法：

```
expect: { smithing: [{ item, trim: { pattern, material } | null }] }
```

玩家身上（不含光标）的物品能按 M6 配对上全部目标，就算到达。`prepare` 核对每个 `item`、`pattern`、`material` 都存在，不存在就报错。

**取出记录**：新增 mixin `SmithingTakeMixin`，挂在 `SmithingMenu.onTake` 开头。训练场正在进行时，记下这次的产物（id、纹饰）和时刻。Shift 点击时 `onTake` 拿到的是空物品（F8），所以把铁砧的 `AnvilQuickMoveMixin` 扩展到 `SmithingMenu`：对产物格的那一次先复制产物，`onSmithingTake` 拿到空物品时用这份副本。

**`status`**：锻造台工作站返回下面几项，只读，不改动状态。

- `items`：玩家身上的每一件物品（带 `trim`、`trimMaterial`，M8），不含光标；
- `carriedItem`：光标上的物品；
- `slots`：界面开着时三个输入格里的东西（`template`、`base`、`addition`）；
- `dropped`：场内地上的物品；
- `containerOpen`；
- `takes: [{ result: { id, trim }, ms }]`。

**建议：采用。**

### M8　补观测：物品上的纹饰（agent 的通用能力）

在 `InventoryApi.slotItem` 里加两个字段，`inventory/get`、`container/get` 和场地 `status` 都带上：

| 字段 | 什么时候有 | 内容 |
|------|-----------|------|
| `trim` | 物品带 `trim` 组件（加了纹饰的盔甲） | `{ pattern: "minecraft:sentry", material: "minecraft:gold" }` |
| `trimMaterial` | 物品带 `provides_trim_material` 组件（能当纹饰材料的物品） | `"minecraft:gold"` |

- 这是补观测，不是教做法。游戏里鼠标移到加了纹饰的盔甲上，提示框就会显示纹饰和材料；
- 有了 `trim`，agent 才能核对自己做对了没有；有了 `trimMaterial`，它看自己的物品栏就能知道哪件物品对应哪种材料（F7）；
- 场地 `status` 原来用 `AnvilArena.describe`（附魔和名字），改成同时带上这两个字段，铁砧场地不受影响。

**建议：采用。**

### M9　数据：锻造配方给 agent 查

出题不需要这份数据（M2 从游戏里读），但 agent 规划时要知道"哪个模板对应哪种纹饰样式""升级要什么"。现在它只能去读源码，而且锻造配方在 jar 的 json 里，不在源码里（F13）。按切石机方案 Q11 的 A，补一份数据：

- `extract-recipes.js` 同一次扫描 jar，多写一份 `data/smithing.json`：

```
{ source, recipes: [
  { name, type: 'transform', template, base, addition: [id…], result },
  { name, type: 'trim', template, base: [id…], addition: [id…], pattern }
] }
```

  标签展开成物品列表，共 30 条。重新生成后 `recipes.json`、`stonecutting.json`、`cooking.json` 逐字节不变；
- `jsonSources` 增加 `smithing`；`data_shapes` 的说明加一句：`trim` 配方的 `pattern` 就是产物 `trim.pattern` 的值；
- `extract-item-props.js` 给能当纹饰材料的物品加 `trimMaterial` 字段（读 `Items.java` 的 `.trimMaterial(TrimMaterials.X)`，再按 `TrimMaterials.java` 换成注册名），写进 `item-props.json` 和 `items.json`。材料 id 和物品 id 的对应关系（F7）只在源码里，配方里没有。

这三项都是游戏自带的事实，agent 用 `core.json.query` 查，和查合成、切石配方一样。

**建议：采用。**

### M10　记录与报告

每轮记录在通用字段之外，增加：

| 字段 | 含义 |
|------|------|
| `target` | 题目说明的简写，供日志、通知、`--by target` 用。一道题时是目标物品 id，多道题时用 `+` 连起来 |
| `kind` | 这一轮的类别：`upgrade`、`trim` 或 `mix`（两类都有） |
| `tasks` | `[{ kind, template, base, addition, goal: { item, trim } }]` |
| `retries` | 出题重抽了几次 |
| `layout` | 每堆物品的格位 |
| `takes` | 每次取出产物的记录（M7） |
| `goalsMet` | 结束时配得上几道题（M6） |
| `final` | `{ items, carriedItem, slots, dropped, containerOpen }` |
| `stationIntact`、`openedMs`、`reachedMs` | 同前几个方案 |

题目说明（label）举例：

- `锻造 1 件：netherite_axe（seed=…）`
- `锻造 3 件：iron_chestplate[sentry/gold] + iron_chestplate[wild/redstone] + netherite_boots（seed=…）`

报告增加 `--by kind|tasks|pattern|material`，锻造场地缺省按 `kind` 分组（`tasks` 按题数分组）；另列三栏：

- "多做"：`takes` 多于 n 次的轮数；
- "配错"：有一次取出的产物和任何一道题的目标都对不上的轮数（材料、样式或盔甲配错）；
- "部分完成"：`goalsMet` 大于 0 但小于 n 的轮数。

**建议：采用。**

### M11　超时、被挖、胶囊库

- **超时**：要做的事是最多 4 次"放三件、取产物"。`timeoutSec` 建议为 **600 秒**，和铁砧场地一样。
- **每轮重置**：补全场地、清物品栏（M1）。
- **被挖**：同 3×3 方案 W8 的 A，判 `lost`。
- **胶囊库**：原样带进训练。铁砧场地学到的"放进格子、取出产物"会迁移过来，格子编号不同（铁砧 0/1/2，锻造台 0/1/2/3）。训练前先备份 `src/capsules/`。

**建议：全部采用。**

### M12　暂不做的部分

以下内容等基本训练稳定后再考虑，现在不做：

- **连做题**（已定）：先把钻石盔甲升级成下界合金，再给它加纹饰（或者反过来，F5 两种顺序都行）。以后作为 `chain=1` 选项
- 换纹饰：底材本身已经带着别的纹饰（F6）
- 底材带附魔、掉了耐久（升级会保留，F5；不影响判定）
- 用工作台复制模板（7 颗钻石 + 模板 + 原料）
- 物品栏里放干扰物品，或者多给几份材料

## 5. 训练命令

### 5.1 完整格式

```
/bt train smithing [runs=<次数>] [seed=<种子>] [tasks=<题数>] [kind=upgrade|trim] [base=<物品>] [pattern=<纹饰样式>] [material=<纹饰材料>]
```

所有选项都可以不写，不写时按场地配置（M3）随机。选项之间用空格分隔，顺序随意。

### 5.2 参数

| 参数 | 取值 | 缺省 | 含义 |
|------|------|------|------|
| `runs` | 1–1000 的整数 | 1 | 连续跑几轮。每轮是一个新会话，各写一条记录 |
| `seed` | 0–4294967295 的整数 | 每轮随机 | 出题种子。第 i 轮用 `seed + (i−1) × 0x9E3779B9`，同一个 `seed` 永远出同一组题 |
| `tasks` | `k` 或 `a-b`，1–4 | 场地配置 `tasks`，缺省 `1-4` | 一轮几道题 |
| `kind` | `upgrade`、`trim` | 每道题两类等概率 | 只出这一类题 |
| `base` | 12 种钻石物品或 29 件可加纹饰的盔甲 | 随机 | 固定底材。钻石工具、矛、马铠、鹦鹉螺铠只能出升级题；钻石以外的盔甲只能出纹饰题；钻石盔甲两类都能出 |
| `pattern` | 18 种纹饰样式的 id（如 `minecraft:sentry`） | 随机 | 固定纹饰样式，只出纹饰题 |
| `material` | 11 种纹饰材料的 id（如 `minecraft:gold`） | 随机 | 固定纹饰材料，只出纹饰题 |

固定参数对每一道题都生效。固定了 `base` 后，同一轮多道题的目标仍然不能完全相同（M3），抽不出足够的不同目标时少出几道。

**参数冲突时直接报错，不开始训练**：

- `kind=upgrade` 和 `pattern`、`material` 一起用；
- `kind=upgrade` 时 `base` 不是钻石物品，`kind=trim` 时 `base` 不是可加纹饰的盔甲；
- `base`、`pattern`、`material` 不在 catalog 里，或者在 `exclude` 里；
- 写了其他场地的选项（如 `n=`、`task=`、`xpLevel=`），按现有规则报"不认这些选项"。

### 5.3 相关命令

| 命令 | 含义 |
|------|------|
| `/arena smithing` | 传送到锻造台场地的场外平台（搭建或补全场地） |
| `/bt train status` | 当前训练的进度和累计结果 |
| `/bt train stop` | 中止当前轮（记 `aborted`），不再跑后面的轮次 |
| `node scripts/training-report.js smithing [--by kind\|tasks\|pattern\|material\|target] [--last <N>] [--batch <批次>]` | 汇总训练记录（M10）。缺省按 `kind` 分组 |

### 5.4 示例

| 命令 | 效果 |
|------|------|
| `/bt train smithing runs=10` | 按缺省设置跑 10 轮，每轮 1–4 道题 |
| `/bt train smithing runs=10 seed=42` | 10 轮，用种子 42 出题；再跑一次同样的命令会出同样的题 |
| `/bt train smithing runs=5 tasks=1 kind=upgrade` | 5 轮，每轮 1 道升级题 |
| `/bt train smithing runs=5 tasks=3 kind=trim` | 5 轮，每轮 3 道纹饰题，练配对 |
| `/bt train smithing runs=3 tasks=2 base=minecraft:iron_chestplate` | 3 轮，每轮两件铁胸甲加不同的纹饰 |
| `/bt train smithing runs=3 material=minecraft:resin` | 3 轮，纹饰材料都是树脂（发树脂砖） |

## 7. 验收清单（实施后）

1. `/arena smithing` 能传送到新场地的场外平台；其他场地和它们的训练不受影响。
2. `/bt train smithing runs=3`：
   - 每轮正前方是锻造台，`aimOk=true`，第一次右键就能打开；
   - 物品栏里只有本轮发的材料，同种物品叠成一堆，和记录里的 `layout` 一致。
3. 抽题检查（单元测试）：
   - 升级、纹饰两类各约一半；纹饰题的样式、盔甲、材料大致等概率；
   - 题数在 1–4 之间等概率；同一轮没有完全相同的目标；
   - 固定参数和冲突检查按 §5.2；
   - 同一种子出同一组题；预览不通过时整组重抽。
4. 预览检查（游戏内）：对几道题用真实锻造台手动操作，产物和预览一致。
5. 观测检查：
   - `inventory/get` 里加了纹饰的盔甲带 `trim`，金锭、青金石、树脂砖等带 `trimMaterial`；
   - `container/get` 打开锻造台时，产物格的预览物品也带 `trim`；
   - `core.json.query` 能查到 `smithing` 的 30 条配方，`items` 里的 `trimMaterial` 和游戏一致。
6. 在游戏里手动验证：
   - 升级题：普通点击取出、放回物品栏，`reachedMs` 有值，判 `success`；
   - 纹饰题：Shift 点击取出，`takes` 里的产物带正确的纹饰（F8 的修正生效），判 `success`；
   - 两道纹饰题把材料配反，两件盔甲的纹饰都不对，判 `false_success`，报告"配错"算一轮；
   - 多道题只做了一部分就报完成，判 `false_success`，`goalsMet` 正确，报告"部分完成"算一轮；
   - 产物还拿在光标上就报完成，判 `false_success`；
   - 东西留在输入格里、界面开着就结束，不判 `lost`；
   - 把一件底材扔出场外，判 `lost`；挖掉锻造台，判 `lost`。
7. `training-report` 能按 `kind` / `tasks` / `pattern` / `material` 汇总，并列出"多做""配错""部分完成"的轮数。
