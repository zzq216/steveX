# 砂轮训练场设计方案

> 状态：**K-S1–K-S3 已实施**（2026-11-23），单元测试通过，mod 编译通过，待游戏内按 §7 验收。审阅结论：K6 选**做法 B**（文案只写"祛魔"），其余决策点按建议执行。实施说明见 §8。
>
> 本方案沿用《工作台训练场设计方案》（下称"3×3 方案"）、《箱子训练场设计方案》（下称"箱子方案"）和《铁砧训练场设计方案》（下称"铁砧方案"）的整体架构：
> - 插件主控，mod 以服务器身份操作场地；
> - 每轮一个新会话，记录写进 jsonl；
> - "恰好达到"的时刻由 mod 在 tick 里检测。
>
> 下面只写和它们不同的部分。
>
> 目标：另建一块场地，正前方放一个砂轮。训练 agent 用砂轮给物品祛魔，并把产物拿回物品栏。

## 1. 用户原始流程

1. agent 传送到对应的训练场地中。正前方放一个砂轮，agent 的视角对着它，直接点右键就能打开
2. 清空 agent 身上的所有物品
3. 开始计时，发布任务：从所有能附魔的无附魔物品里随机选一件，附上耐久 III，放进物品栏，要求 agent 用砂轮给它祛魔，并把产物放回物品栏
4. 检测到物品栏里有对应的目标物品后，停止计时并记录

**审定的调整**（2026-11-23，讨论时分了四档难度）：

- 第 1 档（一件、只带耐久 III）和第 2 档（一件、随机附魔，可能带诅咒，可能是附魔书）**合并**：不再固定耐久 III，每件物品的附魔都随机，可能有诅咒，可能是附魔书；
- **保留第 3 档**：每轮 1 到多件；
- **删除第 4 档**：不出两件合并修复的题，不放干扰物品。

本方案在这个基础上，按 §2 的事实做了几处补充：

- 物品池限定为能附上耐久的物品，另加附魔书（K2）；
- 同一轮里不出现两件同种的有耐久物品，以免变成第 4 档的合并题（K3）；
- 文案只列出物品和附魔，请 agent 用砂轮祛魔，不写磨完的样子（K6，已定做法 B）；
- 判定看物品栏里的物品**恰好**是目标，而不只是"有目标物品"（K7）。

## 2. 已核实的事实

数据来源：`1.21.11_src` 里的 `GrindstoneMenu`、`GrindstoneBlock`、`ExperienceOrb`、`Enchantments`、`AnvilMenu`；mod 的 `arena/AnvilArena.java`、`arena/ArenaManager.java`、`api/ContainerApi.java`、`api/InventoryApi.java`。

| F11 | **诅咒**：<br>- 绑定诅咒只能附在 `equippable_enchantable` 上：盔甲、鞘翅等（`Enchantments` 390–393 行）；<br>- 消失诅咒能附在 `vanishing_enchantable` 上，包括所有有耐久的物品（1138–1141 行）；<br>- 工具和武器只能带消失诅咒，盔甲两种都能带 | 每件物品能带的诅咒按目录里这件物品的附魔表抽（K4） |

## 3. 总体设计

流程和铁砧场地相同，但不需要预览接口：

1. 插件出题：件数、每件的种类、物品、附魔、格位；按 F4 算出每件的目标；
2. `arena/prepare`：放砂轮，清物品栏，发物品，对准视角，登记目标。mod 用真实的砂轮菜单逐件核对目标，对不上就报错；
3. 发布任务，轮询 `arena/status`；
4. 任务结束后调用 `arena/finish`，判定并写记录。

**不需要预览**：只要每件物品至少带一个非诅咒附魔（K4），单独放进砂轮就一定有产物，而且和原物品不同（F2、F4、F5），题目一定做得出来、分得清。目标可以在插件里算，由 mod 在 `prepare` 时用原版逻辑核对一遍（同合成器、酿造台的做法），不用再出题、预览、重抽。

插件侧新增题型 `grindstone`，在新文件 `src/training/grindstone.js` 里实现。

mod 侧的改动：

1. 增加工作站 `grindstone`、场地 `grindstone`；
2. `arena/anvil-catalog` 多返回附魔书能带的附魔；
3. 新文件 `arena/GrindstoneArena.java`：在 `prepare` 时核对目标，并比对物品签名；
4. 砂轮工作站的 `status` 返回物品和砂轮格子；
5. 增加一种"砂轮"写法的到达检测。

## 4. 决策点

### K1　场地、砂轮的摆法

- **场地原点 (10000, 120, 10420)**：接在村民场地（10390）后面，间距 30 格。
- 砂轮和其他工作站一样放在 (ox, oy+1, oz+2)，状态是 **`face=floor`、`facing=east`**（和铁砧的朝向一致）。默认状态是挂墙的（F9），挂墙也能用，但落地是玩家平时放的样子。
- **对准**：外形不是整块（F9），照样用 `aimOk` 自检。射线打不中时，像村民场地那样给砂轮单独设俯角。
- **不用每轮清空**：砂轮没有方块实体，输入格里的东西在关界面时退回玩家（F8）。`prepare` 原有的 `build` 会补回缺失的砂轮。
- **完好检查**：位置上是 `grindstone` 方块就算在。

**建议：采用。**

### K2　物品池

每件物品先抽**种类**，再在种类里抽物品：

| 种类 | 池 | 怎么抽 |
|------|----|--------|
| `item` | `arena/anvil-catalog` 的全部物品，也就是 `enchantable/durability` 标签（铁砧方案 F13），去掉 `exclude` 里的 | 沿用铁砧方案 A2 的分组：先等概率抽一类，再在类里抽一件 |
| `book` | `minecraft:enchanted_book` | — |

- **种类的比例**（待定）：缺省 `kind=mix`，每件以 **1/4** 的概率是附魔书。如果把附魔书只当成分组里的一类，概率约为 1/20，太少见。附魔书是唯一会换 id 的情况（F4），值得多练。`kind=item` 只出物品，`kind=book` 只出附魔书。
- **附魔书能带的附魔**：`arena/anvil-catalog` 多返回一项 `book: { enchantments: [...] }`，列出注册表里的全部附魔，格式和物品的一样（`maxLevel`、`curse`、`exclusive`）。生存模式下附魔书能带任何附魔（宝藏附魔来自战利品和交易），所以不按附魔台能出的范围限制。
- 物品、附魔都按 id 排序，保证同一个种子出同一道题。

**建议：采用；附魔书比例取 1/4。**

### K3　每轮几件

- **件数** k 在 `tasks`（缺省 `1-3`，范围 1–4）里等概率抽。
- **同一轮里有耐久的物品互不同种**：两件同种的放进同一个砂轮会被合并成一件（F3），那是已经删除的第 4 档。抽到重复的就在剩下的物品里重抽。
- **附魔书可以有多本**：两本书一起放进去没有产物（F3），不会合并。
- 有两件以上时，同时放两件进砂轮就没有产物（F3、F7）。这是第 3 档要学的地方，文案里不提。

**建议：采用。**

### K4　每件物品的附魔

1. **非诅咒附魔**：个数在 `enchants`（缺省 `1-3`，范围 1–5）里等概率抽。候选是这件物品能附的非诅咒附魔；依次抽，每次去掉已抽到的和冲突的，级数在 1 到最高级之间等概率抽。候选不够就少抽，**至少 1 个**（F5）。算法同铁砧方案 A3 第 3 步。
2. **诅咒**：个数在 `curses`（缺省 `0-1`，范围 0–2）里等概率抽，候选是这件物品能带的诅咒（F11）。工具和武器只有消失诅咒，抽 2 个时只能抽到 1 个。
3. 不再固定耐久 III（§1 的调整）。耐久只是候选附魔之一。

> `curses` 这个选项名铁砧题也用，在那里是开关（`0` / `1`）。砂轮题写成个数（`k` 或 `a-b`），由各题型自己解析。

**抽取顺序**（同一种子出同一道题）：件数 → 逐件抽（种类 → 物品类别 → 物品 → 非诅咒附魔个数 → 逐个抽附魔 → 诅咒个数 → 逐个抽诅咒 → 各附魔的级数）→ 格位。

**建议：采用。**

### K5　发放

- 每件放在主物品栏 36 格里随机的格子，数量 1。
- **满耐久**：在单件祛魔里耐久不会变，加上损坏值也没有用；而且损坏的、带经验修补的物品拿在手上时，会被经验球修好（F10），会让判定多一层。
- 没有自定义名字，`repair_cost` 是 0。
- 用 `prepare` 现有的 `items[].enchantments` 发放（F12）。

**建议：采用。**

### K6　任务文案（已定：做法 B）

**审阅结论：做法 B。** `prompts/training/grindstone.md`：

```
你正前方有一个砂轮，视角已经对准它。你的物品栏里有{{what}}：
{{items}}
请用砂轮给{{them}}祛魔，产物放回物品栏。
```

- `{{what}}`：一件时是"一件带附魔的物品"，多件时是"k 件带附魔的物品"；`{{them}}` 是"它" / "它们"；
- `{{items}}` 每件一行：`- 带 minecraft:sharpness 3 级、minecraft:vanishing_curse 1 级 的 minecraft:diamond_sword；`，最后一行以句号结尾。附魔写法同铁砧方案 A5；
- 不写磨完的样子，诅咒留着、附魔书变成书都要 agent 自己查出来；判定仍按 F4 算出的目标（K7）。

以下是审阅前列出的两种做法，留作记录。

**做法 A：写出每件物品祛魔后的样子。**

每件一行：

- `- 带 minecraft:sharpness 3 级、minecraft:unbreaking 2 级的 minecraft:diamond_sword → 不带附魔的 minecraft:diamond_sword`
- `- 带 minecraft:protection 4 级、minecraft:binding_curse 1 级的 minecraft:iron_chestplate → 只带 minecraft:binding_curse 1 级的 minecraft:iron_chestplate`
- `- 带 minecraft:mending 1 级的 minecraft:enchanted_book → 不带附魔的 minecraft:book`

理由：

- 和铁砧方案 A5 一样，写的是"做成什么样"，不是做法。铁砧题也写出了目标附魔。
- 只写"祛魔"的话，带诅咒的物品按字面是做不到的（诅咒去不掉，F4），agent 可能一直重试到超时。题目应当是做得到的目标。
- 附魔、物品写注册名，和 `container/get` 一致（同铁砧方案 A5）。

**做法 B：只写"请用砂轮给它们祛魔，产物放回物品栏"**，判定仍按 F4 算出的目标。这样考的是 agent 自己查出"诅咒留着""附魔书变成书"，但带诅咒的题按字面做不到。

**审阅前的建议是 A；审阅选了 B。**

### K7　判定（只看最终状态）

**物品签名**：id + 附魔（附魔书看存储的附魔）+ 损坏值 + 自定义名字。不看 `repair_cost`：只要是砂轮磨出来的，它就是对的（F4）；铁砧题也不看这一项。

**到达条件**：

- 玩家身上（主物品栏、快捷栏、副手、盔甲栏，**不含光标**）的物品按签名计数，**恰好**等于全部目标，没有别的东西；
- 光标为空。

和原流程第 4 步"物品栏里有目标物品"相比，多了"恰好"和"光标为空"，与其他训练场一致。

**不要求关界面**：产物在物品栏里就算完成。物品还留在输入格里，就不在玩家身上，自然不满足条件（F8）。

任务结束时，按以下几处找物品：玩家身上、光标、砂轮的输入格（界面开着时）、场内地上。

| 顺序 | 结果 | 条件 |
|------|------|------|
| 1 | `aborted` | 手动停止；或者 `prepare` 核对目标失败（K8） |
| 2 | `lost` | 砂轮不在了（被挖）；或者某件发放的物品在以上几处都找不到（扔出场外、丢进岩浆） |
| 3 | `timeout` | 超时 |
| 4 | `success` / `false_success` / `failed` | 任务以完成结束时，到达条件成立就是 `success`，否则是 `false_success`；其余情况是 `failed` |

**没做好的原因**（`faults`，`false_success` 和 `failed` 时记，可以有多项）：

| 原因 | 条件 |
|------|------|
| `left` | 有物品还带着非诅咒附魔（没磨） |
| `input` | 有物品留在砂轮的输入格里 |
| `cursor` | 光标上有东西 |
| `dropped` | 有物品在场内地上 |

**建议：采用。**

### K8　目标核对与到达检测（mod）

**`prepare` 核对**：给了 `expect.grindstone` 时，mod 对每件发放的物品临时建一个砂轮菜单（`new GrindstoneMenu(0, inventory)`，不绑定方块，不打开给玩家），只放这一件，读出产物格，再和插件给的目标比签名。对不上就报错 `grindstone data out of date`。

- 用的是原版的 `computeResult`，不另写一套规则。铁砧预览也是这样在服务器上临时建菜单来算的；
- 临时菜单不调用 `onTake`，不会生成经验球（F6）。

**`Expect` 增加一种砂轮写法**：

```
expect: { grindstone: { goals: [{ id, enchantments: { id: 级数 }, damage }] } }
```

满足 K7 到达条件的第一个 tick 记为 `reachedAtMs`，不打断 agent（沿用箱子方案 C9）。

**`status`**：砂轮工作站返回下面几项，只读，不改动状态。

- `items`：玩家身上的物品（各带签名的几项）；
- `carried`：光标上的物品；
- `slots { input0, input1 }`：界面开着时两个输入格里的东西；
- `dropped`：场内地上的物品；
- `containerOpen`、`stationIntact`。

**建议：采用。**

### K9　记录与报告

每轮记录在通用字段之外，增加：

| 字段 | 含义 |
|------|------|
| `target` | 各件目标的说明用 `+` 连起来（同锻造台题），供日志、通知、`--by target` 用 |
| `k` | 件数 |
| `items` | 发放的物品：`[{ slot, kind, id, enchantments, curses }]` |
| `goals` | 每件的目标签名 |
| `final` | `{ items, carried, slots, dropped, containerOpen }` |
| `faults` | K7 的原因 |
| `stationIntact`、`openedMs`、`reachedMs` | 同前几个方案 |

题目说明（label）举例：

- `砂轮 1 件 diamond_sword[sharpness 3、unbreaking 2]（seed=…）`
- `砂轮 3 件 bow[power 4] + enchanted_book[mending 1] + iron_boots[feather_falling 2、binding_curse 1]（seed=…）`

报告增加 `--by k|kind|curses`，砂轮场地缺省按 `k` 分组。`kind` 按"本轮有没有附魔书"分，`curses` 按"本轮有没有诅咒"分。另列两栏：

- "有没磨的"：`faults` 含 `left` 的轮数；
- "留在砂轮"：`faults` 含 `input` 的轮数。

**建议：采用。**

### K10　数据

不需要提取新数据：

- 物品池、附魔、诅咒、冲突关系都从 `arena/anvil-catalog` 读（F12、K2）；
- 目标由插件按 F4 算，由 mod 用原版逻辑核对（K8）。

agent 也不需要新数据（F13）。

**建议：采用。**

### K11　超时、被挖、胶囊库

- **超时**：`timeoutSec` 建议为 **600 秒**，和铁砧场地一样。最多 4 件，每件放进去、取出来。
- **被挖**：同 3×3 方案 W8 的 A。轮次中砂轮被挖掉不补放，记录 `stationIntact=false`，判 `lost`。
- **胶囊库**：原样带进训练。铁砧、锻造台学到的"放进格子、取出产物"会迁移过来。训练前先备份 `src/capsules/`。

**建议：全部采用。**

### K12　暂不做的部分

- 第 4 档：两件同种物品合并修复、物品栏里放干扰物品（已删除）
- 发放损坏的物品（K5）
- 带自定义名字的物品（名字会保留）
- 放不进砂轮的物品、数量超过 1 的堆
- 记录拿到了多少经验（F6 带随机数）

## 5. 训练命令

### 5.1 完整格式

```
/bt train grindstone [runs=<次数>] [seed=<种子>] [tasks=<件数>] [kind=item|book|mix] [item=<物品>] [enchants=<个数>] [curses=<个数>]
```

所有选项都可以不写，不写时按场地配置随机。选项之间用空格分隔，顺序随意。

### 5.2 参数

| 参数 | 取值 | 缺省 | 含义 |
|------|------|------|------|
| `runs` | 1–1000 的整数 | 1 | 连续跑几轮 |
| `seed` | 0–4294967295 的整数 | 每轮随机 | 出题种子，规则同铁砧方案 §5.2 |
| `tasks` | `k` 或 `a-b`，1–4 | 场地配置，缺省 `1-3` | 每轮几件（K3） |
| `kind` | `item`、`book`、`mix` | 场地配置，缺省 `mix` | 每件的种类；`mix` 时每件以 1/4 的概率是附魔书（K2） |
| `item` | 物品池里的物品 id | 不固定 | 每轮的第一件固定是它，其余照常抽 |
| `enchants` | `k` 或 `a-b`，1–5 | 场地配置，缺省 `1-3` | 每件带几个非诅咒附魔（K4） |
| `curses` | `k` 或 `a-b`，0–2 | 场地配置，缺省 `0-1` | 每件带几个诅咒（K4） |

**参数冲突时直接报错，不开始训练**：

- `item` 不在物品池里，或者在 `exclude` 里；
- `kind=book` 和 `item=<有耐久的物品>` 一起写，或者 `kind=item` 和 `item=minecraft:enchanted_book` 一起写；
- 写了其他场地的选项，按现有规则报"不认这些选项"。

### 5.3 相关命令

| 命令 | 含义 |
|------|------|
| `/arena grindstone` | 传送到砂轮场地的场外平台（搭建或补全场地） |
| `/bt train status` | 当前训练的进度和累计结果 |
| `/bt train stop` | 中止当前轮（记 `aborted`），不再跑后面的轮次 |
| `node scripts/training-report.js grindstone [--by k\|kind\|curses\|target] [--last <N>] [--batch <批次>]` | 汇总训练记录（K9），缺省按 `k` 分组 |

### 5.4 示例

| 命令 | 效果 |
|------|------|
| `/bt train grindstone runs=10` | 按缺省设置跑 10 轮 |
| `/bt train grindstone runs=5 tasks=1 curses=0 kind=item` | 5 轮最简单的题：一件、没有诅咒、不是附魔书 |
| `/bt train grindstone runs=5 kind=book` | 5 轮全是附魔书 |
| `/bt train grindstone runs=5 tasks=3-4 curses=1-2` | 5 轮多件、带诅咒的题 |

## 7. 验收清单（实施后）

1. `/arena grindstone` 能传送到新场地的场外平台；其他场地和它们的训练不受影响。
2. `/bt train grindstone runs=3`：
   - 每轮正前方是一个落地的砂轮，`aimOk=true`，第一次右键就能打开；
   - 物品栏里只有本轮发的物品，附魔和记录里的一致，都是满耐久。
3. 抽题检查（单元测试）：
   - 件数、种类的分布大致符合 K2、K3；
   - 每件至少一个非诅咒附魔，附魔互相兼容、级数合法，诅咒只出现在能带它的物品上；
   - 同一轮里有耐久的物品互不同种；
   - 目标按 F4 算：没有诅咒的附魔书变成 `minecraft:book`，带诅咒的只剩诅咒；
   - 同一种子出同一道题。
4. `prepare` 核对（游戏内）：故意传一个错误的目标，`prepare` 报 `grindstone data out of date`。
5. 在游戏里手动验证：
   - 单件：放进去、取出产物，`reachedMs` 有值，报完成后判 `success`；
   - 带诅咒的物品：产物只剩诅咒，判 `success`；
   - 附魔书：产物是 `minecraft:book`，判 `success`；
   - 两件不同的物品同时放进两个输入格，没有产物；
   - 没取产物就关界面，物品退回、附魔还在，报完成后判 `false_success`，`faults` 有 `left`；
   - 产物还拿在光标上就报完成，判 `false_success`，`faults` 有 `cursor`；
   - 物品留在输入格里就报完成，判 `false_success`，`faults` 有 `input`；
   - 把一件物品扔出场外，判 `lost`；挖掉砂轮，判 `lost`。
6. `training-report` 能按 `k` / `kind` / `curses` 汇总，并列出"有没磨的""留在砂轮"的轮数。
