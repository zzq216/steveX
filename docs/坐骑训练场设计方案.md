# 坐骑训练场设计方案

> 状态：**H-S1–H-S4 已实施**（2026-11-21），单元测试通过，待游戏内按 §7 验收。审阅结论：决策点全部按建议执行。实施时和方案不同或补充的地方见 §8。已定的几点（2026-11-21 分析后按建议）：
> - 抽题先在 5 组动物里等概率抽一组，再在组里抽一种，最后在"装上 / 卸下"里等概率抽（H3）；
> - 手拿鞍、马铠直接右键装上（不开界面）也算对，判定只看最终状态（H5）；
> - 动物无敌（H2）；
> - 驴、骡、羊驼在出题时挂好箱子，羊驼的力量在 1–5 里随机（H2）；
> - 物品沿用箱子场地的物品池，只取堆叠上限 64 的；"搬 k 个"沿用箱子场地的"恰好 k 个"判定（H3、H5）；
> - 文案只写目标，不写怎么打开、不写格子编号（H4）；
> - 骆驼组保留，可以在场地配置里排除（H3）。
>
> 本方案沿用《工作台训练场设计方案》（下称"3×3 方案"）、《箱子训练场设计方案》（下称"箱子方案"）和《铁砧训练场设计方案》（下称"铁砧方案"）的整体架构：
> - 插件主控，mod 以服务器身份操作场地；
> - 每轮一个新会话，记录写进 jsonl；
> - "恰好达到"的时刻由 mod 在 tick 里检测。
>
> 下面只写和它们不同的部分。和前面几个场地最大的不同是：**工作站是一只动物（实体），不是方块**。
>
> 目标：另建一块场地，场内正前方有一只已驯服、不会动的成年动物。训练 agent 通过动物身上的物品栏，给它装上或卸下鞍、马铠、地毯、鹦鹉螺铠，以及往它身上的箱子里放、取指定数量的物品。

## 1. 用户原始流程

1. agent 传送到对应的训练场地中。正前方是一只已驯服的成年动物，agent 的视角对着它，直接点右键就能打开它身上的物品栏；动物不能移动
2. 清空 agent 身上的所有物品
3. 开始计时，随机选一种动物，再随机选一个任务：
   1. **马、僵尸马**：①给 agent 一个马铠和一个鞍，要求装到马的马铠槽和鞍槽；②马身上装着鞍和一个马铠，要求取到自己的物品栏
   2. **驴、骡**：①给 agent 一个鞍和 2 格共 64–128 个同种物品（堆叠上限 64），要求装上鞍，并把其中 1–64 个放进驴的物品栏；②驴装着鞍，物品栏里有 2 格共 64–128 个同种物品，要求把鞍和其中 1–64 个取到自己的物品栏
   3. **骆驼、骆驼尸壳**：①给 agent 一个鞍，要求装上；②骆驼装着鞍，要求取下
   4. **羊驼、行商羊驼**：同驴、骡，鞍换成随机颜色的地毯
   5. **鹦鹉螺、僵尸鹦鹉螺**：同马，马铠换成鹦鹉螺铠
4. 检测到物品栏里有对应的目标物品后，停止计时并记录

本方案保留这个流程的主体，按 §2 的事实做了几处调整：

- **直接右键是骑上去，不是打开物品栏**（F5）。文案不写怎么打开，由 agent 自己发现（H4）；
- **鹦鹉螺离水会脱水死亡**（F8），它站在场地里的一格水坑里（H1）；
- 判定不只看玩家的物品栏，还要看动物的鞍槽、身体槽和箱子格（H5）。装上的任务做完后，物品栏里恰好没有了鞍；
- agent 现在读不了坐骑界面（F10），要先补上（H7）。

## 3. 总体设计

流程和箱子场地相同：

1. 插件出题：抽组、动物、任务、装备、物品、数量和格位；
2. `arena/prepare`：清掉上一轮的动物，生成新的动物并设好状态、装备、箱子内容；清玩家物品栏，让玩家下坐骑，发放物品，对准视角，登记目标；
3. 发布任务，轮询 `arena/status`；
4. 任务结束后调用 `arena/finish`（先让玩家下来），判定并写记录。

插件侧新增题型 `mount`，在新文件 `src/training/mount.js` 里实现。装备池要先问 mod（`arena/mount-catalog`），抽题沿用铁砧题的做法，放在 `preview` 钩子里。

mod 侧的改动：

1. 场地 `mount`，工作站是一只动物（"实体工作站"）：生成、记住 UUID、每轮换新、实体准星自检、动物不在了判丢失；鹦鹉螺组另挖一格水坑；
2. 只读接口 `arena/mount-catalog`：每种动物的鞍槽、身体槽能装哪些物品，箱子格数；
3. `prepare` 能生成动物、给它装备、往它的箱子里放物品；开局和结束都让玩家下坐骑；
4. `status` 返回动物的鞍槽、身体槽、箱子格，玩家物品栏，光标，地上掉落物，界面开没开，玩家骑没骑在上面；
5. 一种"坐骑"写法的到达检测；
6. `container/get` 支持坐骑界面（H7），对 agent 的所有任务都生效。

## 4. 决策点

### H1　场地、动物的位置

- **场地原点 (10000, 120, 10240)**：接在锻造台场地（10210）后面，间距 30 格。
- **动物的位置**：(ox + 0.5, oy + 1, oz + 2.5)，也就是其他场地放工作站那一格的中心，面朝玩家（朝 −z）。玩家站在场内中心朝 +z，和以前一样。
  - 骆驼最大（1.7 宽），它离玩家最近的一面在 oz + 1.65，玩家眼睛到它的距离约 1.2 格，在交互距离（3 格）内；
  - 动物的头不在玩家正前方也没关系：潜行右键、骑乘对整个碰撞箱都有效。
- **鹦鹉螺组的水坑**：把 (ox, oy, oz + 2) 这一格地板换成水源，鹦鹉螺站在坑里（y = oy）。四周是地板，水不会流出去；鹦鹉螺 0.95 高，整只泡在水里，不会脱水（F8）。僵尸鹦鹉螺也放在水坑里，同组一致。换成别的组时，`build` 把这一格换回石头。
- **俯角**：按"眼睛 → 动物碰撞箱中心"算。**准星自检**改成服务器端的实体射线检测：准星命中的是本轮这只动物（`aimOk`）。

**建议：采用。**

### H2　动物的生成与每轮重置

每轮 `prepare`：

1. 让玩家下坐骑（`stopRiding`），关界面；
2. 清掉场内的动物：上一轮记下 UUID 的那只，以及场地范围内所有能当坐骑的动物（马类、骆驼类、鹦鹉螺类）。防止上一轮没收拾干净时出现两只；
3. 生成本轮的动物，设置：
   - 成年；
   - 已驯服，主人是玩家（马类 `setTamed` + `setOwner`，鹦鹉螺 `tame`；骆驼恒为已驯服）；
   - **不能移动**：`NoAI`；
   - **无敌**（已定）：agent 误点左键不会把它打死；
   - **不会消失**：`setPersistenceRequired`；
   - 驴、骡、羊驼：挂上箱子；羊驼的力量按题目设成 1–5（已定，由种子决定，访问器 mixin）；
   - 卸下的题：鞍槽、身体槽装好题目给的装备，箱子格按题目放好物品（访问器 mixin 读写 `inventory`）；
4. 记下这只动物的 UUID。

**丢失**：本轮这只动物不在了（被推出场外，或者别的原因消失），判 `lost`。

**建议：采用。**

### H3　出题与抽样（已定：先抽组）

**抽取顺序**（同一种子出同一道题）：组 → 组里的动物 → 任务 → 装备 → 物品 → 总数和两格的分法 → k → 羊驼的力量 → 格位。

| 组 | 动物 | 鞍 | 身体槽 | 箱子 |
|----|------|----|--------|------|
| `horse` | 马、僵尸马 | 有 | 马铠，6 种等概率 | 无 |
| `donkey` | 驴、骡 | 有 | 无 | 15 格 |
| `camel` | 骆驼、骆驼尸壳 | 有 | 无 | 无 |
| `llama` | 羊驼、行商羊驼 | 无 | 地毯，16 色等概率 | 3 × 力量格，力量 1–5 等概率 |
| `nautilus` | 鹦鹉螺、僵尸鹦鹉螺 | 有 | 鹦鹉螺铠，5 种等概率 | 无 |

- **任务**：`equip`（装上）/ `unequip`（卸下），等概率。
- **装备**：只出这只动物能装的（H10）。
- **物品**（只有 `donkey`、`llama` 组有）：
  - 从箱子方案 C3 的物品池里抽，只要堆叠上限 64 的，去掉 `exclude`；
  - 总数 n 在 `total`（缺省 64–128）里等概率；
  - 分成两格：第一格 a 在 [max(1, n − 64), min(64, n − 1)] 里等概率，第二格 n − a。两格都不空、都不超过 64；
  - 要搬的数量 k 在 `move`（缺省 1–64）里等概率。缺省 n ≥ 64，k 不会超过总数；用参数把 `total` 调小时，k 的上限截到 n。
- **格位**：
  - 装上的题：鞍、装备、两格物品放在玩家主物品栏 36 格里随机的格子；
  - 卸下的题：两格物品放在动物箱子格里随机的两格（羊驼力量 1 时只有 3 格，也放得下）。
- **骆驼组**（已定）保留。场地配置的 `groups` 可以去掉它，或者只留某几组。

**建议：采用。**

### H4　任务文案（已定：只写目标）

不写怎么打开（潜行、骑乘、按键），不写格子编号。动物、物品都用注册名。模板放在 `prompts/training/mount_equip.md` 和 `mount_unequip.md`，用占位拼出这一题的要求：

装上：

```
你正前方有一只已驯服的 {{animal}}。
你的物品栏里有 {{given}}。
请{{goals}}。
```

卸下：

```
你正前方有一只已驯服的 {{animal}}，它身上装着 {{worn}}{{chestNote}}。
请{{goals}}。
```

例子：

| 题 | 文案 |
|----|------|
| 马，装上 | 你正前方有一只已驯服的 minecraft:horse。你的物品栏里有 1 个 minecraft:saddle、1 个 minecraft:iron_horse_armor。请把 minecraft:saddle 和 minecraft:iron_horse_armor 都装到它身上。 |
| 驴，装上 | 你正前方有一只已驯服的 minecraft:donkey，它身上挂着箱子。你的物品栏里有 1 个 minecraft:saddle、100 个 minecraft:cobblestone。请把 minecraft:saddle 装到它身上，并把 37 个 minecraft:cobblestone 放进它身上的箱子里，其余的留在你的物品栏里。 |
| 羊驼，卸下 | 你正前方有一只已驯服的 minecraft:llama，它身上装着 minecraft:red_carpet，挂着的箱子里有 minecraft:cobblestone。请把 minecraft:red_carpet 取下来，并从它的箱子里取出 37 个 minecraft:cobblestone，都放进你的物品栏，其余的留在它的箱子里。 |
| 骆驼，卸下 | 你正前方有一只已驯服的 minecraft:camel，它身上装着 minecraft:saddle。请把 minecraft:saddle 取下来，放进你的物品栏。 |

- "挂着箱子"是现状，不是做法：说明这只动物有箱子格；
- 卸下的题不写箱子里有多少个，和箱子方案 C7 一样，由 agent 自己去看；
- "其余的留在……"把"恰好 k 个"写清楚：多搬了算失败（H5）。

**建议：采用。**

### H5　判定（只看最终状态）

**到达条件**（同时满足；不要求关界面，也不要求下坐骑）：

1. 动物还在；
2. 动物的鞍槽、身体槽：装上的题是题目要求的物品，卸下的题是空的；
3. 动物的箱子格：按物品 id 合计，等于目标（装上的题：要搬的物品恰好 k 个；卸下的题：恰好 n − k 个）；
4. 玩家物品栏（主物品栏、快捷栏、盔甲、副手，**不含光标**）：按物品 id 合计，等于目标（装上的题：只剩 n − k 个物品；卸下的题：鞍或地毯、装备各 1 个，加上 k 个物品）；
5. 光标为空。

按 id 合计，不看格子位置：agent 整理过格子不算错。手拿装备右键装上也满足第 2 条（已定）。

**结果**（判定顺序同箱子方案 C8）：

| 顺序 | 结果 | 条件 |
|------|------|------|
| 1 | `aborted` | 手动停止；或者抽不出题 |
| 2 | `lost` | 动物不在了；或者场内地上有掉落物；或者各处物品总数比开局少 |
| 3 | `overshoot` | 搬多了：要搬的物品到了目标方的数量多于 k |
| 4 | `misplaced` | 物品数量都对，但装备不在该在的地方（比如鞍放进了驴的箱子格，而不是鞍槽） |
| 5 | `success` / `false_success` / `failed` / `timeout` | 任务以完成结束时，到达条件成立是 `success`，否则 `false_success`（搬少了、光标上还拿着、装备没装上等）；其余同 3×3 |

- 光标上还拿着东西时，`arena/finish` 先计数再清空光标（同箱子方案 C8）；
- 到达时刻 `reachedMs` 记第一次满足条件的时刻（同箱子方案 C9）。

**建议：采用。**

### H6　到达检测和过程记录（mod）

`Expect` 增加一种坐骑写法：

```
expect: { mount: { saddle: id | null, body: id | null, chest: { id: n }, inventory: { id: n } } }
```

`saddle` / `body` 为 null 表示这个槽要空着；这只动物没有这个槽时插件不写这一项（不检查）。mod 每 tick 按 H5 的 1–5 检测，记第一次满足的时刻。

另外在 tick 里记几个时刻，只记录、不判定：

| 字段 | 含义 |
|------|------|
| `openedAtMs` | 第一次打开这只动物的物品栏（当前界面是坐骑界面，且是这只动物的） |
| `rodeAtMs` | 第一次骑上它 |
| `equippedWithoutMenu` | 鞍槽或身体槽变化时界面没开着：用手拿着右键装上的 |

**建议：采用。**

### H7　补观测：`container/get` 支持坐骑界面（agent 的通用能力）

修 F10：当前界面是坐骑界面时，`container/get` 不再调用 `getType()`，返回：

```
type: "mount"
mount: { entity: "minecraft:donkey", uuid, saddle: { slot: 0, active: true }, body: { slot: 1, active: false }, chest: { from: 2, count: 15 } }
slots: [...]（同其他界面：有东西的格子）
```

- `active` 就是格子的 `isActive()`：告诉 agent 哪些格对这只动物能用（F1）；
- `chest.count` 是箱子格数（0 = 没有箱子格）；
- 格子编号和其他界面一样，可以直接拿去 `container/slot`。

这是补观测，不是教做法：玩家在游戏里看界面就能看到哪些格能用、有几个箱子格。修好之后，以后真实世界里打开马的物品栏也能用。

**建议：采用。**

### H8　下坐骑

agent 可能骑上动物（F5）。

- `prepare` 开头、`finish` 读完状态后，都让玩家下来（`stopRiding`），再关界面、传送。
- 记录里的 `ridingAtEnd` 记结束时还骑没骑着。只做记录，不影响结果。

**建议：采用。**

### H9　数据

不需要提取新数据：

- 每种动物能装什么、有几个箱子格，由 `arena/mount-catalog` 从游戏里实际读出（H10）；
- 物品池用现成的 `item-props.json`（箱子方案 C3）。

agent 也不需要新数据：装备的种类、动物的格子都能从 `container/get` 看到（H7）。

**建议：采用。**

### H10　装备池：由 mod 试出来

`arena/mount-catalog` 是只读接口：

```
→ { animals: [{ id, group, saddle: [item…], body: [item…], chest: 0 | 15 | "strength" }] }
```

- 对每种动物，mod 临时建一只（不放进世界），对全部物品逐个试 `isEquippableInSlot(物品, SADDLE / BODY)`，再加上 `canUseSlot` 和界面里格子的条件（`can_equip_saddle`、`can_wear_horse_armor`、羊驼），列出能装的物品；
- 全部按 id 排序，同一个种子出同一道题；
- 插件每组训练读一次，缓存下来（同铁砧方案 §8 ②）。

这样马铠、鹦鹉螺铠、地毯的清单不用手写，以后游戏加了新的铠甲也会自动进来。

**建议：采用。**

### H11　记录与报告

每轮记录在通用字段之外，增加：

| 字段 | 含义 |
|------|------|
| `target` | 题目说明的简写，例如 `donkey equip`（供日志、通知、`--by target` 用） |
| `group`、`animal`、`task` | 组、动物、装上 / 卸下 |
| `equipment` | `{ saddle: id \| null, body: id \| null }`：这一题涉及的装备 |
| `item`、`total`、`split`、`move` | 物品、总数、两格的分法、要搬的 k（只有 donkey、llama 组有） |
| `strength` | 羊驼的力量（只有 llama 组有） |
| `layout` | 物品的格位 |
| `openedMs`、`rodeMs`、`reachedMs` | H6 的时刻，减去计时起点 |
| `equippedWithoutMenu`、`ridingAtEnd` | H6、H8 |
| `final` | `{ saddle, body, chest, inventory, carried, dropped, containerOpen }` |
| `stationIntact` | 动物还在不在 |

题目说明（label）举例：

- `坐骑 马 装上 saddle + iron_horse_armor（seed=…）`
- `坐骑 驴 卸下 saddle + 37/100 cobblestone（seed=…）`

报告增加 `--by group|animal|task`，缺省按 `group` 分组；另列四栏：

- "放多"：`overshoot` 的轮数；
- "放错"：`misplaced` 的轮数；
- "骑上过"：`rodeMs` 有值的轮数；
- "不开界面装备"：`equippedWithoutMenu` 为真的轮数。

**建议：采用。**

### H12　超时、胶囊库

- **超时**：`timeoutSec` 建议 **600 秒**，同箱子、铁砧、锻造台场地。
- **胶囊库**：原样带进训练。箱子场地学到的"拆叠搬 k 个"会迁移过来，格子编号不同。训练前先备份 `src/capsules/`。

**建议：采用。**

### H13　暂不做的部分

以下内容等基本训练稳定后再考虑，现在不做：

- 骷髅马、猪、炽足兽（能装鞍，但没有物品栏界面，或者要另外的交互）
- 给驴、羊驼挂箱子 / 用剪刀取下装备
- 驯服动物（喂食、骑乘驯服）
- 同时有装备和箱子物品、而且要换装备（比如把铁马铠换成钻石马铠）的题
- 动物可以走动的题

## 5. 训练命令

### 5.1 完整格式

```
/bt train mount [runs=<次数>] [seed=<种子>] [group=horse|donkey|camel|llama|nautilus] [animal=<动物>] [task=equip|unequip] [item=<物品>] [total=<数量>] [move=<数量>]
```

所有选项都可以不写，不写时按场地配置（H3）随机。

### 5.2 参数

| 参数 | 取值 | 缺省 | 含义 |
|------|------|------|------|
| `runs` | 1–1000 的整数 | 1 | 连续跑几轮 |
| `seed` | 0–4294967295 的整数 | 每轮随机 | 出题种子，同前几个场地 |
| `group` | `horse`、`donkey`、`camel`、`llama`、`nautilus` | 场地配置 `groups` 里等概率 | 固定组 |
| `animal` | 10 种动物的注册名（如 `minecraft:mule`） | 组里等概率 | 固定动物，同时也就固定了组 |
| `task` | `equip`、`unequip` | 等概率 | 固定装上 / 卸下 |
| `item` | 物品池里的物品 id | 随机 | 固定要搬的物品；只出 donkey、llama 组 |
| `total` | `k` 或 `a-b`，2–128 | 场地配置 `total`，缺省 `64-128` | 两格物品的总数 |
| `move` | `k` 或 `a-b`，1–64 | 场地配置 `move`，缺省 `1-64` | 要搬的数量 k；超过总数时报错 |

`task` 和铁砧场地共用一个名字（取值不同）。`parseTrainArgs` 接受两边的取值，各自场地再按题型检查（同锻造台场地的 `kind`）。

**参数冲突时直接报错，不开始训练**：

- `animal` 不属于 `group`；
- `item`、`total`、`move` 和 `group=horse|camel|nautilus` 一起用（这几组没有箱子）；
- `move` 的下限大于 `total` 的下限；
- 写了其他场地的选项，按现有规则报"不认这些选项"。

### 5.3 相关命令

| 命令 | 含义 |
|------|------|
| `/arena mount` | 传送到坐骑场地的场外平台 |
| `/bt train status` / `stop` | 同前 |
| `node scripts/training-report.js mount [--by group\|animal\|task\|target] [--last <N>] [--batch <批次>]` | 汇总训练记录（H11），缺省按 `group` 分组 |

### 5.4 示例

| 命令 | 效果 |
|------|------|
| `/bt train mount runs=10` | 按缺省设置跑 10 轮 |
| `/bt train mount runs=5 group=donkey task=equip` | 5 轮驴、骡的装上题 |
| `/bt train mount runs=5 animal=minecraft:trader_llama` | 5 轮行商羊驼 |
| `/bt train mount runs=3 group=llama move=64` | 3 轮羊驼题，每轮搬 64 个 |

## 7. 验收清单（实施后）

1. `/arena mount` 能传送到场外平台；其他场地不受影响。
2. 10 种动物各生成一次：
   - 都是成年、已驯服，不会动，打不死；
   - `aimOk=true`；
   - 驴、骡、羊驼挂着箱子，羊驼的箱子格数等于 3 × 力量；
   - 鹦鹉螺在水坑里，一轮下来没有受伤；
   - 换一组后，上一轮的动物被清掉，水坑换回石头。
3. `container/get`：
   - 潜行右键打开马的物品栏，返回 `type: "mount"`，鞍槽、马铠槽 `active` 为真，`chest.count` 为 0；
   - 驴的身体槽 `active` 为假，`chest.count` 为 15；羊驼的鞍槽 `active` 为假；
   - 骑上去按 E 打开，结果相同。
4. 抽题检查（单元测试）：组、任务大致等概率；装备只出 catalog 里能装的；两格都在 1–64；k ≤ 总数；同一种子出同一道题；参数冲突按 §5.2 报错。
5. 在游戏里手动验证：
   - 马装上题：拿着鞍、马铠右键装上（不开界面），判 `success`，`equippedWithoutMenu` 为真；
   - 驴装上题：开界面放鞍，再拆叠放进 k 个，判 `success`；
   - 多放 1 个，判 `overshoot`；
   - 鞍放进驴的箱子格，判 `misplaced`；
   - 羊驼卸下题：取下地毯、取出 k 个，判 `success`；
   - 骑上去后报完成，`ridingAtEnd` 为真，下一轮开局玩家已经下来；
   - 光标上还拿着物品就报完成，判 `false_success`；
   - 扔一个物品到地上，判 `lost`。
6. `training-report` 能按 `group` / `animal` / `task` 汇总，并列出"放多""放错""骑上过""不开界面装备"的轮数。

## 8. 实施说明（2026-11-21）

**mod（H-S1、H-S2）**：`api/ContainerApi.java`、`arena/MountArena.java`（新）、`ArenaManager.java`、`api/ArenaApi.java`、`mixin/MountMenuAccessor.java`、`mixin/AbstractHorseAccessor.java`、`mixin/LlamaAccessor.java`（新）、`stevex.mixins.json`、`src/mod/methods.js`

- **补充 ①**：访问器是三个，不是两个：除了羊驼的力量（`setStrength` 调用器）和动物的箱子（`inventory` 访问器 + `createInventory` 调用器），坐骑界面对应的动物也是 protected 字段（`AbstractMountInventoryMenu.mount` / `mountContainer`）。`container/get` 和训练场都用 `MountMenuAccessor` 读它。
- `container/get`：坐骑界面报 `type: "mount"` 和 `mount { entity, uuid, saddle{slot, active}, body{slot, active}, chest{from, count} }`，`active` 就是界面格子的 `isActive()`。
- 实体工作站：工作站名 `mount`，在方块表里登记成空气，方块位置上不放东西；鹦鹉螺组的水坑由静态的 `mountWater`（prepare 按本轮的动物设）决定 `build` 把动物脚下那格地板铺成水源还是石头。
- 动物生成在 `MountArena.spawn`：`EntityType.create` → 成年、驯服（马类 `setTamed` + `setOwner`，鹦鹉螺 `setTame` + `setOwner`）→ 羊驼力量 → 挂箱子并重建物品栏 → 装备（先核对这一格对它能用、物品放得进）→ 箱子内容 → NoAI、无敌、不会消失 → 朝向 180°（面向玩家）。参数不对直接报错，不生成。
- **补充 ②**：俯角瞄准动物身高的 0.7 处（不超过顶下 0.2），不是中心：鹦鹉螺在坑里时，瞄中心的视线会擦着坑边的地板。
- **补充 ③**：动物"还在"要求活着、并且在场地范围里；它被清掉、跑出范围都判 `lost`。
- `finish` 读完状态后先 `stopRiding` 再关界面、传送（对所有场地都执行，其他场地本来就不会骑乘）。
- `gradlew compileJava` 通过。实体射线自检、NoAI 动物能不能骑、鹦鹉螺在坑里不脱水，都要游戏内验收确认。

- 抽题放在 `preview` 钩子里（先读 catalog），不需要预览重抽。
- **补充 ④**：物品池另外去掉了能当装备的物品（地毯等），免得要搬的物品和装备是同一种 id，计数混在一起。
