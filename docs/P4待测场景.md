## 共同准备

1. 跑单元测试确认代码状态：`steveX/dsh-plugins/agent/` 下逐个文件跑 `node --test test/<文件>.test.js`（整套 `npm test` 一起跑会卡住），全部通过
2. 启动 mod：`vendor/stevex-template-1.21.11` 里 `./gradlew runClient`（先关掉另一个 mod 的 runClient，否则卡 loom 锁），进**非极限、开作弊**的世界
3. 启动 DSH：`steveX\start-dsh.bat stevex`（**必须带 `stevex`**），新开会话，`/bt status` 有返回即插件已加载
4. 看日志：
   - 任务事件：`steveX/runtime/tasks/<taskId>/events.jsonl`（复盘相关：`reflect/start`、`capsule/saved`、`reflect/done` / `reflect/abandoned`、`task/failed` 的 `by`）
   - 胶囊库：`steveX/src/capsules/manifest.json`，条目在 `code/`、`trees/`
   - DSH 会话：`~/.dsh/sessions/<工作区>/session-*/session.v4.jsonl.zstd`，多帧 zstd，用 `$TEMP/rd.js` 读（看 `capsule_save` 的参数和被拒的错误原文）
5. 胶囊库里已经有第一轮存下的合成类胶囊（`crafting.*`、`inventory.wood-materials`、`container.is-type`）。场景 3 正要用它们；其余场景不受影响

## 场景 3：换一种起始条件，同一个胶囊仍然能用

**验什么**：胶囊没有写死格子号、坐标——换个背包布局 / 工作台位置，第一轮存下的胶囊照用；用不了时，复盘用 `replaces` 改进它。这是"可复用"的最低检验（P6 的多图准入是它的正式版）。

**为什么先不测**：要人专门摆出和第一轮不同的起始状态；第一轮只换了产物（木镐 → 木斧），没换布局。

**步骤**：
1. 清掉上次的产物；把原木 / 木板 / 木棍放到**和第一轮不同的格子**（例如从快捷栏挪到背包上排），工作台换个位置或朝向
2. `/bt task 现在面前有一个工作台，直接点击右键就可以打开，请合成一个木镐`
3. 跑完后看复盘

**期望**：
- 大纲或展开里引用了 `trees/crafting.put-recipe-and-take` 或 `code/crafting.*`（看 `trees/v<N>.json` 里的 `ref`）
- 胶囊里的点击全是按读到的格子算的（`container/slot "$…"`），任务 `done`
- 失败了：看是不是胶囊写死了什么；复盘里应当用 `replaces` 换掉它，老版本留着

**顺带验 2026-10-26 的改动**（[P4实施细则.md](P4实施细则.md) §10.3）：
- 复盘存代码胶囊时，不再因为合成格号 9 / 4、配方倍数 4、`planks` / `stick` 被字面量检查拒绝
- 真被拒时，错误里附一份 `keepLiterals` 模板，大模型照抄键一次通过
- 存子树时漏了 `read` 会被拒（错误写明"in this task n… called it with read: […]"）；没漏就不报

## 场景 4：大模型放弃的任务也复盘

**验什么**：任务以 `bt_abort_task` 结束（`by: agent`）→ 仍发复盘请求；结局可以是什么都不存，`summary` 写明理由（P4-D1）。

**为什么先不测**：要一个大模型自己判断"做不到"并放弃的任务。现在给它做不到的事，它多半会先规划、展开好几轮，不一定走到 `bt_abort_task`。

**步骤**：
1. 背包里只有木头、没有铁
2. `/bt task 现在面前有一个工作台，请合成一把铁镐`

**期望**：
- 大模型查配方发现缺铁 → `bt_abort_task` 写明原因
- `events.jsonl`：`task/failed` 带 `"by":"agent"`，紧接着 `reflect/start`
- 会话里出现"复盘请求 cN（任务 …，已结束：failed，你用 bt_abort_task 放弃…）"
- `bt_reflect_done` 结束；存不存都行，`reflect/done` 的 `reason` 里有理由
- 会话里**没有**单独的"任务已结束"通知（复盘请求代替了它）

## 场景 5：人 `/bt abort` 不复盘，`/bt reflect` 能手动发

**验什么**：人放弃的任务（`by: user`）只发结束通知、不发复盘请求；之后 `/bt reflect` 能对它手动发起复盘（P4-D1）。

**为什么先不测**：随时能手动触发，和场景 3、4 一起补测。

**步骤**：
1. `/bt task …` 随便一个任务，跑到一半
2. `/bt abort 不做了`
3. 看会话，再输入 `/bt reflect`

**期望**：
- 第 2 步后：只有"（执行器通知）任务 … 已结束：**failed**"，没有复盘请求；`task/failed` 带 `"by":"user"`
- 第 3 步后：命令回"复盘请求 cN 已发给大模型"，会话里的请求正文开头有"（人手动发起的复盘）"，结局写"人放弃"
- 复盘还没结束时再 `/bt reflect` → 报"还没结束"
- 开始下一个任务之后 `/bt reflect` → 报"没有已结束的任务"或"还在 running"（任务对象只留到下一个任务开始）

## 场景 6：复盘回合的工具限制

**验什么**：复盘回合里 `bt_inspect live`、`bt_submit_patch` 用不了；`capsule_save` / `bt_reflect_done` 只在复盘回合能用（P4-D4）。

**为什么先不测**：要大模型在复盘回合里主动去调这些工具；第一轮两次复盘都没调。可以在复盘回合里让人插话诱导，或者等它自然出现。

**步骤**：
1. 任务 `done` 后、复盘回合进行中，看会话里有没有这几种调用；没有就在复盘结束后的普通对话里让它"调用 capsule_save 存一个胶囊"

**期望**：
- 复盘回合里 `bt_inspect { what: "live" }` → 结果是"live is not available while reviewing a finished task…"
- 复盘回合里 `bt_inspect { what: "eval" }` 不带 `at` → "eval needs at…"
- 复盘回合里 `bt_submit_patch` → 被 guard 拒绝（"not available while answering an executor request"）
- 普通回合里 `capsule_save` → 被 guard 拒绝（"only for answering a task review (reflect) request"）
