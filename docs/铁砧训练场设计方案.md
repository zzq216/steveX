# 铁砧训练场设计方案

> 状态：**A-S1–A-S3 已实施**（2026-11-20），单元测试通过，待游戏内按 §7 验收。审阅结论：决策点全部按建议执行（含"不要求关界面"）。实施时和方案不同或补充的地方见 §8。已定的几点：
> - 任务文案只写目标，不写"放到格子 1 / 格子 2"（A5）；
> - 第二件物品的随机附魔默认不含诅咒，可用参数打开（A3）；
> - 只做合并的题里 agent 多改了名字，判失败（A6）；
> - 三种任务、两种第二件物品（同种物品 / 附魔书）都等概率抽（A3）。
>
> 本方案沿用《工作台训练场设计方案》（下称"3×3 方案"）、《箱子训练场设计方案》（下称"箱子方案"）、《附魔台训练场设计方案》（下称"附魔台方案"）和《信标训练场设计方案》（下称"信标方案"）的整体架构：
> - 插件主控，mod 以服务器身份操作场地；
> - 每轮一个新会话，记录写进 jsonl；
> - "恰好达到"的时刻由 mod 在 tick 里检测。
>
> 下面只写和它们不同的部分。
>
> 目标：另建一块场地，场内正前方放一个铁砧。训练 agent 用铁砧合并附魔、给物品改名，或者两样一起做，并把产物拿回物品栏。

## 1. 用户原始流程

1. agent 传送到对应的训练场地中。正前方放一个铁砧，agent 的视角对着它，直接点右键就能打开
2. 清空 agent 身上的所有物品
3. 开始计时，把 agent 的经验设成 216 级，并从下面三种任务里随机选一种发布（铁砧左右两个放物品的格子记作格子 1、格子 2）：
   1. **合并附魔**：从所有能附魔的无附魔物品里随机选一件，附上耐久 III，放进物品栏，要求 agent 把它放到格子 1。再从"同一种物品"和"附魔书"里随机选一种放进物品栏，它带有随机的、生存模式下合法的附魔，要求 agent 把它放到格子 2。最后让 agent 把产物拿回物品栏
   2. **改名**：同样给一件带耐久 III 的物品，要求 agent 在铁砧上把它的名字改成一串 8 个字符、中英文混杂的随机字符串，再把产物拿回物品栏
   3. **合并加改名**：把 1 和 2 结合起来
4. 检测到物品栏里有对应的目标物品后，停止计时并记录

本方案保留这个流程的主体，按 §2 的事实做了几处调整：

- 文案只写目标物品是什么样的，不说哪件放哪一格（A5，已定）；
- 物品池限定为能附上耐久的物品（A2）；
- 出题时先用原版铁砧的算法算出产物和花费，保证题目做得出来，且产物和原物品分得清（A4）；
- 每轮换一个新铁砧（A1）；
- 判定看物品类型、附魔、名字三项都完全对上（A6）。

## 3. 总体设计

流程和附魔台场地相同，出题时先预览，再发题：

1. 插件出题：抽任务、第二件物品的种类、物品、第二件的附魔、名字、格位；
2. `arena/anvil-preview`：用原版铁砧算出产物和花费。做不出来、花费 ≥ 40、产物附魔没有变化的，换一道题重抽；
3. `arena/prepare`：换新铁砧，清物品栏，设经验，发两件（或一件）物品，对准视角，登记目标；
4. 发布任务，轮询 `arena/status`；
5. 任务结束后调用 `arena/finish`，判定并写记录。

插件侧新增题型 `anvil`，在新文件 `src/training/anvil.js` 里实现。附魔台题用过的 `preview` 钩子直接沿用，训练器的公共流程不用改。

mod 侧的改动：

1. 增加工作站 `anvil`，场地 `anvil`；
2. 两个只读接口：`arena/anvil-catalog`（物品池和每件物品能用的附魔）、`arena/anvil-preview`（算产物和花费）；
3. `prepare` 能发带附魔的物品（普通物品带 `enchantments`，附魔书带 `stored_enchantments`），每轮换新铁砧；
4. 一个 mixin：在 `AnvilMenu.onTake` 里记下每次取出产物花了多少级；
5. 铁砧工作站的 `status` 返回物品、铁砧格子、损坏档、取出记录；
6. 增加一种"铁砧"写法的到达检测。

## 4. 决策点

### A1　场地、铁砧位置、每轮换新

- **场地原点 (10000, 120, 10180)**：接在附魔台场地（10150）后面，间距 30 格，和工作台、箱子、切石机、熔炉、附魔台场地排成一列。离信标场地 100 格，不在信标的效果范围内（信标方案 F4，4 级时水平 50 格）。
- 铁砧和其他工作站一样放在 (ox, oy+1, oz+2)，放在地板上（铁砧会下落，下面必须有方块）。朝向固定为 `east`，`aimOk` 自检照用（F15）。
- **每轮换新**：`prepare` 时先拆掉旧铁砧再放一个完好的（F10）。上一轮开裂、损坏或碎掉都不影响下一轮。
- **完好检查**：位置上的方块属于 `anvil` 标签就算在（开裂、损坏的铁砧也算），不在才判"被挖"。

**建议：采用。**

### A2　物品池

物品池是 `enchantable/durability` 标签里的全部物品（F13），去掉 `exclude` 里的。由 mod 的 `arena/anvil-catalog` 从游戏里实际读出，不手写清单：

```
arena/anvil-catalog → { items: [{ id, enchantments: [{ id, maxLevel, curse, exclusive: [id…] }] }] }
```

- `enchantments` 是能附到这件物品上的全部附魔（按 `supportedItems`，和铁砧的判断一致，F2），`exclusive` 是和它冲突的附魔；
- 物品、附魔都按 id 排序，保证同一个种子出同一道题；
- 插件在第一次出题时调用一次，同一组训练里缓存下来。

按类别分组，**先等概率抽一类，再在类里抽一件**（同附魔台方案 N3 的 B）。类别：

- 剑、斧、镐、锹、锄、矛（各类多种材质）；
- 头盔（含海龟壳）、胸甲、护腿、靴子（各类多种材质）；
- 弓、弩、三叉戟、重锤、鞘翅、盾牌、打火石、剪刀、刷子、钓鱼竿、胡萝卜钓竿、诡异菌钓竿（各 1 种）。

分组沿用附魔台题的 `kindOf`（按 id 后缀），补上后 8 种单独成类；`kindOf` 认不出的物品各自单独成一类。

> 注意：打火石、剪刀、刷子、两种钓竿、鞘翅、盾牌这几类能附的附魔很少，去掉诅咒后基本只剩经验修补（有的还有效率）。在"合并"题里，它们的第二件物品几乎总是带经验修补。题会重复，但都做得出来。

`item=<id>` 固定物品，这时跳过分组抽样。

**建议：采用。**

### A3　出题与抽样

**任务**（已定，等概率）：

| 任务 | 物品栏里的东西 | 目标 |
|------|--------------|------|
| `merge` 合并 | 物品 A（只带耐久 III）、第二件 B | 合并后的 A，**没有自定义名字** |
| `rename` 改名 | 物品 A（只带耐久 III） | 附魔不变、名字是指定字符串的 A |
| `both` 合并加改名 | 物品 A、第二件 B | 合并后、名字是指定字符串的 A |

**第二件 B**（已定，等概率）：

- `same`：和 A 同种的物品，耐久满，带随机附魔；
- `book`：附魔书，带随机附魔。

**B 的附魔**：

1. 个数 k 在 `enchants`（缺省 `1-3`）里等概率抽；
2. 候选是能附到 A 上的附魔（catalog 里这件物品的 `enchantments`），默认去掉诅咒（已定，`curses=1` 时保留）；
3. 依次抽 k 个：每次从候选里去掉已抽到的、和已抽到的冲突的，再等概率抽一个，级数在 1 到最高级之间等概率抽。候选不够 k 个时就少抽几个；
4. 这样 B 的附魔一定互相兼容，等级不超过最高级，在生存模式下合法。

> 附魔书只从"能附到 A 上"的附魔里抽，不放附不上去的附魔。附不上去的附魔会被跳过（F2），会让题目多一层，这放到以后再做（A11）。

**名字**（`rename`、`both`）：

- 8 个字符，汉字 c 个、英文字母 8 − c 个，c 在 1–7 之间等概率抽，保证两种都有；
- 汉字从一张约 500 个常用字的固定字表里抽，字母从 `A–Z a–z` 抽，最后打乱顺序；
- 不含空格、`§`、控制字符（F7），也不会和物品原名相同。

**格位**：一件或两件物品放在主物品栏 36 格里随机的格子。

**抽取顺序**（同一种子出同一道题）：任务 → 第二件的种类 → 物品类别 → 物品 → B 的附魔个数 → 逐个抽附魔和级数 → 名字 → 格位。预览不通过（A4）时用 `seed + 重试次数` 重抽，最多 20 次；还不行就本轮 `aborted`，报"抽不出能做的题"。

**建议：采用。**

### A4　出题预览：保证能做、分得清

`arena/anvil-preview { item, second, name }` 是一个只读的纯计算接口：

- mod 在服务器上临时建一个铁砧菜单（不绑定方块，不打开给玩家），放进两件物品的副本，有名字就设名字，然后读出产物和花费：

```
→ { result: { id, enchantments, name } | null, cost }
```

- 算法就是原版的 `createResult`，不另写一套合并规则。附魔台方案 N5 也是这样在服务器上临时建菜单来算的；
- 预览前先把玩家设成生存模式（F6；`prepare` 本来也要设），否则创造模式下算出的结果不对。

插件拿到预览后，满足下面三条才发题：

1. 有产物（`result` 不为空）；
2. 花费 ≤ 39（F3）；
3. `merge`、`both` 题：产物的附魔和 A 原来的附魔（只有耐久 III）不同（F4）。

`rename` 题恒能通过（花费 1）。目标物品就是预览的 `result`：物品类型、附魔、名字。

**建议：采用。**

### A5　任务文案（已定：只写目标）

文案只说现状和目标，不说哪件放哪一格、怎么改名、要点什么。三个模板：

`prompts/training/anvil_merge.md`：

```
你正前方有一个铁砧，视角已经对准它。你的经验等级足够这次使用。
你的物品栏里有一个带 {{baseEnchants}} 的 {{item}}，和一个带 {{secondEnchants}} 的 {{second}}。
请用铁砧做出一个带 {{resultEnchants}} 的 {{item}}，放在你的物品栏里。不要给它改名。
```

`prompts/training/anvil_rename.md`：

```
你正前方有一个铁砧，视角已经对准它。你的经验等级足够这次使用。
你的物品栏里有一个带 {{baseEnchants}} 的 {{item}}。
请用铁砧把它的名字改成「{{name}}」，改好的物品放在你的物品栏里。名字要一字不差，附魔不变。
```

`prompts/training/anvil_both.md`：

```
你正前方有一个铁砧，视角已经对准它。你的经验等级足够这次使用。
你的物品栏里有一个带 {{baseEnchants}} 的 {{item}}，和一个带 {{secondEnchants}} 的 {{second}}。
请用铁砧做出一个带 {{resultEnchants}}、名字是「{{name}}」的 {{item}}，放在你的物品栏里。名字要一字不差。
```

- 附魔写成"注册名 级数 级"，用顿号隔开，例如 `minecraft:sharpness 5 级、minecraft:unbreaking 3 级`。注册名和级数与 `container/get` 的 `enchantments` 一致。
- 物品用注册名（`minecraft:diamond_sword`、`minecraft:enchanted_book`）。
- **写出目标附魔**：这是"做成什么样"的要求，不是做法。不写的话，"合到一起"在附魔级数上有歧义（同级加 1、超过最高级截回）。
- **"不要给它改名"**：A6 判定多改了名字算失败（已定），要事先说清楚。
- **"经验等级足够"**：这是这一轮的事实，理由同信标方案 G5 第一句：不说的话，agent 会为"经验不够"写分支。
- 名字用「」括起来。名字里只有汉字和字母，不会和括号混淆。

**建议：采用。**

### A6　判定（只看最终状态）

**目标物品**：玩家身上（主物品栏、快捷栏、副手、盔甲栏，**不含光标**）有一件物品，同时满足：

1. 物品类型是 A 的类型；
2. 附魔和预览的 `result.enchantments` **完全相同**（多一个、少一个、级数不同都不算）；
3. 名字：`merge` 题**没有自定义名字**；`rename`、`both` 题的自定义名字和指定字符串**逐字相同**（多空格也不算）。

不看 `repair_cost`、耐久，也不看是怎么放的（同种物品放反，产物也一样，F5）。

**不要求关界面**：按原流程第 4 步，产物在物品栏里就算完成。关不关界面不影响结果（F11）。

**只做合并的题里多改了名字，判失败**（已定）：产物带了自定义名字，不满足第 3 条，按下表落在 `false_success` 或 `failed`。改了名再改回原名、或者清空名字框，产物不带自定义名字，算对。

任务结束时，按以下几处找物品：玩家身上、光标、铁砧的两个输入格（界面开着时）、场内地上。

| 顺序 | 结果 | 条件 |
|------|------|------|
| 1 | `aborted` | 手动停止；或者抽不出能做的题（A3） |
| 2 | `lost` | 铁砧不在了（被挖，或者取出 3 次以上碎掉了，F10）；或者以上几处都找不到 A 这种物品（A 被扔出场外或丢进岩浆） |
| 3 | `timeout` | 超时 |
| 4 | `success` / `false_success` / `failed` | 任务以完成结束时，到达条件（A7）成立就是 `success`，否则是 `false_success`（比如附魔不对、名字差一个字、多改了名、产物还拿在光标上）；其余情况是 `failed` |

- 铁砧自己碎掉的概率很低（新铁砧要取出 3 次以上，每次 12%），也算 `lost`，记录里能看出原因（`anvilState`、`takes`）。
- 到达时刻 `reachedMs` 记第一次达到的时刻（沿用箱子方案 C9）。之后 agent 又改动了物品，最终结果以结束时为准，`reachedMs` 仍然保留。

**建议：采用。**

### A7　"恰好达到"的检测（mod）

沿用箱子方案 C9：mod 在服务器 tick 里检测，记下第一次达到的时刻 `reachedAtMs`，不打断 agent。

`Expect` 增加一种铁砧写法：

```
expect: { anvil: { item, enchantments: { id: 级数 }, name: 字符串 | null } }
```

玩家身上（不含光标）有一件物品满足 A6 的三条，就算到达。

**经验**：每轮把等级设成 `xpLevel`（缺省 **216**，按原流程），经验进度清零。花费最多 39（F3），所以 ≥ 39 的任何值效果都一样。沿用附魔台场地 `prepare` 的 `xpLevel` 参数。

**mixin `AnvilTakeMixin`**：挂在 `AnvilMenu.onTake` 开头。训练场正在进行时，记下这次的花费（`getCost()`）、产物的附魔和名字、时刻。用途：

- 记录取出了几次、每次花多少级（A8）；
- 判断铁砧碎掉是不是取出造成的。

**`prepare`**：

- 新参数 `anvil: true` 时换新铁砧；
- `items` 的每一项可以带 `enchantments: { id: 级数 }`。附魔书写进 `stored_enchantments`，其他物品写进 `enchantments`；核对每个附魔都存在，级数在 1 到最高级之间，不符合就报错。

**`status`**：铁砧工作站返回下面几项，只读，不改动状态。

- `items`：玩家身上和光标上 A 这种物品、附魔书的列表（各带 `enchantments`、`name`）；
- `slots`：界面开着时两个输入格里的东西；
- `dropped`：场内地上的物品；
- `containerOpen`；
- `anvilState`：`anvil` / `chipped_anvil` / `damaged_anvil` / `missing`；
- `xpLevel`、`takes: [{ cost, enchantments, name, ms }]`。

**建议：采用。**

### A8　记录与报告

每轮记录在通用字段之外，增加：

| 字段 | 含义 |
|------|------|
| `target` | A 的 id（字符串，和其他题型一样供日志、通知、`--by target` 用） |
| `task` | `merge` / `rename` / `both` |
| `item` | A 的 id |
| `second` | `{ kind: 'same' \| 'book', id, enchantments }`；`rename` 题为 `null` |
| `name` | 指定的名字；`merge` 题为 `null` |
| `goal` | 预览的 `result`：`{ id, enchantments, name }` |
| `cost` | 预览的花费，也就是按"A 放左、B 放右"一次做完的花费 |
| `retries` | 出题重抽了几次 |
| `layout` | 物品的格位 |
| `takes` | 每次取出产物的记录（A7） |
| `levelsUsed` | 实际花掉的经验等级（开始的等级 − 结束的等级） |
| `anvilState` | 结束时铁砧的状态 |
| `final` | `{ items, slots, dropped, containerOpen }` |
| `stationIntact`、`openedMs`、`reachedMs` | 同前几个方案 |

题目说明（label）举例：

- `铁砧 合并 diamond_sword + 附魔书[sharpness 4] → sharpness 4、unbreaking 3（花费 6，seed=…）`
- `铁砧 改名 iron_boots →「风a雪Bc林dE」（seed=…）`
- `铁砧 合并加改名 bow + bow[power 2、mending 1] →「…」（花费 …，seed=…）`

报告增加 `--by task|item|second`，铁砧场地缺省按 `task` 分组；另列三栏：

- "多次取出"：`takes` 多于 1 次的轮数；
- "多花经验"：`levelsUsed` 大于 `cost` 的轮数。同种物品放反时花费可能更少，所以只统计多花的；
- "名字错"：`rename`、`both` 题里产物的附魔对、名字不对的轮数，以及 `merge` 题里多改了名的轮数。

**建议：采用。**

### A9　数据

不需要提取新数据：

- 物品池、每件物品能附的附魔、最高级、冲突关系、诅咒标记，都由 `arena/anvil-catalog` 从游戏里实际读出（A2）；
- 产物和花费由 `arena/anvil-preview` 用原版算法算（A4）；
- 插件里只有一张常用汉字表（写成常量）。

agent 也不需要新数据：附魔、名字、花费、经验都能从 `container/get` 和 `player` 读到（F12）。

**建议：采用。**

### A10　超时、被挖、胶囊库

- **超时**：要做的事是放一到两件物品、可能写一个名字、取出产物。`timeoutSec` 建议为 **600 秒**，和箱子、熔炉、附魔台、信标场地一样。
- **每轮重置**：换新铁砧、清物品栏、设经验（A1、A7）。
- **被挖**：同 3×3 方案 W8 的 A。轮次中铁砧被挖掉不补放，记录 `stationIntact=false`，判"丢失"（`lost`）。
- **胶囊库**：原样带进训练。其他场地学到的"放东西进格子"会迁移过来。训练前先备份 `src/capsules/`。

**建议：全部采用。**

### A11　暂不做的部分

以下内容等基本训练稳定后再考虑，现在不做：

- 修复题：给一件掉了耐久的物品，用材料或同种物品修复
- 附魔书里混入附不上去的附魔（F2，会被跳过）
- A 本身带多个随机附魔（现在只带耐久 III），包括和 B 冲突的附魔
- 两本附魔书合并
- 经验不够、"过于昂贵"、需要先分步降低花费的题
- 物品栏里放干扰物品

## 5. 训练命令

### 5.1 完整格式

```
/bt train anvil [runs=<次数>] [seed=<种子>] [task=merge|rename|both] [second=same|book] [item=<物品>] [enchants=<个数>] [curses=0|1] [xpLevel=<等级>]
```

所有选项都可以不写，不写时按场地配置（A2、A3）随机。选项之间用空格分隔，顺序随意。

### 5.2 参数

| 参数 | 取值 | 缺省 | 含义 |
|------|------|------|------|
| `runs` | 1–1000 的整数 | 1 | 连续跑几轮。每轮是一个新会话，各写一条记录 |
| `seed` | 0–4294967295 的整数 | 每轮随机 | 出题种子。第 i 轮用 `seed + (i−1) × 0x9E3779B9`，同一个 `seed` 永远出同一组题（A3 的抽取顺序） |
| `task` | `merge`、`rename`、`both` | 三种等概率 | 固定任务 |
| `second` | `same`、`book` | 两种等概率 | 固定第二件物品的种类 |
| `item` | 物品池里的物品 id（A2） | 先抽类别再抽物品 | 固定物品 A |
| `enchants` | `k` 或 `a-b`，1–5 | 场地配置 `enchants`，缺省 `1-3` | 第二件物品带几个附魔。候选不够时少抽（A3） |
| `curses` | `0`、`1` | 场地配置 `curses`，缺省 `0` | 第二件物品的附魔里能不能有诅咒 |
| `xpLevel` | 39–1000 的整数 | 场地配置 `xpLevel`，缺省 `216` | 每轮开始时的经验等级 |

**参数冲突时直接报错，不开始训练**：

- `task=rename` 和 `second`、`enchants`、`curses` 一起用（改名题没有第二件物品）；
- `item` 不在物品池里，或者在 `exclude` 里；
- `xpLevel` 低于 39（会出现取不出产物的题）；
- 写了其他场地的选项（如 `n=`、`station=`、`payment=`），按现有规则报"不认这些选项"。

### 5.3 相关命令

| 命令 | 含义 |
|------|------|
| `/arena anvil` | 传送到铁砧场地的场外平台（搭建或补全场地） |
| `/bt train status` | 当前训练的进度和累计结果 |
| `/bt train stop` | 中止当前轮（记 `aborted`），不再跑后面的轮次 |
| `node scripts/training-report.js anvil [--by task\|item\|second\|target] [--last <N>] [--batch <批次>]` | 汇总训练记录（A8）。缺省按 `task` 分组 |

### 5.4 示例

| 命令 | 效果 |
|------|------|
| `/bt train anvil runs=10` | 按缺省设置跑 10 轮 |
| `/bt train anvil runs=10 seed=42` | 10 轮，用种子 42 出题；再跑一次同样的命令会出同样的 10 道题 |
| `/bt train anvil runs=5 task=rename` | 5 轮改名题 |
| `/bt train anvil runs=5 task=merge second=book` | 5 轮"物品 + 附魔书"合并题 |
| `/bt train anvil runs=3 task=both item=minecraft:bow enchants=2` | 3 轮弓的合并加改名题，第二件带 2 个附魔 |
| `/bt train anvil runs=5 curses=1` | 5 轮，第二件的附魔里可能有诅咒 |

## 7. 验收清单（实施后）

1. `/arena anvil` 能传送到新场地的场外平台；其他场地和它们的训练不受影响。
2. `/bt train anvil runs=3`：
   - 每轮正前方是一个完好的铁砧，`aimOk=true`，第一次右键就能打开；
   - 经验等级是 216；
   - 物品栏里只有本轮发的一到两件物品，附魔和记录里的一致。
3. 抽题检查（单元测试）：
   - 三种任务、两种第二件物品各约一半或三分之一；
   - 物品类别大致等概率；
   - 第二件的附魔互相兼容、级数合法，默认没有诅咒；
   - 名字是 8 个字符，汉字和字母都有，没有空格和 `§`；
   - 预览不通过时会重抽；同一种子出同一道题。
4. 预览检查（游戏内）：
   - 对几道题，用真实铁砧手动操作，产物的附魔、名字、界面上的花费和预览一致；
   - 构造一道"花费 ≥ 40"的题，预览返回空产物，插件会重抽；
   - 玩家在创造模式下调用预览，结果和生存模式相同（预览先设成生存模式）。
5. 在游戏里手动验证：
   - 合并题：放好两件、取出产物，`reachedMs` 有值，报完成后判 `success`；
   - 合并题多改了名字，判 `false_success`，报告"名字错"算一轮；
   - 同种物品放反（B 放左、A 放右），产物附魔相同，判 `success`；
   - 附魔书放左、物品放右，没有产物；
   - 改名题：先放物品、再用 `container/text` 写名字，取出后判 `success`；
   - 先写名字、后放物品，名字被冲掉（F8），产物没有名字；
   - 合并加改名题分两次做（先合并再改名），判 `success`，`takes` 有 2 次，`levelsUsed` 比 `cost` 多 1，报告"多次取出""多花经验"各算一轮；
   - 产物还拿在光标上就报完成，判 `false_success`；
   - 把物品 A 扔出场外，判 `lost`；挖掉铁砧，判 `lost`。
6. 一轮里铁砧开裂后，下一轮 `prepare` 换回完好的铁砧。
7. `training-report` 能按 `task` / `item` / `second` 汇总，并列出"多次取出""多花经验""名字错"的轮数。

  - `anvilState`、`xpLevel`、`takes`。

**插件（A-S2、A-S3）**：`src/training/anvil.js`（新）、`trainer.js`、`config.js`、`index.js`、`prompts.js`、`prompts/training/anvil_{merge,rename,both}.md`、`report.js`、`scripts/training-report.js`
