# 训练课程设计大纲（草稿，2026-11-07）

> 状态：大纲，决策点已审定（§5）。审定后每个阶段再写详细方案（题型、出题、判定、mod 端训练场改动）。

## 0. 为什么要调整顺序

craft2x2 / craft3x3 收敛慢。看 4 轮 3×3 的日志，长推理几乎都花在物品栏操作上，合成本身（查配方、确认产物、终验）几乎不花时间：
- **定量拆分**：从一叠里分出恰好 k 个；
- **收拢碎叠**：把碎成多叠的同种物品合到一起；
- **同种材料分到多格、每格数量达标**。

每个新配方都会把这几个子问题重新组合一遍，agent 就把它们揉进一个整体规划器里重写。4 个任务里出现了 6 个规划器。

所以课程改为先单独练会物品栏操作，再练合成，最后练各种带界面的方块。

## 1. 总原则

1. **题目只给目标，不给方法**。指令写"把 X 放进 2 号快捷栏""背包里的 X 恰好分成 4 叠"，不写"用右键对半"。
2. **判定靠读状态**：每道题由训练场读 inventory / container 判定是否恰好达成。做多了、做少了、动了不该动的格子都算失败。
3. **技能在树这一层组合**：基础技能存成 compute 代码或子树。高层任务按顺序调用：compute 读真实状态 → forEach 执行点击 → 下一个 compute。沙箱代码之间不互相调用。
4. **每一族内部由易到难**：整叠 → 碎叠；一种物品 → 多种物品；空背包 → 背包里有干扰物品。
5. **什么时候进入下一族**：连续若干轮全部做对、没有再写新的规划器、规划用时降到稳定水平（由用户判断，见 D1）。
6. **回归**：进入新阶段后，定期穿插几轮旧题型，检查替换的新版本有没有把旧技能弄坏。

## 2. 阶段 A：物品栏操作（玩家背包界面 / 不开界面）

| 族 | 题型 | 出题 | 判定 |
|---|---|---|---|
| **A1 移动物品** | A1.1 把某格物品移到指定格（空格 / 有别的物品的格 → 交换） | 随机放几叠物品，指定源物品和目标格 | 目标格是该物品且数量不变，其余格不变 |
| | A1.2 穿戴盔甲（从背包或快捷栏穿到对应盔甲位；已穿着时换下） | 背包里放几件盔甲 | 盔甲位正确，换下的盔甲回到背包 |
| | A1.3 放到副手：开物品栏 / 不开物品栏两种 | 指定物品在背包或快捷栏 | 副手是该物品；不开物品栏的题，过程中界面始终没打开 |
| **A2 拆分与合并** | A2.1 把 n 格相同物品**合成** m 格（n > m，含 m = 最少叠数） | 同种物品碎成 n 叠 | 该物品恰好 m 叠，总数不变 |
| | A2.2 把 n 格相同物品**拆成** m 格（n < m），可指定每格数量 | 给 n 叠 | 恰好 m 叠（或每格数量符合要求），总数不变 |
| **A3 获取定量物品** | A3.1 从 n 格同种物品里取出恰好 k 个，放到指定格 | 给 n 叠，总数 > k | 目标格恰好 k 个，总数不变 |
| | A3.2 取出几份数量不同的物品，分别放到 p 个指定格（每格 k₁…kₚ） | 同上 | 每个目标格恰好 kᵢ |
| | A3.3 在合成格（2×2，不合成）的指定格里各放恰好 k 个 | 同上 | 合成格各格数量正确，产物格不取 |
| **A4 2×2 合成** | 用给定的 m 份材料恰好合成 n 个产物（沿用现有 craft2x2） | 现有出题 | 现有判定（恰好 n 个，不多做） |

**排期（2026-11-09）**：A1 延后。移动物品 agent 在合成摆料里已经会了；盔甲、副手和后面的合成、方块界面课程不衔接，等生存 / 战斗类任务需要时再和它们一起设计。新训练场跑通前可以用 1～2 轮"移动物品"做冒烟测试，不算正式课程。

说明：
- 原提纲里 2.1 / 2.2 的 n、m 写反了：**合并**是 n > m，**拆分**是 n < m，上表已按这个改过来。
- A3.2 / A3.3 是合成摆料去掉配方后剩下的核心部分，也是 3×3 日志里最耗时的部分，建议多练。
- A1.3 "不开物品栏"对应 `key/swap-hands`；"开物品栏"对应在界面里点击副手格。两种都有现成命令。

## 3. 阶段 B：带界面的方块

按"能复用多少阶段 A 的技能 + 布置训练场要做多少事"排序，前面的复用最多、布置最少：

| 顺序 | 方块 | 新增的东西 | 训练场布置 |
|---|---|---|---|
| B1 | 工作台 3×3 合成 | 打开方块界面、3×3 格号对照（沿用现有 craft3x3） | 已有 |
| B2 | 箱子 / 漏斗：存取物品 | 容器格和背包格之间搬运，不同容器的格号对照；物品放进漏斗后会被传走（看 D5） | 放一个容器，可预置物品 |
| B3 | 切石机 | 放料后从方案列表里按按钮选（`container/button`），取产物 | 放方块 + 给石料 |
| B4 | 织布机 | 三个输入格 + 按钮选图案；图案按钮是全局下标 | 放方块 + 给旗、染料、图案 |
| B5 | 熔炉（原提纲没有，建议加） | **要等**：燃料、烧制进度，产物过一会儿才出来 | 放方块 + 给燃料、原料 |
| B6 | 附魔台：附魔、刷新选项 | 青金石支付、经验等级、书架数；"刷新"要先附魔一次或换物品 | 放附魔台 + 书架 + 给经验 |
| B7 | 信标 | 选主效果 / 副效果、支付物；`container/beacon` | 要搭金字塔底座 |
| 之后 | 铁砧、锻造台、酿造台、村民交易…… | 按需 | 按需 |

原提纲把漏斗排在第 3 位。它其实只是普通容器操作，建议提到 B2，和箱子一起练。附魔台和信标的布置最重，放到最后。

## 4. 要做的工程

- **mod 端**：`arena/prepare` 目前只会布置合成题。每个新题型都要能布置初始背包或方块，`arena/status` / `arena/finish` 要能返回判定需要的状态。
- **插件端**：训练器每个题型一个出题器和一个判定器；`config.training` 增加题型和难度分级；新题型的训练记录照现有格式写。
- **提示词**：只改题目的说法，不改方法论。
