> 本方案沿用前几个训练场的整体架构（见《告示牌训练场设计方案》等）：
> - 插件主控，mod 以服务器身份操作场地；
> - 每轮一个新会话，记录写进 jsonl；
> - "恰好达到"的时刻由 mod 在 tick 里检测。
>
> 下面只写和它们不同的部分。
>
> 目标：新建一块场地，agent 站在场地边缘的平台上，前方 48 × 48 × 48 格的空中随机放 1–4 个标靶。每个标靶指定一个面，agent 要把弓拉满，用一支箭射中这个面。训练 agent 掌握弓箭的弹道：蓄力、下坠、抬高多少。移动靶留到战斗训练。

## 1. 用户原始流程

1. agent 传送到对应的训练场地中，站在场地的边缘位置，面前是一块没有任何方块的空场地
2. 清空 agent 身上的所有物品
3. 给 agent 一把弓和箭
4. 开始计时，发布任务：场地里随机放 1–4 个标靶；对每个标靶，在 agent 看得到的面里随机抽一个，取这个面的中点，要求 agent 把弓蓄满力，把箭射到这个中点；有多个标靶时依次射
5. 检测到箭射到所有的对应位置后，停止计时并记录

**审定的调整**（2026-11-24，讨论时确定）：

1. **场地 48 × 48 × 48 格**：原来写的 16 × 16 × 16 个区块（256 格见方）太大。满蓄力的箭在同一高度最远约 116 格，48 格以外即使瞄准完全正确，也有三成以上打不中整个面，结果主要看运气（F5）。
2. **不给无限附魔，箭数等于标靶数**：每个标靶只有一次机会，agent 要在射之前就算好，不能靠多射几次碰运气（Q4）。
3. **命中判定**：箭射中指定标靶的指定面就算命中，另外记录命中点离中点多远，作为准度指标（Q6）。中点是 1/30 格见方的区域，几乎只能靠运气射中（F3、F6）。
4. **离开平台整局判失败**（Q7）。
5. **不强制射击顺序**：射中哪个标靶就算哪个（Q6）。

**第一稿审阅意见**（2026-11-24）：

6. **弓和箭随机放在物品栏里**，不指定位置，开局不在手上（Q4）。
7. **不开放视觉**：任务中看不到箭落在哪。任务结束后把每一箭的结果告诉 agent，只能等下一轮再修正（Q10、Q13）。

**第三稿**（2026-11-25，用户提出）：

8. **加入弩的训练**，用同一块场地（Q14–Q20）。弩的随机散布和弓完全相同，判定看箭实际落在哪，不用另算散布（F15）。

**第四稿**（2026-11-26，用户提出）：

9. **加入三叉戟的训练**，用同一块场地，继续用标靶检测（Q21–Q26）。掷出的三叉戟在原版里就是一种箭，现有的登记、命中检测都能直接用（F21）。

**第五稿**（2026-11-27，用户提出）：

10. **加入钓竿的训练**，训练逻辑和弓、弩相同（Q27–Q34）：
    - 钓竿的射程只有十来格（F29），出题只在场地的近处抽，场地本身不改（Q28）；
    - 继续用标靶检测，不放无 AI 的生物（Q27）。浮标撞到方块照样走原版的命中，但浮标的碰撞箱比射线宽，约三成瞄得完全正确的抛竿不触发命中，mod 要补判（F31、Q31）。

## 2. 已核实的事实

数据来源：`1.21.11_src` 里的 `BowItem`、`Projectile`、`AbstractArrow`、`TargetBlock`、`MultiPlayerGameMode`、`Minecraft`；第三稿加 `CrossbowItem`、`ProjectileWeaponItem`、`Items`、`ServerGamePacketListenerImpl`，第四稿加 `TridentItem`、`ThrownTrident`、`EntityType`，第五稿加 `FishingRodItem`、`FishingHook`；mod 的 `mixin/LevelRendererMixin.java`、`arena/ArenaManager.java`，第三稿加 `api/InventoryApi.java`、`api/ContinuousApi.java`、`api/OneShotApi.java`，第五稿加 `arena/BowArena.java`、`api/PlayerApi.java`；插件的 `src/training/bow.js`。

| # | 事实 | 对方案的影响 |
|---|------|------------|
| F1 | **蓄力**：松手时按拉弓的 tick 数 j 算力度 f：t = j / 20，f = (t² + 2t) / 3，最大为 1。**拉满要 20 tick**（1 秒），拉得更久 f 仍是 1；f < 0.1（不到 3 tick）不射。箭的初速 = 3f 格/tick。**只有 f = 1 的箭是暴击箭**（`BowItem` 36–43、66–73 行）。物品栏里要有箭才能射（`getProjectile`，31–34 行） | 训练场用"是不是暴击箭"判断有没有拉满（Q6）；拉满不需要蓄力状态的观测，按住超过 1 秒再松手就一定是满的 |

## 3. 总体设计

流程和告示牌场地相同，不需要预览：

1. 插件出题：标靶几个、各在哪、各指定哪个面（Q2、Q3）；发物品的格子和选中的快捷栏格（Q4）；
2. `arena/prepare`：清物品栏，清掉上一轮的标靶和箭，放标靶，发弓和箭，登记目标；
3. 发布任务，轮询 `arena/status`；箭用完了还没全中、或者 agent 离开了平台，就立刻结束本轮（Q7）；
4. 任务结束后调用 `arena/finish`，判定并写记录；
5. 把每一箭的结果交给本轮的复盘（Q13），agent 在复盘里决定记下什么，下一轮再用。

插件侧新增题型 `bow`，在新文件 `src/training/bow.js` 里实现；复盘流程增加"训练场判定"一段（Q13）。

mod 侧的改动：

1. 增加场地 `bow`：射击平台加空场地，布局和其他场地不同（Q1）；
2. `prepare` 新参数 `bow`，放标靶；
3. 记录本轮每一支箭：从哪射出、方向、是否拉满、飞行轨迹、命中点（Q8）；
4. 增加一种"射箭"写法的到达检测；
5. 盯住玩家是否离开平台（Q7）。

## 4. 决策点

### Q1　场地

- **场地原点 (10300, 120, 10000)**：离开 x = 10000 那一排，也离开信标场地（10100），四周留足空间。
- **射击平台**：以原点为中心的 3 × 3 地板，玩家站在中心 (ox, 121, oz)，朝 +x，眼睛高度 122.62。平台后面和两侧各有 2 格高的屏障护栏，前面敞开。
- **空场地**：平台正前方，x ∈ [ox+2, ox+49]，z ∈ [oz−24, oz+23]，y ∈ [99, 146]，48 × 48 × 48 格。眼睛高度在中间附近，所以标靶有高有低。
  - 场地里除了标靶什么都没有，下方也不铺地面。没中的箭飞出场地范围就算没中（Q8）。
  - 这一带可能有山，第一次搭场地时把整个范围清成空气；之后每轮 `prepare` 检查一遍，有别的方块也清掉。
- **场外平台**：沿用其他场地的做法，在 −x 方向。
- 场地名、题型名都叫 `bow`。没有工作站，标靶也不算工作站（Q7 的 `lost` 另判）。
- `prepare` 把玩家放在平台中心，朝 +x、视线水平，不对准任何标靶。

**建议：采用。**

### Q2　题目

- **标靶数**在 `targets`（缺省 `1-4`，范围 1–4）里等概率抽。
- 标靶用原版标靶方块 `minecraft:target`，悬在空中。
- 每个标靶指定一个面，目标点是这个面的中点。比如方块 (x, y, z) 朝 −x 的面，中点是 (x, y + 0.5, z + 0.5)。
- 只有一种题型。弩、三叉戟、钓竿用同一个题型，按选项 `weapon` 区分（第三稿 Q14、第四稿 Q21、第五稿 Q27）。

**建议：采用。**

### Q3　标靶放在哪、指定哪个面

**位置**：

- 在空场地里等概率抽一格；
- 眼睛到这一格中心的距离在 `dist`（缺省 `8-40`，范围 2–60）里，理由见 F5；
- 和已有标靶的间距至少 3 格（三个方向上取最大的那个）；
- 至少有一个面能当目标（见下），否则重抽。

**哪些面能当目标**：原流程是"agent 看得到的面"。但箭走的是抛物线，看得到的面不一定射得到。比如标靶在头顶上方较远处时，它的底面看得到，但箭飞到那里已经在往下落，碰不到底面。所以按弹道来判断，一个面要同时满足：

1. **看得到**：从眼睛看过去，这个面朝着自己（原流程的条件）；
2. **射得到**：从发射位置（F2，按站在平台中心、站立的眼睛高度算），满蓄力、不带随机偏差，存在一条低弧线的弹道正好穿过这个面的中点；
3. **从这一面进去**：这条弹道最先碰到的就是这个面，不会先擦到同一块标靶的别的面；
4. **不太斜**：箭到达时的速度方向和这个面的法线夹角不超过 70°。太斜的面，箭擦边就过去了；
5. **路上没有阻挡**：这条弹道离别的标靶、平台和护栏都至少 0.5 格。随机偏差会让箭偏离理想弹道，留出余量，免得射向这个标靶的箭误中别的标靶。

模拟按 F2–F4 的顺序逐 tick 算，放在插件里（`bow.js`），出题不需要问 mod。模拟只用来保证题目做得出来，不给 agent 看。

**抽面**：在能当目标的面里等概率抽一个。放完所有标靶后，对每个目标再查一遍第 5 条（后放的标靶可能挡住先放的），不满足就整题重抽。

**建议：采用。**

### Q4　发什么物品、放在哪

- 一把普通的弓 `minecraft:bow`（不附魔）和与标靶数相同的箭 `minecraft:arrow`，分别放在主物品栏 36 格里随机的两格（第一稿审阅意见）；
- **开局手上是空的**：`selectedSlot` 在快捷栏里没放物品的格子中随机抽，和告示牌题一样。弓要 agent 自己找到、拿到手上；
- 不发别的东西。弓的耐久有 384 次，够用。

**建议：采用。**

### Q5　任务文案

写目标和规则，不说怎么瞄准、要抬高多少、怎么拉弓。`prompts/training/bow.md`：

```
你站在一个平台上，前方的空中有 {{n}} 个标靶（minecraft:target）。你的物品栏里有一把弓（minecraft:bow）和 {{n}} 支箭（minecraft:arrow）。
请站在平台上把弓拉满射箭，让箭分别射中下面 {{n}} 个点：
{{points}}
每个点都是一个标靶某一面的中心，每个点只有一支箭，顺序不限。没拉满射出的箭不算数；离开平台本轮直接结束。
```

- `{{points}}` 每个点一行，例如 `- (10315.0, 125.5, 10003.5)`；
- 坐标写到一位小数，就是精确值（面的中点只会是 .0 或 .5）；
- 不说是哪个面、不说距离，agent 从坐标自己算。

"没拉满不算数""离开平台直接结束"是规则，不是方法，写出来让 agent 知道代价。文案不说任务中看不到落点、结束后会告诉结果：任务中确实看不到，结果在复盘里自然会看到（Q13）。

**建议：采用。**

### Q6　一支箭怎么算

训练场记录每一支本轮射出的箭（玩家射出的、生成时本轮还在进行中）。

**这支箭有没有效**：

| 情况 | 记为 |
|------|------|
| 不是暴击箭（没拉满，F1） | `weak`：无效，射中了也不算 |
| 射出时玩家不在平台上 | 不会出现：一离开平台本轮就结束了（Q7） |
| 其余 | 有效 |

**有效的箭的结果**：

| 结果 | 条件 |
|------|------|
| `hit` | 射中某个标靶的指定面，而这个标靶还没被射中过 |
| `repeat` | 射中某个标靶的指定面，但这个标靶已经被射中过（这支箭浪费了） |
| `wrong_face` | 射中标靶，但不是指定的面 |
| `platform` | 射中平台或护栏 |
| `out` | 飞出场地范围 |
| `stuck` | 发射后 10 秒还没有结果（正常情况下不会出现，兜底用） |

**偏差**：
- `hit` 和 `repeat`：命中点离这个面中点的偏差，按面内两个方向取大的（同 F6 的算法），另外记 (dx, dy, dz)，复盘时能看出偏高还是偏低；
- 没中的箭：对每个还没被射中的标靶，取这支箭的轨迹穿过它指定面所在平面的那个点，算到中点的偏差，记最小的那个和对应的标靶。轨迹没穿过任何一个平面就不记。

**建议：采用。**

### Q7　判定

**到达条件**：每个标靶都被一支有效的箭射中过指定面（`hit`）。满足的那一 tick 记为 `reachedAtMs`，就是原流程第 5 步"停止计时"的时刻。

**提前结束（doomed）**，轮询时发现就立刻结束本轮：

| 代号 | 条件 |
|------|------|
| `left-platform` | 玩家离开了平台：脚下不在 3 × 3 地板上方，或者脚的高度低于地板顶面。mod 在 tick 里一发现就记下时刻，并把玩家传送到场外平台，免得摔死 |
| `out-of-arrows` | 没全中，而且箭已经没了：物品栏、光标、平台上的掉落物里都没有箭，也没有还在飞的箭 |

**结果**：

| 顺序 | 结果 | 条件 |
|------|------|------|
| 1 | `aborted` | 手动停止 |
| 2 | `lost` | 有标靶不在了（正常情况下够不着，不会出现） |
| 3 | `timeout` | 超时 |
| 4 | `success` / `false_success` / `failed` | 任务以完成结束时，到达条件成立就是 `success`，否则是 `false_success`；doomed 和其余情况是 `failed` |

**没做好的原因**（`faults`，`false_success` 和 `failed` 时记，可以有多项）：

| 原因 | 条件 |
|------|------|
| `miss` | 有标靶没被射中 |
| `weak` | 有箭没拉满 |
| `unshot` | 报完成时还有箭没射 |
| `left-platform` | 离开了平台 |

不要求物品栏状态。

**建议：采用。**

### Q8　mod 怎么记录箭

- **生成时**：本轮进行中，有箭生成、主人是本轮的玩家，就登记这支箭：
  - 编号（第几支）、生成的 tick 和时刻；
  - 生成位置、初速度（含随机偏差，就是它实际射出的方向和速度）；
  - 玩家当时的位置和朝向（与初速度对比，看得出 F8 的滞后）；
  - 是不是暴击箭；
  - 把它的 `pickup` 改成不能捡（F7）。
- **飞行中**：每 tick 记一次位置，最多 200 个点，供插件算没中的箭的偏差（Q6）。离开场地范围（空场地加平台，外扩 2 格）就记 `out`，删掉这支箭。
- **命中方块时**（`AbstractArrow.onHitBlock`，F4）：记方块坐标、哪一面、命中点，判 `hit` / `repeat` / `wrong_face` / `platform`。射中的箭留在原处，和原版一样。
- **偏差**：射中指定面时由 mod 算（Q6）；没中的箭的偏差由插件按轨迹算。
- 每轮 `prepare` 删掉场地里所有的箭，`finish` 删掉还在飞的箭。

**建议：采用。**

### Q9　mod 的改动

- **新文件 `arena/BowArena.java`**：
  - 搭场地：射击平台、护栏、清空场地；
  - `place(level, targets)`：清掉上一轮的标靶和箭，放这一轮的标靶；
  - 箭的登记、轨迹、命中处理（Q8），离开平台的检测（Q7）；
  - `Spec(targets: [{ pos, face }])` 和 `reached(...)`。
- **新 mixin**：`AbstractArrow.onHitBlock` 开头注入，交给 `BowArena`。
- **箭的生成**：在服务端实体加载时挑出本轮玩家射出的箭（Fabric 的实体加载事件，或者在 `BowItem.releaseUsing` 里注入，实施时选一种）。
- **`ArenaManager`**：
  - 场地 `bow`，单独的搭建逻辑（F10）；
  - `prepare` 新参数 `bow { targets: [{ pos: [x, y, z], face }] }`，只在 `bow` 场地上收；mod 再查一遍标靶都在场地范围内、互不重叠；返回 `bow { targets, items, selectedSlot }` 供插件核对；
  - `Expect` 增加一种射箭的写法：

```
expect: { bow: { targets: [{ pos, face }] } }
```

  - `status`：返回 `arrows`（每一支箭的登记和结果）、`hits`、`leftPlatformMs`、箭的剩余数量（物品栏、光标、平台上的掉落物、还在飞的）；
  - `finish`：读完状态，删掉还在飞的箭，传送到场外平台。
- **`ArenaApi`**：解析 `bow` 和 `expect.bow`。
- **`src/mod/methods.js`**：`arena/prepare` 的 `bow` 参数、`expect.bow`、`status` 的说明。

**建议：采用。**

### Q10　任务中看不到落点（第一稿审阅意见）

- **不开放视觉**：任务中 agent 不知道箭落在哪，每一箭都按自己的计算射出去。这一轮射偏了，只能在任务结束后看到结果（Q13），下一轮再修正。
- 任务中 agent 还能看到的：物品栏里箭少了几支、手上是什么、自己的位置和朝向。这些不涉及落点，不用处理。
- **声音是个旁路**（F11）：箭撞到方块的声音带坐标，agent 如果在箭落地的那一刻读 `sound`，就能知道落点。处理办法有两种：
  - **A. 先不处理**：声音是 agent 本来就有的感知，要正好在箭落地时去读才读得到，概率不大。从任务日志里看 agent 有没有在射箭后读 `sound`，真出现了再处理。
  - **B. 本场地屏蔽**：本轮进行中，`sound` 不返回箭命中的声音。要在通用接口里加场地特例。

  **建议：A。** 先看实际有没有发生，不为一个没出现的问题在通用接口里加特例。

**建议：采用。**

### Q13　任务结束后告诉 agent 结果（第一稿审阅意见）

**问题**：现在复盘在训练场判定之前就开始了，复盘时 agent 只知道自己报的结果，不知道射中没有（F12）。要"任务结束后告诉 agent 结果"，得让复盘等到判定出来，并把结果放进复盘请求。

**做法**：

1. **训练场题型可以提供"判定说明"**：题型新增可选钩子 `debrief(record)`，返回一段文字。先只有 `bow` 题提供；其他题型不提供，复盘照旧，不受影响。
2. **复盘等判定**：训练器在本轮开始时告诉桥"这个任务的复盘要等判定"。任务结束时，桥照常创建复盘请求，但先不发出去；训练器在 `arena/finish` 判定后把判定说明交给桥，桥再渲染并发出。最多等 60 秒，等不到就照旧发出，判定说明一栏写"（训练场判定没有按时给出）"。
3. **复盘文案新增一段**（`requests/reflect.md`），只在有判定说明时出现：

```
## 训练场判定

这一轮由训练场判定，下面是它看到的结果（只是事实）：

{{debrief}}
```

4. **有判定说明时一定复盘**：不走 `onDone: 'changed'` 的"没有新情况就跳过"。即使任务"成功"、树没有变化，每一箭的偏差也是新的信息。
5. **判定说明的内容**：只列事实，不给建议（不写"应该再抬高几度"）：
   - 本轮结果（`success` / `false_success` / `failed` / `timeout`）、射中几个标靶，doomed 的原因；
   - 每个标靶：目标点、是否射中；
   - 每一支箭，按射出的顺序：
     - 是否拉满；
     - 射出时服务端记录的玩家位置和朝向（俯仰角、偏航角）；
     - 结果（Q6 的 `hit` / `repeat` / `wrong_face` / `platform` / `out` / `stuck`）；
     - 射中方块时：方块、哪一面、命中点、相对目标点的偏移 (dx, dy, dz)；
     - 没中时：轨迹穿过最近那个目标面所在平面的点、相对目标点的偏移（轨迹没穿过任何目标面所在的平面就写"没有经过任何目标面"）。

   朝向写服务端实际用来射箭的值。如果 F8 的滞后存在，agent 能从"我设的朝向"和"服务端用的朝向"不一致里发现。
6. **跨轮怎么用**：复盘时 agent 自己决定记下什么（胶囊、事实），下一轮规划时照常检索。训练场不替它总结规律。判定说明同时写进任务历史的 `training` 字段，以后用 `task_get` 也查得到。

**影响**：

- 桥的复盘流程多一个"等外部判定"的状态。人手动发起的复盘（`/bt reflect`）不等；
- 训练器停止（`/bt train stop`）时，正在等的复盘直接发出，判定说明一栏写"（训练已停止，没有判定）"；
- 其他训练场不提供 `debrief`，行为不变。以后别的场地也想在复盘里看到判定，加这个钩子就行，这次不做。

**建议：采用。**

  - 钓竿的距离和其他三种差四五倍（F29、Q28），混在一起，`dist` 和按距离分段的报告都说不清；
  - `weapon=any` 同一个种子出的题和第四稿相同；
  - 练钓竿就写 `weapon=fishing_rod`。
- **检测工具：继续用标靶**：
  - 浮标撞到方块照样走原版的命中（F28）；
  - 判定看碰到的方块、面和位置，标靶、面中点、偏差的算法都能沿用；
  - 碰撞箱先碰到、没有命中事件的情况由 mod 补判（F31、Q31）。
- **备选：放无 AI 的生物当目标。** 不采用：
  - 勾实体只看射线碰没碰到实体的碰撞箱（F32），没有"哪一面""面中点"，Q6 的偏差、Q13 的判定说明都要另写；
  - 无 AI 的生物照样有重力、会被推动，收竿还会把它拉过来（F32），要另外设成不受重力、无敌、不会消失，每轮还要清理；
  - 勾住生物、把它拉过来是另一种技能，以后要练再单独出题（Q12）。
- **照旧的部分**：
  - 标靶、面的抽法（Q2、Q3），弹道换成浮标的（Q33）；
  - 离开平台（Q7）；
  - 看不到落点（Q10）；
  - 复盘等判定（Q13）；
  - 超时 600 秒；
  - 一轮只用一种武器（Q14）。

**建议：采用。**

### Q28　距离（钓竿）

**场地本身不缩小**：
- 48 格的空场地照用，钓竿的题只在靠平台的一小块里抽；
- 平台、护栏、场外平台都不变，mod 的 `prepare` 不用为距离改；
- 另建小场地要多搭一套平台和场外平台，没有好处。

**距离的缺省值按武器分开**：
- 场地配置新增 `rodDist`，缺省 `3-10`。钓竿的轮次没写 `dist=` 时用它，写了就用写的；
- 弓、弩、三叉戟仍用 `dist`（缺省 `8-40`）；
- 钓竿的 `dist` 上限 16，写超了报错，并说明钓竿的范围。再远，低弧线几乎够不着任何面（F29：水平最远约 14 格），抽题只会反复失败。

**为什么是 3–10 格**：
- 下限 3 格：再近就差不多是直线（3 格平抛仰角 2.6°），标靶也容易挤在平台边上；
- 上限 10 格：和眼睛等高的目标 10 格还够得着（仰角 15°）。11 格以外，只剩比眼睛低的少数位置够得着（F29、F30）；
- 标靶间距至少 3 格照旧。3–10 格的范围里放 4 个标靶，空间够用。

**建议：采用。**

### Q29　发什么物品、能抛几次（钓竿）

- **一根钓竿** `minecraft:fishing_rod`，不附魔、满耐久，放在主物品栏里随机的一格，开局手上是空的，和 Q4 相同。不发别的东西。
- **抛竿次数等于标靶数**。钓竿用不完（F33），"每个点只有一次机会"要训练场自己数：
  - 每抛出一个浮标算一次（mod 登记，Q31），收竿不算；
  - 第 n + 1 次及以后的抛竿记 `extra`：无效，碰到标靶也不算；
  - 抛满 n 次、每一次都有了结果、还有标靶没中，就提前结束（Q31）。
- **备选 A：发 n 根钓竿，每根只能抛一次。** 不采用：原版里一根钓竿能一直抛，要改原版行为才做得到。
- **备选 B：不限次数。** 不采用：违反"每个点只有一次机会"（§1 第 2 条），agent 可以一直抛到碰上为止。

**建议：采用。**

### Q30　任务文案（钓竿）

新模板 `prompts/training/fishing_rod.md`，其他三份模板不动：

```
你站在一个平台上，前方的空中有 {{n}} 个标靶（minecraft:target）。你的物品栏里有一根钓竿（minecraft:fishing_rod）。
请站在平台上用钓竿抛出浮标，让浮标分别碰到下面 {{n}} 个点：
{{points}}
每个点都是一个标靶某一面的中心，一共只能抛 {{n}} 次，多抛的不算数，顺序不限。离开平台本轮直接结束。
```

- **和三叉戟的文案一样不写"没拉满不算数"**：钓竿没有蓄力（F26）。
- **"一共只能抛 n 次，多抛的不算数"是规则**（Q29），写出来让 agent 知道代价。
- **不说的内容**：
  - 浮标在外面时再按使用键是收竿，要先收竿才能再抛；
  - 要抬多高；
  - 浮标比箭慢多少、落得多快。

**建议：采用。**

### Q31　mod 怎么记录浮标、怎么判定（钓竿）

**登记**：Q8 的做法推广到浮标。
- 服务端实体加载时登记为一次抛竿，条件是：本轮进行中、`tickCount == 0`、主人是本轮玩家的 `FishingHook`；
- 记编号、时刻、生成位置、初速度、玩家位置和朝向；
- `weapon` 记 `minecraft:fishing_rod`。浮标没有 `getWeaponItem`，按实体类型定；`crit` 记否；
- 编号大于标靶数的，登记时就记 `extra`（Q29），照样记轨迹；
- 每 tick 记轨迹，飞出场地（外扩 2 格）记 `out` 并删掉，和箭相同。

**判定**：下面四种按先发生的算。
1. **射线命中**：新 mixin 在 `FishingHook.onHitBlock` 开头注入，交给 `BowArena`，和箭走同一套判定（`hit` / `repeat` / `wrong_face` / `platform` / `out`），命中点就是射线的命中点。
2. **碰撞箱碰到**（F31）：每 tick 结束时，还没有结果的浮标如果这一 tick 被方块挡住了（`horizontalCollision` 或 `verticalCollision`），就按碰撞箱贴着的那一面判定：
   - 碰撞箱朝挡住的方向外扩一点点，找贴着的方块。贴着好几个面时（撞在棱上），取和上一 tick 的运动方向最正对的那一面；
   - 命中点取浮标的位置（碰撞箱底面中心）沿这一面的法线投到面上的点，和射线命中用同一个参考点；
   - 判定的种类和第 1 种相同。
3. **勾住实体**：场里只可能是平台上的掉落物（F32），记 `platform`。
4. **没有结果就没了**：浮标还没碰到任何方块就消失了，比如被收竿、玩家手上不再拿着钓竿，记 `stuck`（同 §8 的兜底）。

**碰撞箱碰到也算命中**：
- 这就是原版玩家看到的"浮标碰到了标靶"；
- 指定面的判定范围因此比射线宽：水平方向两侧各宽 0.125 格，下沿宽 0.25 格；
- 偏差本来就小（F30），宽出的这一点不会让运气变成主要因素。

**`via`**：记录里每一次抛竿多一个 `via`，`ray` 是射线命中，`contact` 是碰撞箱碰到。只用于核对，不写进判定说明。

**备选：只认射线命中。** 不采用：约三成瞄得完全正确的抛竿会判成没中（F31）。

**其余**：
- **场地清理**：`prepare` 删掉场地里的浮标（和箭一起删），`finish` 删掉还在外面的浮标；
- **提前结束**：`out-of-arrows` 的"弹药"换成抛竿次数，条件是抛满 n 次、每一次都有了结果、还有标靶没中。代号不改，判定说明和报告里换说法（Q34）；
- **`unshot`**：报完成时还有抛竿次数没用；
- **`weak`**：不判，第四稿起只对弓判；
- **到达条件**不变：每个标靶都被一次有效的命中碰过指定面。`expect.bow` 的说明从"一支拉满的箭"改成"一次有效的命中"。

**建议：采用。**

### Q32　浮标在不在外面的观测（钓竿）

**问题**：浮标在外面时再按使用键是收竿（F26）。现在 agent 观测不到浮标在不在外面，分不清下一次按键是抛还是收。原版玩家看得到：钓竿的外形会变，浮标和鱼线也看得到。

- **`player` 的 `flags` 新增 `fishing`**：自己的浮标在外面时为 true（客户端的 `player.fishing`，F26）：
  - 和 `onGround`、`sneaking` 一样是玩家本身的状态，任何场合都有；
  - 只给有没有，不给浮标的位置。给位置就等于任务中看得到落点，违反 Q10。
- **旁路**：飞出场地的浮标会被删掉，`fishing` 随即变成 false。agent 如果抛完马上反复读 `player`，能分出"出界了"和"停在了某处"，但不知道停在哪。处理同 Q10 的声音：先不处理，从任务日志里看有没有发生。
- **说明**：`src/mod/methods.js` 里 `player` 的说明补一句这个字段。
- **备选：不加。** agent 在任务中没有任何办法确认自己按的那一下是抛还是收，只能等复盘里看到"第二次没抛出去"。

**建议：加字段。**

### Q33　弹道模拟（钓竿）

- **武器表 `WEAPONS` 加 `fishing_rod`**，弹道换成浮标的模型（F27、F28），不只是换一个速度：
  - 出手：眼睛高度，沿水平朝向前移 0.3 格；水平速度 0.6·cos 仰角 + 0.5，竖直速度是它乘 tan 仰角（限制在 ±5）；
  - 每 tick：沿当前速度做射线检测 → 竖直速度减 0.03 → 按碰撞箱移动 → 速度乘 0.92；
  - 0.25 × 0.25 的碰撞箱要算进去（F31）；
  - 朝向的三角函数按 float 算（`Math.fround`），和原版一致。
- **Q3 的五个条件**按浮标的弹道算，条件 3"从这一面进去"改成"射线或碰撞箱最先碰到的就是这个面"，和 Q31 的判定一致。其余照旧：
  - 低弧线。有的点只有高吊抛才够得着，要飞 60–100 tick，不出这种题；
  - 不太斜（夹角不超过 70°）；
  - 路上离别的标靶、平台、护栏至少 0.5 格。偏差虽然小得多，余量也不放宽，免得碰撞箱擦到。
- **移动速度**：钓竿不加（F27），模拟本来就按站着不动算。
- **单元测试**：
  - 固定钓竿在 3 / 4 / 6 / 8 / 10 格平抛的仰角。F30 按 double 算出来是 2.57° / 3.55° / 6.15° / 9.39° / 15.02°，实施时按 float 重算后固定；
  - 再固定一个"射线没碰到、碰撞箱先碰到"的例子。

**建议：采用。**

### Q34　判定说明、记录与报告（钓竿）

- **判定说明**（Q13 第 5 条）：
  - 第一行写"本轮武器：钓竿（minecraft:fishing_rod）"；
  - 每一次写"第 k 次抛竿"，不写"是否拉满"；写"抛出时玩家在…，服务端用来抛竿的朝向…"、"浮标从…出发"；
  - `extra` 写"超出了 n 次，不算数"；`stuck` 写"浮标还没碰到任何方块就没了"；
  - 次数用完提前结束时写"抛竿次数用完了还有标靶没命中"；报完成时还有次数没用，写"报完成时还有 k 次抛竿没用"；
  - 其余照旧，只列事实。命中是射线还是碰撞箱判出来的不写（Q31）。
- **记录**：
  - `weapon` 是 `fishing_rod`，`target` 写 `fishing_rod:<标靶数>`；
  - `arrows` 每一项是一次抛竿，多一个 `via`；
  - label 例如 `钓竿：3 个靶，4–9 格（seed=…）`。
- **报告**：
  - `--by weapon` 四种武器各一行；记录里有两种以上武器时按武器分表，多一张 `【钓竿】`；
  - 钓竿的表不显示"没拉满"两栏；"箭用完""箭没射完""箭命中率"改叫"次数用完""没抛完""命中率"；
  - `--by dist` 对钓竿按 2 格一段：2–4、4–6、6–8、8–10、10 以上。弓、弩、三叉戟仍是 8 格一段。

**建议：采用。**

## 5. 训练命令

### 5.1 完整格式

```
/bt train bow [runs=<次数>] [seed=<种子>] [targets=<标靶数>] [dist=<距离>] [weapon=<武器>]
```

所有选项都可以不写，不写时按场地配置随机。

### 5.2 参数

| 参数 | 取值 | 缺省 | 含义 |
|------|------|------|------|
| `runs` | 1–1000 的整数 | 1 | 连续跑几轮 |
| `seed` | 0–4294967295 的整数 | 每轮随机 | 出题种子，规则同铁砧方案 §5.2 |
| `targets` | `k` 或 `a-b`，1–4 | 场地配置，缺省 `1-4` | 标靶数（Q2）。和其他场地的 `targets` 同名，取值按场地分别校验 |
| `dist` | `a-b`，2–60；钓竿 2–16 | 场地配置，缺省 `8-40`；钓竿用 `rodDist`，缺省 `3-10` | 眼睛到目标点的距离（Q3；钓竿见第五稿 Q28） |
| `weapon` | `bow`、`crossbow`、`trident`、`fishing_rod`、`any` | 场地配置，缺省 `bow` | 本轮用的武器，`any` 每轮在弓、弩、三叉戟里等概率抽一种，不抽钓竿（第三稿 Q14，第四稿 Q21 加三叉戟，第五稿 Q27 加钓竿） |

写了其他场地的选项，按现有规则报"不认这些选项"。

### 5.3 相关命令

| 命令 | 含义 |
|------|------|
| `/arena bow` | 传送到弓箭场地的场外平台 |
| `/bt train status` / `/bt train stop` | 同其他场地 |
| `node scripts/training-report.js bow [--by targets\|dist\|weapon] [--last <N>] [--batch <批次>]` | 汇总训练记录（Q11、Q20、Q26、Q34），缺省按 `targets` 分组；记录里有两种以上武器时按武器分表 |

### 5.4 示例

| 命令 | 效果 |
|------|------|
| `/bt train bow runs=10` | 按缺省设置跑 10 轮 |
| `/bt train bow runs=5 targets=1 dist=8-16` | 每轮 1 个近处的标靶，先熟悉拉弓 |
| `/bt train bow runs=5 targets=4 dist=24-40` | 每轮 4 个远处的标靶 |
| `/bt train bow runs=5 weapon=crossbow targets=1 dist=8-16` | 用弩，每轮 1 个近处的标靶 |
| `/bt train bow runs=5 weapon=trident targets=1 dist=8-16` | 用三叉戟，每轮 1 个近处的标靶 |
| `/bt train bow runs=10 weapon=any` | 每轮随机用弓、弩或三叉戟 |
| `/bt train bow runs=5 weapon=fishing_rod targets=1` | 用钓竿，每轮 1 个 3–10 格内的标靶 |
| `/bt train bow runs=5 weapon=fishing_rod targets=4 dist=6-12` | 用钓竿，每轮 4 个稍远的标靶 |

## 7. 验收清单（实施后）

1. `/arena bow` 能传送到新场地的场外平台；其他场地和它们的训练不受影响。
2. `/bt train bow runs=3`：
   - 玩家站在平台中心，朝 +x；平台后面和两侧有护栏，前面敞开；
   - 场地里只有本轮的标靶，上一轮的标靶和箭都不在了；
   - 物品栏里只有一把弓和 n 支箭（n 等于标靶数），各在随机的一格，手上是空的。
3. 抽题检查（单元测试）：
   - 标靶数、距离在范围内；间距至少 3 格；都在场地范围内；
   - 指定的面满足 Q3 的 5 个条件；
   - 同一种子出同一道题。
4. 弹道模拟和原版一致：在游戏里站在平台中心，用 `camera/*` 设好朝向后等 1 tick 再拉满射出，记录里箭的初速度和模拟一致（只差随机偏差）；没中的箭，记录里的轨迹和模拟的轨迹在随机偏差范围内重合。
5. 复盘等判定（Q13）：
   - 一轮结束后，复盘请求里有"训练场判定"一段，每一箭的结果、偏移和记录一致；
   - 成功而且树没变化的一轮也会复盘；
   - 其他场地的训练（比如 `/bt train sign runs=1`）复盘照旧，没有这一段，也不等；
   - 复盘等待中 `/bt train stop`，复盘立刻发出，写明没有判定；
   - F11：射箭后马上调 `sound`，看能不能读到箭命中的声音和坐标，把结论补进 F11。
6. 在游戏里手动验证：
   - 拉满射中指定面，判 `hit`，偏差和肉眼看到的位置一致；射完全部标靶后报完成，判 `success`，`reachedMs` 是最后一中的时刻；
   - 拉不满就松手，判 `weak`，射中了也不算；
   - 射中同一块标靶的另一面，判 `wrong_face`；射向空中，判 `out`，箭被删掉；
   - 射到平台上的箭捡不起来；
   - 箭用完没全中，本轮立刻结束，判 `failed`，`doomed` 为 `out-of-arrows`；
   - 走下平台，立刻被传送到场外平台，判 `failed`，`doomed` 为 `left-platform`；
   - 还有箭没射就报完成，判 `false_success`，`faults` 有 `unshot`。
7. F8：转完视角立刻松手，看记录里箭的初速度方向是不是上一 tick 的朝向，把结论补进 F8。
8. `training-report` 能按 `targets` / `dist` 汇总。
