# 书与笔训练场设计方案

> 状态：**J-S1–J-S3 已实施**（2026-11-23），单元测试通过，mod 编译通过，待游戏内按 §7 验收。审阅结论：J3 选**做法 A**（`book/set` 对齐编辑框规则，删掉后门），其余决策点按建议执行。实施说明见 §8。
>
> 本方案沿用《训练场设计方案》（2×2 合成场地）、《箱子训练场设计方案》（下称"箱子方案"）和《铁砧训练场设计方案》（下称"铁砧方案"）的整体架构：
> - 插件主控，mod 以服务器身份操作场地；
> - 每轮一个新会话，记录写进 jsonl；
> - "恰好达到"的时刻由 mod 在 tick 里检测。
>
> 下面只写和它们不同的部分。
>
> 目标：另建一块没有工作站的场地。物品栏里有 1–3 本写了字的书与笔，训练 agent 把书拿到手上、打开、按要求改写或清空指定的页，并保存。

## 1. 用户原始流程

1. agent 传送到对应的训练场地中
2. 清空 agent 身上的所有物品
3. 开始计时，发布任务：给 agent 一本书，第 1–4 页里随机 2 页写了随机字符，要求 agent 把第 1–4 页的内容改成指定的随机字符（指定内容、样式等属性）
4. 检测到书中有目标内容后，停止计时并记录

**审定的调整**（2026-11-23，讨论时确定）：

- **去掉"样式"**：书与笔只存纯文字，原版做不出样式（F7、J2）；
- **判定按"恰好"**：全部页逐字等于目标，书还是书与笔（J10）；
- 加四项变化，全部都要：
  1. 书放在 36 格里随机的一格，多数不在手上（J4）；
  2. 书的页数随机，只改其中几页，其余原样保留（J5、J6）；
  3. 有"清空某页"的目标（J6）；
  4. 一轮 1–3 本书，各有各的目标（J7）。

## 2. 已核实的事实

数据来源：`1.21.11_src` 里的 `WritableBookItem`、`LocalPlayer`、`BookEditScreen`、`BookSignScreen`、`MultilineTextField`、`StringUtil`、`ServerGamePacketListenerImpl`、`ServerboundEditBookPacket`、`WritableBookContent`、`Items`；mod 的 `api/BookApi.java`、`mixin/BookEditScreenAccessor.java`、`api/ContainerApi.java`、`api/InventoryApi.java`、`arena/ArenaManager.java`。

## 3. 总体设计

流程和 2×2 合成场地相同，不需要预览：

1. 插件出题：几本书、每本的页数和开局内容、要改哪几页、改成什么，书放在哪一格，当前选中哪个快捷栏格；按 F5 算出每本的目标；
2. `arena/prepare`：清物品栏，发带内容的书，设选中的快捷栏格，登记目标；
3. 发布任务，轮询 `arena/status`；
4. 任务结束后调用 `arena/finish`，判定并写记录。

插件侧新增题型 `book`，在新文件 `src/training/book.js` 里实现。

mod 侧的改动：

1. 增加场地 `book`（没有工作站）；
2. `prepare` 的 `items` 每项可以带 `pages`，发带内容的书与笔；新参数 `selectedSlot`；
3. `status` 返回玩家身上、光标上、地上的书和每本的页；
4. 增加一种"书"写法的到达检测；
5. `book/set` 按编辑框的规则查（J3，待定）。

## 4. 决策点

### J1　场地

- **场地原点 (10000, 120, 10450)**：接在砂轮场地（10420）后面，间距 30 格。
- 没有工作站，布置同 2×2 合成场地：平视，四周空地，准星不对着方块（F11）。
- 场地名、题型名都叫 `book`。

**建议：采用。**

### J2　只考纯文字，不考样式

书与笔只存纯文字，编辑框也打不出 `§`（F3、F7）。唯一能"带样式"的办法是用 `book/set` 直接写格式码，这是我们接口的后门，不是原版能力（F9）。所以目标只要求内容。

**建议：采用。**

### J3　`book/set` 对齐编辑框的规则（已定：做法 A）

`book/set` 现在直接改页列表，能写进编辑框打不出来的东西（F9）：

- **做法 A（建议）**：`book/set` 按编辑框的规则查。文字里有 `StringUtil.filterText` 会删掉的字符（`§`、控制字符、DEL；换行可以），超过 1024 个字符，或者按 114 像素宽折行后超过 14 行，就报错，不截断、不改页。
  - 理由：给 agent 的能力和原版一致，不留后门；本训练场的目标本来就都在这个范围里（J8），对训练没有影响。
  - 影响：这是 agent 的通用接口。胶囊库里已有的书本代码如果写过超长或带 `§` 的文字，会开始报错。训练前先备份 `src/capsules/`。
- **做法 B**：不改。本训练场的目标不含这些字符，判定也只比文字，后门不影响结果。

**审阅结论：A。** 补充依据：告示牌没有这个问题，服务端收告示牌文字时先去掉格式码（`ServerGamePacketListenerImpl.handleSignUpdate` 1947 行，`ChatFormatting::stripFormatting`）；书的内容服务端不查 `§`（F6），原版只靠客户端的编辑框拦着，所以后门只在书上有效。

### J4　书放在哪、手上拿着什么

- 每本书放在主物品栏 36 格里随机的一格，各不相同。
- `prepare` 新参数 `selectedSlot`（0–8），由插件按种子随机抽，记进记录。书正好在选中的快捷栏格里时，它已经在手上；否则 agent 要换选中格，或者把书移到手上（F1）。
- 不用副手。

**建议：采用。**

### J5　书的开局内容

- **页数** n 在 `pages`（缺省 `1-6`，范围 1–8）里等概率抽。
- 每页以 1/2 的概率写一串随机文字，否则是空页。**最后一页一定有字**：保存会删掉末尾的空页（F5），开局留着末尾空页的话，agent 没改的地方也会变。
- 各本书、各页的文字互不相同，也和全部目标文字不同。

**建议：采用。**

### J6　修改目标

- **改几页** m 在 `edits`（缺省 `1-3`，范围 1–4）里等概率抽，页号从第 1 页到第 n + 2 页里不重复地抽（可以要求写到书现在还没有的页）。
- 每个页号的目标：

| 页号 | 目标 | 抽法 |
|------|------|------|
| ≤ n，现在有字 | 改成一串新文字，或者**清空** | 清空的概率 1/4 |
| ≤ n，现在是空页 | 写上一串文字 | — |
| > n（还没有这一页） | 写上一串文字 | — |

- **目标页列表**：开局页列表套用这些修改；写到第 n + 2 页而第 n + 1 页没被要求时，第 n + 1 页是空页；最后**删掉末尾的空页**（F5）。清空最后一页，书就变短。
- 每个修改都会改变内容，所以目标一定和开局不同。

**建议：采用。**

### J7　一轮几本书

- **本数** k 在 `books`（缺省 `1-3`，范围 1–3）里等概率抽，每本各自按 J5、J6 出题。
- **怎么指明是哪本**：文案按开局内容描述，"现在第 q 页写着「…」的那本"，q 是这本书第一张有字的页。文字互不相同（J5），所以不会混淆。
- 书的内容在物品栏信息里看不到（F10），agent 要逐本打开才能认出来。这是本项要学的地方，文案里不提。
- 只有一本时不加描述。

**建议：采用。**

### J8　随机文字

- 长度 6–16 个字符，从铁砧题的常用汉字表、英文字母、数字里抽，汉字和字母数字都有；不含空格、换行、`§`、控制字符。
- 16 个汉字大约折成 2 行，远在 14 行以内（F3）。所有文字都是编辑框打得出来的。

**建议：采用。**

### J9　任务文案

只写目标，不说怎么拿书、怎么翻页、怎么保存。`prompts/training/book.md`：

```
你的物品栏里有{{what}}。请修改：
{{edits}}
没有提到的页保持原样。改好的书留在物品栏里。
```

- `{{what}}`：一本时是"一本书与笔"，几本时是"k 本书与笔"。
- `{{edits}}`：
  - 一本时，每个修改一行：`- 第 2 页的内容改成「风a雪B12」；`、`- 第 3 页清空；`，最后一行以句号结尾；
  - 几本时，每本先写一行"现在第 q 页写着「…」的那本："，下面是这本的修改。
- 页号从 1 开始，和书上显示的一致（`book/*` 接口的页号从 0 开始，这个对照 agent 自己查）。
- 写到还没有的页也只说"第 p 页的内容改成「…」"，不提"追加"。
- 不提保存，不提署名（F4、F9）。

**建议：采用。**

### J10　判定（只看最终状态）

**到达条件**：

- 光标为空；
- 玩家身上（主物品栏、快捷栏、副手、盔甲栏，不含光标）只有书与笔，恰好 k 本；
- 这 k 本的页列表（逐字比较）和 k 个目标页列表作为多重集合相等。

不比哪本放在哪一格。书之间没有别的区别，换了位置也算对。

任务结束时，按以下几处找书：玩家身上、光标、场内地上。成书（署名后）也算找到。

| 顺序 | 结果 | 条件 |
|------|------|------|
| 1 | `aborted` | 手动停止 |
| 2 | `lost` | 以上几处的书与笔和成书合计不到 k 本 |
| 3 | `timeout` | 超时 |
| 4 | `success` / `false_success` / `failed` | 任务以完成结束时，到达条件成立就是 `success`，否则是 `false_success`；其余情况是 `failed` |

**没做好的原因**（`faults`，`false_success` 和 `failed` 时记，可以有多项）：

| 原因 | 条件 |
|------|------|
| `unsaved` | 有一本书的内容还和某本的开局内容一样（没改，或者改了没保存） |
| `wrong` | 有一本书的内容既不是开局内容也不是目标（改错了、多改了、少改了） |
| `signed` | 有成书 |
| `cursor` | 光标上有东西 |
| `dropped` | 有书在场内地上 |

**建议：采用。**

### J11　mod 的改动

- **`prepare`**：
  - `items` 的每项可以带 `pages: [string]`：物品必须是 `minecraft:writable_book`、数量 1，最多 100 页、每页最多 1024 个字符，写进 `WRITABLE_BOOK_CONTENT`；
  - 新参数 `selectedSlot`（0–8），设当前选中的快捷栏格，并同步给客户端；
  - 返回 `book { items: [{ slot, pages }], selectedSlot }`，插件用它核对发对了。
- **`Expect` 增加一种书的写法**：

```
expect: { book: { goals: [[页文字...], ...] } }
```

  满足 J10 到达条件的第一个 tick 记为 `reachedAtMs`（沿用箱子方案 C9）。

- **`status`**：书场地返回下面几项，只读。
  - `books`：玩家身上的书与笔和成书 `[{ slot, id, pages, title? }]`；
  - `carriedItem`（同上的一项或 null）；
  - `held`、`dropped`（按 id 计数），`droppedBooks`（地上每本的页）；
  - `selectedSlot`。

**建议：采用。**

### J12　记录与报告

每轮记录在通用字段之外，增加：

| 字段 | 含义 |
|------|------|
| `target` | 各本目标的简述用 `+` 连起来，供日志、通知、`--by target` 用 |
| `k` | 本数 |
| `books` | 每本：`{ slot, pages（开局）, label（指明用的页号和文字，一本时为 null）, edits: [{ page, op: 'write' \| 'clear', text }], goal }` |
| `selectedSlot`、`inHand` | 选中的快捷栏格；开局时是不是已经有一本书在手上 |
| `hasAppend`、`hasClear` | 有没有要求写到还没有的页、有没有清空 |
| `faults`、`final`、`reachedMs` | 同前几个方案 |

题目说明（label）举例：`书与笔 2 本：[4 页，改 2、清 4] + [1 页，改 1、3]（seed=…）`。

报告增加 `--by k|hand|ops`，书场地缺省按 `k` 分组：

- `hand`："开局在手上" / "要先拿到手上"；
- `ops`：按本轮有没有追加、有没有清空分成四组；
- 每个原因各占一栏。

**建议：采用。**

### J13　超时、胶囊库

- **超时**：`timeoutSec` 建议为 **600 秒**。最多 3 本书，每本最多改 4 页。
- 场地没有工作站，没有"被挖"的问题。
- **胶囊库**：原样带进训练。训练前先备份 `src/capsules/`。

**建议：全部采用。**

### J14　暂不做的部分

- 署名（成书、标题）：要点界面上的"署名"按钮，现在没有接口（F9）。要做时先单独定接口
- 样式（J2）
- 书放在副手、讲台上的书
- 在一页里改一部分文字（现在每个目标都是整页内容）
- 多行内容（换行）

## 5. 训练命令

### 5.1 完整格式

```
/bt train book [runs=<次数>] [seed=<种子>] [books=<本数>] [pages=<页数>] [edits=<改几页>]
```

所有选项都可以不写，不写时按场地配置随机。

### 5.2 参数

| 参数 | 取值 | 缺省 | 含义 |
|------|------|------|------|
| `runs` | 1–1000 的整数 | 1 | 连续跑几轮 |
| `seed` | 0–4294967295 的整数 | 每轮随机 | 出题种子，规则同铁砧方案 §5.2 |
| `books` | `k` 或 `a-b`，1–3 | 场地配置，缺省 `1-3` | 每轮几本书（J7） |
| `pages` | `k` 或 `a-b`，1–8 | 场地配置，缺省 `1-6` | 每本书开局几页（J5） |
| `edits` | `k` 或 `a-b`，1–4 | 场地配置，缺省 `1-3` | 每本书改几页（J6） |

写了其他场地的选项，按现有规则报"不认这些选项"。

### 5.3 相关命令

| 命令 | 含义 |
|------|------|
| `/arena book` | 传送到书场地的场外平台 |
| `/bt train status` / `/bt train stop` | 同其他场地 |
| `node scripts/training-report.js book [--by k\|hand\|ops\|target] [--last <N>] [--batch <批次>]` | 汇总训练记录（J12），缺省按 `k` 分组 |

### 5.4 示例

| 命令 | 效果 |
|------|------|
| `/bt train book runs=10` | 按缺省设置跑 10 轮 |
| `/bt train book runs=5 books=1 pages=4 edits=4` | 接近原流程：一本 4 页的书，改 4 页 |
| `/bt train book runs=5 books=3` | 5 轮，每轮 3 本书 |

## 6. 实施分期

## 7. 验收清单（实施后）

1. `/arena book` 能传送到新场地的场外平台；其他场地和它们的训练不受影响。
2. `/bt train book runs=3`：
   - 物品栏里只有本轮发的书，每本的页和记录里的一致；
   - 选中的快捷栏格和记录里的 `selectedSlot` 一致。
3. 抽题检查（单元测试）：
   - 页数、改几页、本数在范围内；开局最后一页有字；
   - 清空只出在有字的页上；目标页列表删掉了末尾空页；
   - 所有文字互不相同，长度、字符符合 J8；
   - 同一种子出同一道题。
4. 在游戏里手动验证：
   - 书在快捷栏、不在快捷栏两种开局，拿到手上、右键打开、`book/set`、`book/close`，判 `success`；
   - 清空最后一页，保存后书变短，和目标一致；
   - 写到第 n + 2 页，第 n + 1 页是空页，判 `success`；
   - 改了但不关书就报完成，判 `false_success`，`faults` 有 `unsaved`；
   - 多改了一页，判 `false_success`，`faults` 有 `wrong`；
   - 把书扔出场外，判 `lost`。
5. J3 选 A 时：`book/set` 写带 `§` 的文字、1025 个字符、超过 14 行的文字都报错，页不变；写 14 行以内的正常文字照常成功。
6. `training-report` 能按 `k` / `hand` / `ops` 汇总。

## 8. 实施说明（2026-11-23）

**mod（J-S1）**：`arena/BookArena.java`（新）、`ArenaManager.java`、`api/ArenaApi.java`、`api/BookApi.java`、`src/mod/methods.js`

- `BookArena`：
  - `stack`：做带内容的书与笔（只认 `minecraft:writable_book`、数量 1，最多 100 页、每页最多 1024 个字符）；
  - `pages`、`describe`、`items`、`dropped`：读页（原文）；成书另带页（纯文字）和标题；
  - `reached`：玩家身上只有书与笔、每本数量 1，页列表和目标作为多重集合相等。
- 场地 `book` 在 (10000, 120, 10450)，没有工作站。
- `Give` 加第 7 个分量 `pages`；`prepare` 加参数 `selectedSlot`：设 `Inventory.setSelectedSlot`，再发 `ClientboundSetHeldSlotPacket` 同步给客户端。
- `Expect` 加第 17 个分量 `book`。给了 `expect.book` 时：
  - `prepare` 返回 `book { items, selectedSlot }`；
  - `status` 返回 `held`、`books`、`carriedItem`、`dropped`、`droppedBooks`、`selectedSlot`；
  - 到达检测在"光标为空"之后按 `BookArena.reached` 比对。
- **`book/set`（J3 做法 A）**：
  - 改页之前查三条：`StringUtil.filterText(text, true)` 和原文一致（报错写明第几个字符、码值）；最多 1024 个字符；
  - 行数用一个和编辑框同样设置的 `MultilineTextField`（宽 114、上限 1024 字符、14 行）试写：`setValue` 超出行数时不改值，值和原文不一致就报错；
  - 不符合就报错，页不变、不截断。`book/get`、`book/page`、`book/close` 没改。
- 胶囊库和代码里目前没有用到 `book/set` 的地方，收紧不影响已有胶囊。
- **补充（2026-11-23，审阅后追加）**：
  - `book/set` 改的不是当前页（比如在后面追加一页）时，重算右上角的页码缓存 `numberOfPages`，屏幕上的"共 y 页"马上更新（原来要等翻页）；
  - `book/close` 等客户端线程做完才返回，当前不是书的编辑界面时报错 `book editor not open`（原来什么都不做也返回成功）；
  - 三个接口等不到客户端线程时，报 `timed out waiting for the client thread`（原来报错信息是 null，`Map.of` 会抛异常）。
- `gradlew compileJava` 通过。选中格同步、`book/set` 的行数检查要等游戏内验收确认。
- **已改（2026-11-23，和告示牌训练场一起实施）**：`book/set` 去掉 `page` 参数，只改当前页；`book/page` 翻到"总页数"时追加一张空页，等同于在最后一页点"下一页"。上面"改的不是当前页时重算页码"的补充随之删掉。详见《告示牌训练场设计方案》Q9。
- **已补（2026-11-23，同上一起实施）**：书与笔训练里 3 本书的题全是 `false_success`，原因是行为树读不到书的内容（F10 的影响比预想的大：不只是"要逐本打开"，打开了树里也读不到）。`container/get` 在书打开时报 `type: "book_edit"`，带 `pages`、`currentPage`；`container/close` 对书等同于 Esc（关掉、不保存），F9 里"关书只能用 `book/close`"不再成立。详见《告示牌训练场设计方案》F13、Q14。
