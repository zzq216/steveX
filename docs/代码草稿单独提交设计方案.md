# 代码草稿单独提交设计方案

> 状态：**J-S1–J-S4 已实施**（2026-11-23），单元测试通过，待训练中观察效果（§5）。审阅结论：D1–D7 全部按建议执行。实施说明见 §6。
>
> 已经确定的方向：
> - 新增工具 `bt_write_code`，代码草稿可以不和树一起提交，单独写；原来提交工具里的 `code` 字段保留；
> - 模型返回坏的工具参数 JSON（`MALFORMED_RESPONSE`）时，选方案 A：每个请求另给 2 次不计次的重试，用完以后再照常计次。

## 1. 起因

起因是合成器训练 `task-20261123052433-4`（`stone_spear` ×15）的会话日志。

- 5 个回合里，有 2 个回合因为工具参数 JSON 不合法出错结束：
  - 第 1 回合：`bt_submit_tree`，18.5 KB；
  - 第 3 回合：`bt_submit_patch`，10.5 KB。
- 两次坏在同一个位置：树或补丁写完、刚进入 `"code"` 字段时，外层括号的层数对不上。同一个参数里还塞着一段约 11 KB 的 JS 代码（转义成 JSON 字符串）。
- 代价：
  - 出错回合里的工具调用都没有执行，那 11 KB 代码也跟着丢了；重试回合要把代码和树全部重写一遍，每次 3–6 分钟。
  - 每次出错都按"不合法尝试"计次，3 次额度用掉了 2 次，可树本身其实没有任何问题。
- 重试提示的最后一段写的是"把代码草稿写短、去掉注释与兜底分支，或者改成 `expand`"。这是在教写法，和"只补能力与证据、不教写法"的原则冲突。

| # | 事实 | 位置 |

## 3. 决策点

### D1　新工具 `bt_write_code`

- **参数**：`{ requestId, name, signature, body, description? }`，一次写一条草稿。
- **检查**：
  - `requestId` 必须是这个会话正在处理的规划、展开或修复请求（沿用 `checkRequest`）；
  - 内容检查沿用 `saveDraft`（签名、沙箱编译）。
- **返回**：
  - 通过：`{ ok, ref: "task/名字@hash", hash }`；
  - 不通过：逐条错误原文。
- **生效**：草稿写进去就留在本任务的草稿区。之后同一任务里的任何提交（树、展开、补丁）都可以用 `task/名字` 引用，跨回合也有效，直到任务结束。
- **工具说明**只写能力和边界：
  - 草稿可以单独写好，也可以继续放在提交工具的 `code` 字段里；
  - 同名重写算新版本，树里 `task/名字` 引用的是提交时最新的那一版；
  - 写好的草稿不会因为后面回合出错而丢失。

  **不写**"代码长就分开交"这类建议。

**建议：采用。**

### D2　`bt_write_code` 写错了要不要计次

| 方案 | 做法 | 说明 |
|------|------|------|
| **A** | 不计次，只返回错误原文 | 写草稿时树还没交，这只是编译检查，和"交上来的树不合法"不是一回事。回合本身有步数上限，不会无限循环 |
| B | 和提交失败一样计次 | agent 会因为怕扣次数而少用这个工具，不符合加这个工具的初衷 |

**建议：A。**

### D3　哪些回合能用

- 加进三类回合的工具列表：`REQUEST_TOOLS.plan`、`expand` 和修复类（`PATCH_TOOLS`，含 recover、escalate、failed、died）。
- 复盘回合**不给**：复盘用 `capsule_save` 把草稿转正，不需要再写新草稿。
- 整理回合**不给**：整理不接受没经过任务验证的新代码。
- 快树**本期不做**：快树补丁很短（S7），以后有需要再加。

**建议：采用。**

### D4　坏 JSON 另给不计次的重试（已选 A）

- 新增常量 `MALFORMED_RETRY_MAX = 2`，和 `TRANSIENT_RETRY_MAX` 并列，每个请求分别计数（`req.malformedRetries`）。
- `onTurnError` 的判断顺序：
  1. 网络、API 故障：沿用现在的处理；
  2. 坏 JSON（命中 `MODEL_FAULT`），且 `malformedRetries < 2`：不计次，重试消息写"模型返回的工具参数不是合法 JSON，不算不合法尝试（这类重试还剩 n 次）"；
  3. 其余情况照常计次。坏 JSON 的 2 次用完以后，再出坏 JSON 也照常计次。
- 适用的请求：规划、展开、修复、复盘（复盘本来就是"出错多少次后关闭"，同样先用掉这 2 次不计数的重试）。整理回合出错本来就不自动重试，不变。快树不变（S7）。
- 一个请求的总上限因此是：3 次不合法尝试 + 2 次坏 JSON + 5 次网络故障。坏 JSON 一直出的模型，第 6 个出错的回合以后照样会用完次数。
- 测试 `bridge.test.js:269` 的断言"坏 JSON 不是网络故障"保留：判定函数不变，只是多一个不计次的类别。

### D5　重试提示改成只陈述事实

`prompts/requests/retry.md` 和 `reflect_retry.md` 最后一段"把代码草稿写短……改成 `expand`"删掉，换成事实：

```
出错那一步的工具调用都没有执行（同一条消息里的其他调用也一样）；在那之前已经执行的调用照常有效。
已经用 bt_write_code 写下的草稿还在：{{drafts}}。
```

- `{{drafts}}` 是本任务草稿区里现有草稿的引用列表（`task/名字@hash`），没有就写"（没有）"。
- 这是 agent 自己做过的事的现状，规划回合又没有 `bt_view` 可查（S5），所以列出来。这不是汇总好的游戏证据，不违背"不往请求里预塞证据"的约定。

**建议：采用。**如果你认为连这份列表也不该给，可以只写第一句，再说明"写下的草稿仍可引用"。

### D6　提示词和文档

- `prompts/system/authoring.md` 第 35 行附近补一句：草稿也可以用 `bt_write_code` 单独写。
- 三个 skill（`expand.md`、`recover.md`、`reflect.md`）里"要改就在 `code` 字段里同名重写"改成"要改就同名重写（`code` 字段或 `bt_write_code`）"。
- `outline.md` 不加新内容：它没提过 `code` 字段的写法，系统提示词里有就够了。

### D7　记录

- 训练记录增加 `malformedTurns`：本任务所有请求里，因坏 JSON 出错的回合数（不管计没计次）。
- 再增加 `draftWrites`：本任务里 `bt_write_code` 调用成功的次数。
- 以后可以用这两个字段看新工具有没有被用、坏 JSON 有没有减少。
- 数据从 bridge 上属于这个任务的请求里汇总，trainer 现在读 `planAttempts` 用的也是这条路径。

**建议：采用。**

## 5. 验收

1. 跑一次 `/bt train crafter`，在会话日志里确认：agent 能先用 `bt_write_code` 写草稿再交树；就算不用，原来的 `code` 字段也照常可用。
2. 人为让一个回合出现坏 JSON（或在测试里模拟），重试消息写的是"不算不合法尝试，还剩 n 次"，并列出已有的草稿。
3. 训练记录里有 `malformedTurns` 和 `draftWrites`。

## 6. 实施说明（2026-11-23）

- **`bridge.writeCode`**：
  - 先用 `checkRequest` 检查请求，类型限 `plan` / `expand` / 四种修复，必须是本会话的、还没回答、没关闭的请求；
  - 再用 `saveDraft` 写入草稿区；
  - 成功时在请求上累加 `draftWrites`；写错只返回 `errors`，不计次。
- **工具 `bt_write_code`**（`src/tools/tree.js`）：
  - 参数 `{ requestId, name, signature, body, description? }`；
  - 结果写成"已写入草稿 task/名字@hash……"，或"没有写入（不算不合法尝试）：……"。
- **回合放行**：`REQUEST_TOOLS` 的规划、展开、修复三类加入 `bt_write_code`；复盘、整理回合不加，被守卫挡住。
- **坏 JSON 的计数**（`onTurnError`）：
  - 新增 `isMalformedError`（沿用 `MODEL_FAULT` 正则）和 `MALFORMED_RETRY_MAX = 2`；
  - 请求上的 `malformedTurns` 记所有坏 JSON 回合，`malformedRetries` 记用掉的不计次重试；
  - 判断顺序：网络故障 → 坏 JSON 不计次 → 照常计次。
- **重试提示**：
  - `retry.md` 最后一段改成事实陈述，并用新变量 `{{drafts}}` 列出本任务草稿区里每条草稿的最新版本，没有就写"（没有）"；
  - `reflect_retry.md` 只留第一句事实陈述。
- **提示词**：`authoring.md`、`expand.md`、`recover.md`、`reflect.md` 按 D6 改。
- **训练记录**：增加 `malformedTurns` 和 `draftWrites`，从 bridge 上属于该任务的全部请求累加。
- **测试**：
  - `bridge.test.js` 的出错测试改为"前 2 次坏 JSON 不计次，第 3 次计次"，并检查重试提示不再教写法；
  - 新增一条 `bt_write_code` 的整轮测试，覆盖：
    - 回合放行名单；
    - 请求不存在、请求属于别的会话、编译不过（不计次）；
    - 出错后重试提示列出草稿；
    - 树和展开都能引用单独写的草稿，同名重写算新版本；
    - 请求回答过以后拒绝再写；
  - `plugin.test.js`、`tools.test.js` 的工具数改为 31 / 28 / 20。
  - 插件 310 条、根目录 312 条测试通过。
