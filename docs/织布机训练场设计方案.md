# 织布机训练场设计方案

> 状态：**L-S1–L-S3 已实施**（2026-11-22），单元测试通过，待游戏内按 §6 验收。审阅结论：L1–L14 全部按建议执行。实施时补充的地方见 §7。已定的两点（2026-11-22 分析后同意）：带图案物的图案第一版就做，但用参数开启、默认不出；旗帜和染料都比目标多发 0–3 个。
>
> 本方案沿用《切石机训练场设计方案》（下称"切石机方案"）的整体架构：插件主控，mod 以服务器身份操作场地；每轮一个新会话；记录写进 jsonl；"恰好达到"的时刻由 mod 在 tick 里检测。织布机和切石机一样，要用界面按钮选方案、对数量有精确要求、多做要判错，所以框架照搬切石机场地，下面只写不同的部分。
>
> 目标：在已有场地旁边另建一块场地，场内正前方放一台织布机。训练 agent 用织布机把素色旗帜做成指定图案、指定颜色的旗帜，每种恰好指定的数量。

## 1. 用户原始流程

1. agent 传送到对应的训练场地中。正前方放一台织布机，agent 的视角对着它，直接点右键就能打开
2. 清空 agent 身上的所有物品
3. 开始计时，并发布任务：
   - 从织布机的配方表中任意选 1–3 种原材料（参数控制）
   - 每种原材料的数量为物品栏 0–1/12 格，每格放随机个数（参数可以改成每格放满）
   - 每种原材料随机选 0–3 种要做成的样式，把数量平均分成样式数那么多份，每份随机生成一个目标数量
   - 任务里只告诉 agent 有哪种材料，请它把这种材料分别做成各样式的目标个数
4. 检测到物品栏里的目标物品恰好是指定数量（不多不少）时，停止计时并记录

本方案保留这个流程。"原材料"和"样式"按织布机的实际机制重新定义（§2 F1–F3、L4、L5）：原材料是某种底色的素旗，样式是"图案 + 染料颜色"。染料、图案物按目标另外发放（L6）。

## 2. 已核实的事实

依据 `1.21.11_src` 的 `LoomMenu`、`AbstractContainerMenu`、`BannerPatternTagsProvider`、`BannerDuplicateRecipe`、`Items`，以及 mod 现有的 `ContainerApi` / `InventoryApi`。

| # | 事实 | 对方案的影响 |
|---|------|------------|
| F1 | 织布机有 4 格：0 = 旗帜、1 = 染料、2 = 图案物（可空）、3 = 结果；4–30 背包、31–39 快捷栏。取一次结果：旗帜格、染料格各消耗 1 个，图案物**不消耗**。结果是 1 面旗：底下那面旗的复制品，加一层"选中的图案 + 染料的颜色" | 每做一面旗都要一面素旗和一份染料。原流程只发"要被切的材料"，做不成。要按目标发染料（L6） |
| F2 | 织布机没有配方表。可选方案来自注册表标签：图案物格为空时，是 `no_item_required` 的 **32 种**基础图案（任意底色、任意染料都能用）；放进图案物，就换成这个图案物提供的图案（1.21.11 里 10 种图案物，各提供 1 种：花朵、苦力怕、头颅、Mojang、地球、猪灵、涡流、旋风、砖纹、波纹边） | "配方表"由 mod 从注册表读出来（L11）。图案物的图案要先放图案物，方案列表会整个变掉（L5） |
| F3 | 带图案的旗帜和素旗 **id 相同**（都是 `minecraft:white_banner` 这样的 id），区别只在 `banner_patterns` 组件（每层一个图案 + 颜色） | 计数和判定都要按"id + 图案层"区分，不能只按 id（L8、L9） |
| F4 | 旗帜一叠最多 **16** 个；染料 64 个；图案物 1 个 | "0–1/12 格"是 0–3 格、最多 48 面旗；算格数要按 16 算（L4） |
| F5 | 选方案用 `clickMenuButton(i)`，只检查 i 小于方案数，和界面滚动无关。取走结果后，只要旗帜格、染料格都还有东西，**选中的图案保留**，马上生成下一面；有一格空了，选中重置为 −1。方案只有 1 种时（放了图案物），自动选中第 0 号 | 只是事实，不写进文案 |
| F6 | 按住 Shift 点结果格会**循环做**：`AbstractContainerMenu` 的快速移动只要产物还是同一种物品（`isSameItem` 不看组件）就继续，直到旗帜或染料用完、或物品栏装不下 | 染料多发时，Shift 点一下就会超出目标数。这是这项训练要观察的主要失误（L8） |
| F7 | 旗帜已有 6 层时，织布机不出结果。把做好的旗再放回旗帜格，可以再叠一层 | 叠第二层就是做错样式（L8）。第一版不出多层的题（L14） |
| F8 | 关闭界面时，三个输入格的物品退回物品栏（`removed` → `clearContainer`）；结果格只是预览，直接丢弃，不消耗 | 本轮结束时，输入格里的东西不算丢失（L8、L9） |
| F9 | **2×2 合成能复制旗帜**（`BannerDuplicateRecipe`）：一面有图案的旗 + 一面同色素旗（各 1 个）→ 复制出一面，原旗退回；消耗那面素旗，**不用染料**。2×2 里还能把染料两两混成别的颜色 | 做出一面后，可以不再用织布机、也不耗染料就得到更多。旗帜总数不变（L8、L10） |
| F10 | `container/get` 已支持织布机：`selectedPattern`；`patterns` 是方案列表，下标和按钮号一一对应，每项是"选它会得到的那面旗"（带 `bannerPatterns`）；旗帜或染料缺一时为 `[]`。`container/button {button:i}` 选第 i 个方案，不用先滚动。物品栏里的旗帜带 `bannerPatterns: [{ pattern, color }]`（注册名和颜色名，如 `minecraft:stripe_bottom`、`red`） | agent 这边不需要新接口 |
| F11 | 织布机是完整方块。按 3×3 场地的布局（工作站在 `(ox, oy+1, oz+2)`），现在的俯角公式对准方块中心，和工作台一样 | 俯角公式不用改，`aimOk` 照常自检（L2） |
| F12 | mod 现在的到达检测（`Expect`）按物品 id 计数；锻造台另有按纹饰比对的写法（`List<Smith>`）。`status` 的计数都是 id → 数量 | 要加一种按"id + 图案层"计数和比对的写法（L9） |

## 3. 总体设计

流程和切石机方案相同：插件出题 → `arena/prepare` 发放旗帜、染料、图案物，补回织布机，对准视角，登记目标 → 发布任务 → 轮询 `arena/status` → 任务结束后调用 `arena/finish` → 判定并写记录。

插件侧新增训练题型 `loom`，在新文件 `src/training/loom.js` 里实现，接口和 `stonecut.js` 相同。训练器、记录、报告、每轮新会话都直接复用。

mod 侧改动：

1. 增加工作站 `loom`、场地 `loom`，`opensStation` 认 `LoomMenu`；
2. 物品计数改用"签名"：素的物品是 id，带图案的旗帜是 id 加图案层（L9）；
3. 织布机工作站的 `status` / `finish` 返回物品栏、光标、织布机输入格、地上四处的计数；
4. `Expect` 增加一种织布机写法；
5. 新增 `arena/loom-catalog`，从注册表读底色、染料、图案、图案物。

## 4. 决策点

### L1　场地

新增场地 `loom`，origin 设在 `(10000, 120, 10270)`，在坐骑场地 `(10000, 120, 10240)` 之后、间隔 30 格，工作站为织布机。场地的搭建、清场、屏障墙、告示牌逻辑原样复用。`/arena loom` 传送到场外平台，`/bt train loom` 开始训练。

**建议：采用。**

### L2　织布机的位置、朝向和视角

和切石机方案 Q2 相同：织布机放在 `(ox, oy+1, oz+2)`，玩家朝 +z 站着，俯角由 mod 计算，`prepare` 返回前做射线自检 `aimOk`（F11）。织布机的 `FACING` 取朝向玩家，只影响外观。

**建议：采用。**

### L3　底色

原材料是素旗。16 种底色，去掉 `exclude` 里的，等概率抽。同一轮的几种底色互不相同。参数 `banner=<旗帜 id>` 固定第一种底色。

不需要切石机方案那样的家族抽样：16 种底色地位相同，不存在某一类占比过高的问题。

**建议：采用。**

### L4　每种底色的数量与目标个数

对每种底色：

1. **规模 N**：照用户流程抽。格数 s 在参数 `slots=k|a-b`（1–3，默认 `1-3`）里随机；每格的数量按 `fill=random|full|mix` 决定，random 时在 [1, 16] 里随机，full 时每格 16（F4）。N 是各格之和，最多 48。0 格出不了题，所以下限从 0 改成 1。
2. **样式数 m**：在参数 `styles=k|a-b`（1–3，默认 `1-3`）里随机，并且不超过 N。下限从 0 改成 1。
3. **选样式**：见 L5。
4. **平均分**：每份 `share = ⌊N / m⌋`。
5. **目标个数 t**：每个样式在 `[1, share]` 里随机。织布机一次只出 1 面，所以不用像切石机那样按产出数取整。

N 只用来定目标的规模。实际发多少旗帜见 L6：按目标数加余量发，不是发 N 面。

**建议：采用。**

### L5　样式（图案 + 颜色）与图案物

每个样式是一对"图案 + 染料颜色"：

- **图案**：默认从 32 种基础图案（F2）里抽，去掉 `exclude` 里的。
- **颜色**：从 16 种染料颜色里抽，**不和底色相同**。白旗加白色图案做法合法，但几乎看不出效果，题意也容易让人困惑。
- 同一种底色下，m 个样式两两不同（图案或颜色至少一项不同）。不同底色的旗做出来本来就不一样，不用再去重。

**图案物**（已定：第一版就做，用参数开启，默认不出）：参数 `itemPatterns=off|on`，默认 `off`。

- `on` 时，每个样式有 1/3 的概率改从 10 种图案物图案里抽。
- 这道题要用的图案物各发 1 个（不消耗，F1）。任务文案不提图案物，agent 读物品栏就能看到。
- 难点在于：放进图案物后，方案列表只剩它那一种，并且自动选中（F5）；同一轮里还有基础图案要做时，得先把图案物拿出来。这正是想观察的地方。

**建议：采用。**

### L6　发料（余量）

已定：旗帜和染料都比目标多发 0–3 个，参数 `spare=k|a-b`（0–3），默认 `0-3`。

| 物品 | 数量 |
|------|------|
| 每种底色的素旗 | 该底色全部目标之和 + 余量 |
| 每种颜色的染料 | 全部底色里用这种颜色的目标之和 + 余量（每种颜色各抽一次余量） |
| 图案物 | 本轮要用的每种各 1 个（`itemPatterns=on` 时） |

- **为什么要留余量**：如果染料恰好够，做错一次就无法挽回，题目会过于严苛。剩下的素旗和染料不算错（L8）。余量为 0 的轮次照样会出，用来观察"一次做对"。
- **摆放**：素旗按 16、染料按 64 拆成若干叠。`fill=full` 时尽量满叠；random 时叠数在 `⌈x/叠上限⌉` 和它加 1 之间随机，再随机拆分数量。全部物品叠在 36 格里随机分布，由种子决定。
- **容量检查**：开局占用格数 S，加上全部目标做完后的叠数 `Σ⌈t/16⌉`，必须不超过 36，超了就重抽这一轮（同一种子出的题仍然确定）。最坏情况是 3 种底色、9 个样式、余量全是 3，按上限估算可能超出，所以要检查；平时远远用不满。

**随机数的抽取顺序**：底色种数 → fill（mix 时）→ 逐种底色（底色 → 格数 s → 每格数量 → 样式数 m → 逐个样式：是否用图案物 → 图案 → 颜色 → t）→ 逐种底色抽旗帜余量 → 逐种颜色抽染料余量 → 拆叠 → 打乱格位。

**建议：采用。**

### L7　任务文案

按"只补能力与证据，不教写法"的原则：文案只说现状和要求，不提右键、按钮编号、Shift 点击、复制旗帜，也不说发了多少染料、有没有图案物。agent 可以自己读物品栏和 `container/get`。

模板 `prompts/training/loom.md`：

```
你正前方有一台织布机，视角已经对准它。你的物品栏里有这些旗帜：{{banners}}。
请做出：{{list}}。做好的旗帜留在物品栏里，不要做出其他物品。
```

- `{{banners}}` 是底色旗帜的 id 列表，例如 `minecraft:white_banner、minecraft:black_banner`
- `{{list}}` 按底色分组，例如 `用 minecraft:white_banner 做 5 面加了 red 色 minecraft:stripe_bottom 图案的、3 面加了 blue 色 minecraft:cross 图案的；用 minecraft:black_banner 做 4 面加了 yellow 色 minecraft:creeper 图案的`
- 图案用注册名，颜色用颜色名，和 `bannerPatterns` 的写法一致（F10），不另造说法

"用哪种底色做、什么图案、什么颜色"是题目本身，写出来只是把要求说清楚，不替 agent 做决定。"不要做出其他物品"是要求，不是做法。

**建议：采用。**

### L8　判定

在任务结束时，按以下几处计数：物品栏（不含光标）、光标、织布机三个输入格（界面还开着时）、场内地上。计数按签名（L9）。判定顺序沿用切石机方案 Q8：

| 顺序 | 结果 | 条件 |
|------|------|------|
| 1 | `aborted` | 手动停止 |
| 2 | `lost` | 织布机被挖掉；场内地上有物品（比如 Shift 做满后掉出来的，F6）；图案物不见了；或者**旗帜总数**变少了 |
| 3 | `overshoot` | 任一目标在四处合计超过 t |
| 4 | `misweave` | 出现了题目没要的东西：任何不是目标的带图案旗帜（图案或颜色不对、叠了两层，F7），或者开局时没有的物品 id（比如 2×2 混出来的染料，F9） |
| 5 | `timeout` | 超时 |
| 6 | `success` / `false_success` / `failed` | 任务以完成结束时，到达条件（L9）成立就是 `success`，否则是 `false_success`；其余情况是 `failed` |

- **旗帜守恒**：织布机是 1 面旗换 1 面旗，2×2 复制也是消耗 1 面素旗换 1 面（F9），场内又没有别的途径做出或消耗旗帜。所以四处的旗帜总数（素的加带图案的，所有底色）应该等于开局发的数。少了说明有旗被扔出场外，判 `lost`。切石机场地做不到这一点（它的材料当量会误判），织布机这边是严格成立的。
- 剩下的素旗、染料不判。
- 记录里写 `madeOf`（每个目标实际做了多少）、`extra`（多余的东西及数量）、`copied`（L10）。

**建议：采用。** `misweave` 的中文名是"做错"。

### L9　计数签名与"恰好达到"的检测（mod）

**签名**：一叠物品的计数键。没有图案层的物品就是 id；带图案的旗帜是 `id#图案/颜色`，多层用 `+` 连接，例如 `minecraft:white_banner#minecraft:stripe_bottom/red`。`status` / `finish` 在织布机场地上按签名计数，插件按同样的规则解析。其他场地的计数不变。

**到达检测**：沿用切石机方案 Q9，mod 在服务器 tick 里检测，记下第一次达到的时刻 `reachedAtMs`，不打断 agent。`Expect` 增加织布机写法：`expect: { loom: { goals: [{ banner, pattern, color, count }], allowed: [id...] } }`，`allowed` 是开局发的全部物品 id（素旗、染料、图案物）。同时满足下面几条就算到达：

1. 每个目标的签名在物品栏里恰好是 count 个，在光标和织布机输入格里都是 0；
2. 光标为空；
3. 物品栏、光标、织布机输入格里，没有不在 `allowed` 里的 id，也没有目标以外的带图案旗帜。

剩多少素旗和染料不比较。

`status` 对织布机工作站返回 `held`、`carried`、`loomInput`（玩家当前打开的织布机界面的 0–2 号格，界面没开时为空）、`dropped`。只读计数，不改动状态，`finish` 的顺序不用改。

**建议：采用。**

### L10　2×2 复制旗帜（F9）

做出一面目标旗后，可以在 2×2 里用"这面旗 + 一面同色素旗"复制出更多，不用织布机，也不耗染料。

| 方案 | 做法 | 说明 |
|------|------|------|
| **A** | 允许，结果一样就算对；记录里写 `copied` | 每个样式仍然至少要用织布机做出第一面，训练目的不受影响。复制是 agent 自己可能发现的另一种做法，记下来就能观察到。`copied` 由插件算：做出的带图案旗帜总数 − 消耗的染料数（织布机每面耗 1 份染料，复制不耗），不用改 mod |
| B | 禁止：发现复制就判错 | mod 要区分产物来自哪个菜单，判定复杂；而且产物完全相同，没有理由算错 |
| C | 出题时让染料恰好够，逼着用织布机 | 和已定的"多发 0–3 个"冲突 |

混染料（2×2 把两种染料混成新颜色）会产生开局没有的 id，按 L8 判为 `misweave`。题目要的颜色都已经发了，混色没有用处。

**建议：A。**

### L11　图案目录

| 方案 | 做法 | 说明 |
|------|------|------|
| **A** | mod 新增 `arena/loom-catalog`，从注册表和标签读出：16 种素旗（id、颜色）、16 种染料（id、颜色）、32 种基础图案（按 `no_item_required` 的顺序）、图案物（id 和它提供的图案）。插件出题前读一次 | 数据就是游戏自己的，和锻造台、坐骑场地的做法一致 |
| B | 提取脚本从源码里抄出一份 `data/loom.json` | 要多维护一份数据，版本一变就要重抄 |

**agent 这边不加数据文件**：方案列表、每个方案会得到什么样的旗，`container/get` 都给了（F10），树可以在执行时读出来，再按 `bannerPatterns` 找到对应的按钮号。这和切石机不同：切石机要提前知道"切一次出几个"才好算数量，织布机一次只出 1 面。

**建议：A，不给 agent 加数据。**

### L12　记录与报告

### L13　超时、织布机被挖、胶囊库

- **超时**：一轮最多 9 个样式、最多约 150 面旗，每面都要经过织布机（Shift 循环能一次做很多，但要控制数量）。场地配置 `timeoutSec` 建议为 **900 秒**，和切石机相同。
- **织布机被挖**：同切石机方案 Q12。每轮 `prepare` 都重新放织布机；轮次进行中被挖掉不补放，记录 `stationIntact=false`，判为 `lost`。
- **胶囊库**：原样带进训练。切石机训练里"按按钮号选方案、往输入格放恰好 k 个、避免 Shift 循环过量"这类子树，可能会被迁移过来，这正是想观察的。训练前先备份 `src/capsules/`。

**建议：全部采用。**

### L14　暂不做的部分

以下内容等基本训练稳定后再考虑，现在不做：

- 在已有图案的旗上再叠一层，或者目标本身是多层图案（F7）
- 盾牌加旗帜图案（工作台合成，不在织布机上）
- 物品栏里放干扰物品、材料不够做不到的题
- 不告诉 agent 用哪种底色（L7 的另一种写法）

## 6. 验收清单（实施后）

1. `/arena loom` 能传送到新场地的场外平台；其他场地和它们的训练不受影响。
2. `/bt train loom runs=3`：每轮开始时，正前方有织布机，`aimOk=true`，物品栏里只有本轮的素旗、染料（和图案物），第一次右键就能打开织布机。
3. `arena/loom-catalog` 返回 16 种素旗、16 种染料、32 种基础图案、10 种图案物。
4. 抽题检查（单元测试，并用真实目录抽几千道）：
   - 样式颜色不等于底色，同一底色下的样式两两不同；
   - 发的素旗 = 目标之和 + 余量，染料按颜色同理，余量在 `spare` 范围内；
   - `itemPatterns=off` 时不出图案物图案，`on` 时约 1/3 的样式用图案物，并且发了对应的图案物；
   - 开局格数加目标叠数不超过 36；
   - 同一种子出同一道题。
5. 在游戏里手动验证：
   - 恰好做完时，`reachedMs` 有值，判为 `success`；
   - 用 Shift 做多了判为 `overshoot`；
   - 做错图案或颜色、叠了两层，判为 `misweave`；
   - 在 2×2 里复制旗帜，结果正确时判为 `success`，记录里 `copied` 大于 0；
   - 把一面旗扔出场外，判为 `lost`；
   - 任务结束时旗帜、染料还在织布机输入格里，不算丢失；
   - 放进图案物后方案只剩一种、自动选中（F5）。
6. 轮次中把织布机挖掉后，记录里 `stationIntact=false`；下一轮开始时织布机已经补回。
7. `training-report` 能按 `banners` / `styles` / `pattern` / `color` / `item` 汇总，`misweave` 显示为"做错"。
