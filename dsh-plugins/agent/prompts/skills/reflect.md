# skill：慢树反思（任务中）

任务树里有一步失败了，原地重试一次也没成功。失败的那一步（目录里的"失败"节点）是**症状出现的地方**，原因不一定在它身上。

## 步骤

1. **找原因**：这一步为什么失败？它依赖的前提是什么，前提是在哪一步、因为什么没有成立？需要什么就用 `bt_inspect` 去看。
2. **决定怎么修**，选一种：
   - **原地再来**：`ops: []`。失败是偶然的、再跑一次大概率会成功时用这个
   - **补一步**：`insert-before` 失败的节点，先把缺的前提补上
   - **改掉这一段**：`replace` 失败的节点（或它所在的、还没完成的一段），换一种做法
   - **放弃**：任务在当前局面下做不到，用 `bt_abort_task` 写明原因
3. **提交**：`bt_submit_patch`。被拒绝就按错误原文修正后重交。

## 补丁的规则

- `ops` 每项是 `{ op, id, node? }`，`node` 是编写格式的子树（与展开相同），`id` 只点名树里已有的节点；新节点的 id 由执行器分配
- `replace` 换掉一个节点；`insert-before` / `insert-after` 只能插进 `seq` / `sel` 里；`remove` 删掉一个节点
- **已经执行完的步骤不会重跑**：改它们、或插在它们中间都会被拒绝。原因在更早的步骤时，在失败的节点前 `insert-before` 补做
- 整份补丁的新节点有上限，超了就把一部分写成 `expand`，留到执行时再规划

## 注意

- 用 `bt_inspect` 看到的具体值（格子号、数量、坐标）用来**判断**；补丁里仍然用读取节点、条件和 `$键` 取数据，不要把看到的值写成字面量——补丁下一次运行时，世界不一定还是这个样子。
- 同样的修法已经失败过（看节点的执行次数与补丁来源），就换一种做法，不要原样重交。
- 要用到的代码草稿（`task/…`）可以直接引用；要改就在 `code` 字段里同名重写。
