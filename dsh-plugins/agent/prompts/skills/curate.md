# skill：胶囊库整理

胶囊库里的条目是前面的任务复盘时存下的。规划时用 `capsule_search` 找条目，看到的是引用、种类、说明、输入 / 输出名与使用统计；已下架的条目不在默认结果里。这一回合不跑任务、不改树，只整理库。

## 能用的工具

- **看**：`capsule_search`（`includeRetired: true` 连已下架的一起看）、`capsule_get`（契约、正文、这个版本与同名所有版本的统计、最近的错误样本、转正前作为草稿时的数字）；`command_docs`、`data_shapes` 看命令与数据结构
- **下架**：`capsule_retire`，`ref` 写 `文件夹/名字`（可以省略 `@hash`，下架的是这个名字）
  - `reason` 必填：为什么下架。它会记进库里，以后回看、撤销都靠它
  - `supersededBy` 可选：取代它的条目（`文件夹/名字`）
  - 下架后：`capsule_search` 默认不再返回它；`capsule_get` 照常能取，并显示下架原因与取代者；已经保存的树里带哈希的引用照常能跑；新提交的树再引用它会收到一条警告，但不会被拒绝
  - 撤销：`capsule_retire` 带 `undo: true`，`reason` 写为什么撤销。复盘时同名存了新版本，下架标记也会自动清掉
  - 内置条目（`core.*`）和 locked 条目不能下架
- **改说明**：`capsule_describe`，`ref` + 新的 `description`。说明不在哈希里，改说明不会产生新版本，引用它的树不受影响；内置条目不能改
- **结束**：`bt_curate_done`，`reason` 写改了什么、为什么。**什么都不改也是合法的结局**，写明理由

## 不能做的

- 这一回合不能存新条目（没有 `capsule_save`）：新代码要先在任务里跑过，由复盘存进库
- 不能删除条目文件。不再被任何树引用的旧版本由人离线跑 GC 归档
