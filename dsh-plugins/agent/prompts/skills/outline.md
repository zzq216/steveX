# skill：慢树大纲

把一条指令写成一棵**马上可以开始执行**的树。

## 步骤

1. **看有什么可用**：`capsule_search` 看有没有做过的同类子树或代码（结果只有名字，说明与契约用 `capsule_get` 看）；`task_search` 查做过的同类任务，`task_get` 看它的树、成本画像和复盘时记下的问题；`fact_search` 查事实库里从源码确认过的游戏机制（结果只有名字，全文与源码引用用 `fact_get` 看）；`command_docs` 查原始命令的名字与参数。要写处理数据的条件代码 / Compute，先用 `data_shapes` 查数据长什么样：`state.*`（玩家状态、背包、F3、容器界面）、`json.recipes`（配方）、`nbt.*`（记忆世界）的字段结构与词表（枚举型字段的全部取值，如 `container.type` 的工作台是 `"crafting"`）。字段含义用 `command_docs` 查对应的读取命令（`inventory`、`container/get`……）。**不要猜字段名**——猜错了，条件代码要么永远不成立，要么像"找不到字段就返回 true"那样形同虚设。你看不到当前状态的值——它们由树去读（见下面"先读后展开"）。
2. **拆任务**：把指令拆成几个子任务（按先后顺序）。
3. **写成具体节点**：现在就知道怎么做的部分写成具体节点（`steps` / `act` / `compute` / `cond` / `forEach` / `use`）。库里的子树执行时自己读状态、自己验收，`use` 它就是一个具体节点。
4. **定不下来的部分写成 `expand`**：要看前面的执行结果（哪一步成功、失败，黑板上有了哪些结论）才能定下树结构的部分，写成 `{ "expand": 目标 }`。目标写清楚"要达成什么"，不写"怎么做"。展开时你能看到整棵树的执行结果、前面没做成的分支停在哪，黑板上的小值直接给出，大块数据与记忆世界查询结果只给形状。规划回合看不到配方、记忆世界和现场状态的值；展开回合看得到树读出来写进黑板的小值（如背包里各物品的数量），配方等记忆世界查询结果仍只给形状。依赖这些值的选择（背包里是什么材料、分成几堆、各多少，配方是什么）可以由树里的条件代码 / Compute 在执行时按读到的值去做；树的结构本身要看现场才能定的，也可以先读进黑板、再写 `expand`（多一个展开回合）。执行到每个 `expand` 时会再开一个回合来展开它。
5. **一次提交**：用 `bt_submit_tree` 交回，`requestId` 用请求里的那个。被拒绝就按错误原文修正后重交。

## 先读后展开

你写大纲时不知道现状（背包里有什么、配方是什么、附近有什么）。不要猜，**把"读"写成具体节点**；依赖读到的值的选择写成条件代码 / Compute，在执行时按读到的值去做；要看前面的执行结果或现场才能定下结构的部分留成 `expand`（树读出来写进黑板的小值，展开时会直接给你；配方等记忆世界查询结果只给形状）：

```
seq 做木镐
├─ compute code/core.json.query → recipe.pickaxe                  ← 具体节点：查配方
├─ compute task/plan-clicks read=[inventory] params $recipe.pickaxe ← 代码按读到的配方与背包算出要做什么
├─ forEach $plan.clicks → act container/slot                      ← 照算出的结果执行
└─ expand 合成木镐                                                ← 执行到这里时看前面的结果再定结构
```

- 读状态：条件代码 / Compute 的 `read`（`player` / `inventory` / `f3` / `container`）；查记忆：`code/core.nbt.query`；查配方等数据：`code/core.json.query`
- 读到的结论写进黑板（带前缀的键名），后面用 `$键` 引用，**不要把值抄成字面量**
- 需要按情况分支（有工作台 / 没有），就写成 `sel` + `cond`，让树在执行时判断

## 注意

- 具体节点要有验收：关键的 `steps` / `act` 写 `expect`，让失败有证据。
- 需要算东西（点击计划、坐标、计数）就写 Compute 代码，放在提交的 `code` 字段里。
- 指令不清楚、或者当前做不到（缺前置条件又无从获取）：用 `ask_user_question` 问人，或 `bt_abort_task` 放弃并说明原因。
