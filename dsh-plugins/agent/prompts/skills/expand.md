# skill：慢树展开

把树里一个 `expand` 节点换成一棵具体的子树。前面的步骤已经执行过了，现在的世界就是它们留下的样子。

## 步骤

1. **看现状**：请求里给了整棵树（每个节点的返回码）、要展开的节点在哪里、黑板上有哪些键及其**形状**（类型与结构，不给值）。你看不到当前状态——不要假设前面的步骤都如愿完成了：需要确认的，写成树里的 `cond`（条件代码 + `read`）或 `expect` 去验证。
2. **对照目标**：这个 `expand` 要达成什么？前面的节点留下了哪些结论（黑板键）？还缺什么信息？
3. **同样只沿第一条路径拆到底**：把目标拆成几步，只把第一步写成具体节点，其余写成 `expand`（与「慢树大纲」相同的形状）。还缺信息就先写读取节点（Compute 的 `read`、`code/core.nbt.query`、`code/core.json.query`），把依赖结果的部分再留成 `expand`。
4. **交回**：`bt_submit_expansion`，`requestId` 用请求里的那个，`subtree` 是替换这个节点的子树。被拒绝就按错误原文修正后重交。

## 注意

- 写条件代码 / Compute 前用 `data_shapes` 查要处理的数据（状态、配方、记忆世界）的字段结构与词表，不要猜字段名和取值；`expect` 要能真的失败，不要写成"读不到就当成立"。
- 黑板里的值一律用 `$键` / `$键.字段` 引用，**不要写成字面量**——你也看不到具体值；需要新的结论就用 Compute 算出来再写进黑板。
- 黑板里还没有判断所需的结论（比如目标已达成），就写成 `sel`：第一支 `cond` 判断已达成，第二支去做。
- 之前提交的代码草稿（`task/…`）可以直接引用；要改就在 `code` 字段里同名重写。
- 这一段确实做不了（前置条件不满足且无法补救）：`bt_abort_task` 放弃整个任务，写明原因。
