# skill：慢树恢复

任务树正在做某一步时被打断了——被快树（安全反射）打断，或者你死了、已经自动重生。被打断的那一步（目录里标出的节点）已经归零：原树继续时它会**从头**重新执行。它之前的步骤已经完成，不会重跑；但它们留下的东西（拿到的物品、所在的位置）不一定还在。

## 步骤

1. **弄清现状**：被打断的那一步做到哪了？打断期间发生了什么？现在的世界和那一步开始时有什么不同？需要什么就用 `bt_inspect` 去看。
2. **决定怎么继续**，选一种：
   - **原树继续**：`ops: []`。那一步从头重来就能接上时用这个
   - **补一步**：`insert-before` 被中断的节点，先把它需要的前提恢复，再让它重跑
   - **改掉这一段**：`replace` 被中断的节点（或它所在的、还没完成的一段）
   - **放弃**：局面已经无法完成任务，用 `bt_abort_task` 写明原因
3. **提交**：`bt_submit_patch`。被拒绝就按错误原文修正后重交。

## 补丁的规则

- `ops` 每项是 `{ op, id, node? }`，`node` 是编写格式的子树（与展开相同），`id` 只点名树里已有的节点；新节点的 id 由执行器分配
- `replace` 换掉一个节点；`insert-before` / `insert-after` 只能插进 `seq` / `sel` 里；`remove` 删掉一个节点
- **已经执行完的步骤不会重跑**：改它们、或插在它们中间都会被拒绝。要补做，就在当前步骤前 `insert-before`
- 整份补丁的新节点有上限，超了就把一部分写成 `expand`，留到执行时再规划

## 注意

- 用 `bt_inspect` 看到的具体值（格子号、数量、坐标）用来**判断**；补丁里仍然用读取节点、条件和 `$键` 取数据，不要把看到的值写成字面量——补丁下一次运行时，世界不一定还是这个样子。
- 要用到的代码草稿（`task/…`）可以直接引用；要改就在 `code` 字段里同名重写。
