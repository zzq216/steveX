# skill：快树反思

快树是常驻的安全反射：每个 tick 从上到下检查每条 arm 的 `when`，**第一个成立的**接管身体，跑完它的 `then` 才重新检查；都不成立就是 `otherwise`（什么都不做）。快树运行时没有大模型可问，只能靠写好的 arm。

这一批事件是快树**没处理好**的经历：

| kind | 含义 |
|---|---|
| `unhandled-harm` | 命中 `otherwise` 时掉了血（快树没认出这个局面） |
| `death` | 死了，之前没有掉血记录 |
| `arm-failed` | 某条 arm 认出了局面，但它的 `then` 失败了 |
| `arm-harmed` | 某条 arm 跑完了，但期间（或两次情节之间）还在掉血 |

每条事件标着它发生时的快树版本。旧版本下的事件，问题可能已经被后来的版本改掉了，用 `fast_inspect` 的 `versions` 对照。

## 步骤

1. **弄清每条事件发生了什么**：什么伤的、在什么环境里、当时快树做了什么、哪一步不起作用。需要什么就用 `fast_inspect` 去看。
2. **判断这批事件里有几种局面**：同一种局面只需要处理一次。
3. **决定怎么改**，每种局面选一种：
   - **加一条 arm**：快树没认出来的局面
   - **改一条 arm**：认出来了但没处理好；或者 `when` 成立得太早 / 太晚 / 抢了别的 arm
   - **删一条 arm**：它带来的问题比解决的多
   - **调整顺序**：两条 arm 的 `when` 会同时成立，优先级不对
   - **不改**：用 `fast_skip` 写明理由
4. **提交**：`fast_submit_patch`（一次提交可以有多条 op）。被拒绝就按错误原文修正后重交。

## 注意

- arm 的统计（`fast_inspect` 的 `arms`）是"这条反射有没有用"的依据：从没命中过、或命中了总是失败，都说明了问题。
- 写 `when` 之前，用 `fast_inspect` 的 `eval` 拿事故的快照（`before@eN` / `after@eN`）试算，确认它在那次事故里**会成立**，在平常状态下**不会成立**。
- 一个改动可能影响别的 arm：新 arm 插得靠前，会抢走后面 arm 的局面。
- 改动通过校验就自动生效，没有人审。拿不准的时候，宁可不改，用 `fast_skip` 写下你看到了什么。
